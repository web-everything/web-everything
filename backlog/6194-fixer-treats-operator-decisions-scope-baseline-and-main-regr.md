Operator 2026-10-17: "we have to keep improving the fixer", meaning no direct Codex passes on conveyor PRs except in emergencies. Preserve that goal: a repair round must receive the operator's complete ruling, its allowed scope and explicit exclusions, all current blocked findings, and a requirement to preserve main's deny behavior when repairing a guard or gate.

The original incident account names PR #5403 (13 rounds), PR #5461, a repeated-finding reset associated with PR #5463, and a joined round associated with PR #5465. ## Design

### One required input section, composed from existing readers

Add we:scripts/conveyor/fix-brief-inputs.mjs with a pure builder/renderer and an injectable read boundary. Its input is a repository/PR/head identity, complete ordered comments, complete changed paths, declared scope, current block-ruled referrals and optional main comparison evidence. Its output is either a structured refusal or a versioned required section containing decisions, obligations, reset constraints and regression instructions. Keep explanatory code snippets in the existing optional context pack.

Reuse the sanctioned send-back reader in we:scripts/lib/operator-send-backs.mjs and the answer reader/linkage/disposition rules in we:scripts/conveyor/stand-down-answer-core.mjs. Thread an opt-in complete-body mode through both the send-back parser and the open-request reader; existing compact display callers retain their current default. Keep the existing stripped text for resolution matching, but retain the original authenticated decision text separately for full rendering: removing only the 4,000-character cap would still lose HTML-comment content at we:scripts/lib/operator-send-backs.mjs:24. Preserve that text verbatim inside a data fence whose delimiter cannot be closed by the prose. Carry comment id, author, time, repository, PR and observed head separately; neither a body assertion nor viewer ownership authenticates a new operator ceremony. Normalize REST author/time/node-id fields at the read boundary without converting a numeric REST id into a stand-down's GraphQL identity. Retain the existing distinction between a trusted posting principal and a claim that a human personally typed the words. Do not expand the set of authorized principals.

Read the thread through we:scripts/conveyor/pr-comments-complete.mjs:23, preserving its paginated reader's author, node id and URL. Recompute referrals from that snapshot with the existing live-state reader in we:scripts/lib/referral-live-context.mjs:20, including the PR body and creation time it needs. Do not infer a complete empty referral set from the best-effort wrapper at we:scripts/conveyor/review-referral-hold.mjs:261, which returns an empty array on error. Pending referrals retain their existing hold; no new ruling is inferred. Current trusted reviews must be bound to the observed head using the verdict readers in we:scripts/conveyor/mechanical-round-cap.mjs:229 and we:scripts/conveyor/mechanical-round-cap.mjs:259, respecting the producer-slot advisory outcome used at we:scripts/conveyor/reconcile-core.mjs:1348. A quoted outcome or historical review does not create a new current obligation. These are reused readers, not additional edit targets.

The required section states that operator rulings settle the specified repair questions while review gates and ratified decisions remain in force. Aggregate unresolved send-backs, the applicable stand-down answer, current block-ruled referrals and the current trusted review finding set into one round. Preserve the existing planner's joined CI/review selection and carry its CI evidence bound to the same head; do not implement another join timer. Deduplicate by source comment/finding identity, not matching prose. Preserve source boundaries and include a checklist row for each blocked finding. Require one repair pass addressing the entire set, with per-finding change/test evidence before successful hand-back; if any cannot be repaired within the authorized scope, report that blocker rather than claim the round complete. Do not resurrect resolved requests or historical findings merely because round history mentions them. Deterministically incompatible metadata refuses assembly; conflicts in prose are an explicit fixer stand-down obligation, not a promised semantic conflict detector. This item does not invent precedence between contradictory operator policies.

### Reset constraints

Reuse we:scripts/conveyor/repeated-finding-reset.mjs and its corrective-commit reset path. Recognize a standalone `scope-baseline: <40 lowercase hex characters>` line and zero or more `out-of-scope: <repo-qualified path>` lines in the decoded, sanctioned decision body. A path names an exact file or a directory ending in `/`; no shell/glob interpretation, absolute paths, traversal or foreign repository prefix. A later applicable baseline decision replaces the earlier baseline/exclusion bundle; do not mix exclusions from a superseded baseline. Exclusion-only active decisions narrow the current scope and cannot authorize a reset by themselves. Multiple differing baseline values within one decision refuse.

Preserve existing operator-authored standalone baseline markers as legacy input, including the optional HTML-comment wrapper accepted at we:scripts/conveyor/repeated-finding-reset.mjs:94; new exclusion metadata must come from a sanctioned decision. Read new metadata only from standalone lines outside quoted/fenced examples in the authenticated body or decoded answer reason. The reset switch and repeated-finding trigger keep their current semantics: a marker alone does not trigger a reset. Exclusions subtract from the existing scope, never enlarge it, and remain instructions for ordinary repair even when automatic reset is disabled. Validate the baseline contribution and every prospective replay path; a baseline already containing excluded contribution refuses rather than silently rewriting the operator's baseline. Reject malformed sanctioned metadata instead of falling back to an older usable marker. Preserve dirty-lane, ancestry, merge/conflict and main-projection checks. Validation refusals occur before index/worktree mutation; a later cherry-pick conflict retains the existing discard-lane/no-push path, not a newly promised transactional reset. Continue using an ordinary corrective commit, never force-push. Following a reset, the next repair receives the same unresolved obligation set; a mechanical reset alone is not evidence that every finding was fixed.

### Main-regression requirement

Classify the complete actual touch set, not just the card's predicted scope. The initial deterministic classifier covers we:scripts/guard-*.mjs, we:scripts/check-standards.mjs, source basenames containing a hyphen-delimited `gate` token, files under a `gates` directory, and gate-named workflow/config files. Treat both rename sides as touched. Repo prefixes are normalized against the requested repo before matching; no WE-only assumption in sibling dispatches. Explicitly enumerate positive/negative fixtures in the classifier tests. Unreadable/incomplete paths refuse classification.

The new input reader must keep file records, including rename status and previous filename, rather than consume only the lossy path strings returned by we:scripts/conveyor/reconcile-fix-dispatch.mjs:644. Read all pages and validate every raw row and the returned count against the PR's changed-file count before deduplication. Treat endpoint caps, missing rename origins and count mismatches as incomplete input. Pin head before the reads and check it again after them; a head mismatch refuses this attempt. This belongs in the new shared reader, without changing existing generic scope-fallback behavior. Tests cover a guard renamed to an ordinary filename, a gate directory, a gate-named workflow/config file, an ordinary source file and a near-match such as a basename containing `delegate` rather than a `gate` token. Classification concerns known naming patterns, not an assertion that every semantic gate can be discovered from paths.

For a positive match, pin the observed main commit, stage the relevant main source/diff or an immutable reference readable from that provider's sandbox, and require the fixer to enumerate main's denied shapes and add a denial case for each. A remote URL alone is insufficient for the networkless launcher provider. Prove a newly added path absent at the pinned main tree explicitly; distinguish known absence from a failed read, and require comparison with any existing gate the addition changes or wraps. The evidence matrix has input shape, main refusal, candidate refusal, test and outcome. A missing/error input must still refuse; documentation/configuration/data entry points remain cautious alongside source code. An intentional weakening inconsistent with the recorded ruling is escalated. This is a required brief/test obligation, not a new authorization policy or an automatic proof that the model found every semantic shape.

Update we:skills-src/conveyor/fix-agent-brief.md so read-only main comparison is explicitly permitted without merging main or changing the PR's base. Respect we:docs/agent/platform-decisions.md#local-gate-never-full-suite-by-default: request scoped tests through heavy admission, preserving the existing proof-only rule and using the verify gate for candidate after-evidence. No repeated local green runs or broad default suite. Main's preserved-denial pins are non-regression evidence; the newly added brief/classifier tests supply this item's red-to-green proof.

## Edge cases this change must handle

1. **Untrusted text** — authenticate before parsing; quote decision bodies as data. Never execute prose, marker values or a path as a shell command.
2. **Truncated reads** — complete paginated comments and file lists are mandatory; failed reads or the mandatory-content ceiling refuse. Optional excerpts remain dispensable.
3. **Shared state files** — no new mutable ledger; derive from the scoped PR snapshot and use existing claim/private-prompt cleanup. Reset only the acquired repair lane.
4. **Fail closed** — unavailable main evidence, unsafe reset metadata, unresolved conflicting instructions or changed head cannot degrade to a plain patch brief.
5. **Identity scoping** — bind repo/PR/head and comment ids; reject foreign-repository exclusions and unlinked answers.
6. **State over time** — apply existing request resolution and answer supersession; rebuild on each round/head and retain unresolved obligations across a mechanical reset.
7. **Who wrote it** — use existing posting-principal checks and sanctioned envelope parsing; attributed actor prose is not cryptographic human presence.
8. **Receive/write endpoint abuse** — no new endpoint. Existing readers, GitHub ceremonies and repair claims remain in use. The mandatory-section byte cap bounds prompt assembly; repeated reset authorization still requires the existing repeat trigger and valid operator baseline. HTTP CSRF/origin checks and new rate limits are not applicable to this internal reader/brief change.
