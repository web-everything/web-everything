## Design

### One required input section, composed from existing readers

Add we:scripts/conveyor/fix-brief-inputs.mjs with a pure builder/renderer and an injectable read boundary. Its input is a repository/PR/head identity, complete ordered comments, complete changed paths, declared scope, current block-ruled referrals and optional main comparison evidence. Its output is either a structured refusal or a versioned required section containing decisions, obligations, reset constraints and regression instructions. Keep explanatory code snippets in the existing optional context pack.

Reuse the sanctioned send-back reader in we:scripts/lib/operator-send-backs.mjs and the answer reader/linkage/disposition rules in we:scripts/conveyor/stand-down-answer-core.mjs. Thread an opt-in complete-body mode through both the send-back parser and the open-request reader; existing compact display callers retain their current default. Keep the existing stripped text for resolution matching, but retain the original authenticated decision text separately for full rendering: removing only the 4,000-character cap would still lose HTML-comment content at we:scripts/lib/operator-send-backs.mjs:24. Preserve that text verbatim inside a data fence whose delimiter cannot be closed by the prose. Carry comment id, author, time, repository, PR and observed head separately; neither a body assertion nor viewer ownership authenticates a new operator ceremony. Normalize REST author/time/node-id fields at the read boundary without converting a numeric REST id into a stand-down's GraphQL identity. Retain the existing distinction between a trusted posting principal and a claim that a human personally typed the words. Do not expand the set of authorized principals.

Preserve the existing planner's joined CI/review selection and carry its CI evidence bound to the same head; do not implement another join timer. ### Reset constraints

Reuse we:scripts/conveyor/repeated-finding-reset.mjs and its corrective-commit reset path. Recognize a standalone `scope-baseline: <40 lowercase hex characters>` line and zero or more `out-of-scope: <repo-qualified path>` lines in the decoded, sanctioned decision body. A path names an exact file or a directory ending in `/`; no shell/glob interpretation, absolute paths, traversal or foreign repository prefix. A later applicable baseline decision replaces the earlier baseline/exclusion bundle; do not mix exclusions from a superseded baseline. Exclusion-only active decisions narrow the current scope and cannot authorize a reset by themselves. Multiple differing baseline values within one decision refuse.

Preserve existing operator-authored standalone baseline markers as legacy input, including the optional HTML-comment wrapper accepted at we:scripts/conveyor/repeated-finding-reset.mjs:94; new exclusion metadata must come from a sanctioned decision. Read new metadata only from standalone lines outside quoted/fenced examples in the authenticated body or decoded answer reason. The reset switch and repeated-finding trigger keep their current semantics: a marker alone does not trigger a reset. Exclusions subtract from the existing scope, never enlarge it, and remain instructions for ordinary repair even when automatic reset is disabled. Validate the baseline contribution and every prospective replay path; a baseline already containing excluded contribution refuses rather than silently rewriting the operator's baseline. Reject malformed sanctioned metadata instead of falling back to an older usable marker. Preserve dirty-lane, ancestry, merge/conflict and main-projection checks. Validation refusals occur before index/worktree mutation; a later cherry-pick conflict retains the existing discard-lane/no-push path, not a newly promised transactional reset. Continue using an ordinary corrective commit, never force-push. Following a reset, the next repair receives the same unresolved obligation set; a mechanical reset alone is not evidence that every finding was fixed.

## Edge cases this change must handle

1. **Untrusted text** — authenticate before parsing; quote decision bodies as data. Never execute prose, marker values or a path as a shell command.
2. **Truncated reads** — complete paginated comments and file lists are mandatory; failed reads or the mandatory-content ceiling refuse. Optional excerpts remain dispensable.
3. **Shared state files** — no new mutable ledger; derive from the scoped PR snapshot and use existing claim/private-prompt cleanup. Reset only the acquired repair lane.
4. **Fail closed** — unavailable main evidence, unsafe reset metadata, unresolved conflicting instructions or changed head cannot degrade to a plain patch brief.
5. **Identity scoping** — bind repo/PR/head and comment ids; reject foreign-repository exclusions and unlinked answers.
6. **State over time** — apply existing request resolution and answer supersession; rebuild on each round/head and retain unresolved obligations across a mechanical reset.
7. **Who wrote it** — use existing posting-principal checks and sanctioned envelope parsing; attributed actor prose is not cryptographic human presence.
8. **Receive/write endpoint abuse** — no new endpoint. Existing readers, GitHub ceremonies and repair claims remain in use. The mandatory-section byte cap bounds prompt assembly; repeated reset authorization still requires the existing repeat trigger and valid operator baseline. HTTP CSRF/origin checks and new rate limits are not applicable to this internal reader/brief change.
