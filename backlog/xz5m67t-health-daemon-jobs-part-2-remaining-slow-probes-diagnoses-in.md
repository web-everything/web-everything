## Edge cases this change must handle

One line per class: either the handling, or `n/a: <why>`.

1. **Untrusted text** — probe output and investigation findings are scrubbed at capture (`scrubText`/`scrubDeep`) before any record, sidecar or report write, as slice 1 does.
2. **Truncated reads** — a truncated, oversized, corrupt or unreadable job record or scan page is unavailable evidence, never proof that a job recovered (Design 5).
3. **Shared state files** — only the tick writes health state; the serial lifecycle job alone writes the investigation ledger; job records go through the runtime's per-record lock.
4. **Fail closed** — a queued/running/failed read never becomes a healthy empty sample; an indeterminate investigator launch keeps its slot and is reaped, never relaunched.
5. **Identity scoping** — the tick reattaches only health-owned records; other daemons' records are read-only evidence; foreign-host handles are reported, never judged.
6. **State over time** — diagnosis intents and dispatch reservations are durable before their job is admitted; consumed result ids persist with the episode state.
7. **Who wrote it** — results carry their job id and generation; a diagnosis result whose episode id no longer matches the subject's current episode is rejected.

## Design (prepared for #4131, 2026-10-08)

1. Declare health job kinds in we:skills-src/conveyor/daemon-manifest.mjs using the existing shared kind contract. Export kind definitions built with `defineJobKind` and `kindRegistry` from we:scripts/lib/daemon-jobs.mjs:60; the health tick must consume them explicitly because manifest registration alone does not run jobs. Declare probe, diagnosis and investigation-lifecycle kinds with pinned `readonly-tree` code, an explicit daemon cap of two, and `serial: true` for investigation lifecycle work. Reserve one of the two slots for that lifecycle by admitting at most one nonterminal probe/diagnosis job into the health job store at a time (including queued/backoff work). Keep the other due intents in tick-owned state in oldest-due order. Also allow at most one nonterminal lifecycle job. The shared runtime can then admit both kinds without an older probe backlog consuming the lifecycle slot; a launch callback that merely refuses an already-selected probe would not suffice because admission has already truncated the candidate list. Use the full kind registry on every reattach so stalled jobs never look undeclared. This is adopter-side enqueue discipline, not a change to global runtime admission policy. Keep the existing runtime attempt/backoff defaults; these mechanical attempts do not grant another investigator admission. Add we:scripts/conveyor/health-watch-job.mjs (planned) as the child entry composing `runJob`; reuse the shared runtime without copying its handle, retry, snapshot or lock implementation. Introduce per-kind rollout switches, initially retaining inline execution until live proof passes; disabling new job admission must still reconcile already-running jobs before returning that kind to inline execution.
2. In we:scripts/conveyor/health-watch.mjs separate cheap local reads from command/network probes. Queue due slow reads: daemon status, command-backed heavy status/process reads, clone comparison, verification-head and untracked-card reads, GraphQL/REST budgets, credential inventory, PR/agent/stale-state/merged-PR reads and their dependent reads, including `buildSessions`. Preserve each existing cadence and the separate inventory stamp. Leave the side-effecting session-watchdog, clone-ref refresh and maintenance paths under their current owners and include their costs in the tick proof. Keep dependent inputs in the same job input/result generation. Before lifecycle admission, persist the current episode/config view so a child cannot launch from state that only existed in the parent's memory. Persist a pending diagnosis intent with the episode state before admitting its job, then use an episode-derived stable job ID to enqueue/recover it on subsequent ticks. Do not rely on the opening transition being emitted again. Queue deterministic diagnosis commands by episode ID, preserving completed/failed outcomes so restart cannot repeatedly reschedule an exhausted diagnosis. A due probe with a queued or running job gets no duplicate. Persist absolute state, lane-pool, source-repository and log roots in job input/environment so snapshot-relative defaults cannot inspect an empty snapshot instead of the host. Fixture and dry-run paths must remain isolated from host reads and dispatch. A dry run neither enqueues nor reattaches with side effects. Use the planned we:scripts/conveyor/health-watch-job.mjs entry for both the job supervisor and its explicit worker mode, keeping the scope to one new source/test pair. Run existing synchronous probe bodies in a worker beneath the heartbeat-owning job process; the parent job event loop must remain free to heartbeat during a 300-second read. Bound each command, propagate errors, and terminate subordinate work when its owning job stops so a retry cannot overlap an orphan probe. Cover forced supervisor death as well as graceful termination: record subordinate identity, and confirm that work is gone before relaunch; a SIGTERM-only cleanup handler is insufficient. Preserve the watchdog's independently owned fresh process read when no new process result is available, rather than passing a stale or fabricated empty process list into an acting watchdog. Charge that fallback to the measured tick cost. Append heavy-run history only for a newly consumed process result, using its sample timestamp; queued ticks must not manufacture repeated observations or error samples.
3. Results belong to the job record/checkpoint and contain scrubbed values, sample time, per-probe errors and a generation/job ID. Only the tick writes health episode state, cursors, cadence stamps and reports. It consumes each completion once, independently per probe, retaining partial-success semantics. Queued/running/failed reads never become healthy empty samples. Missing fresh samples suspend the dependent smell's hysteresis; replaying a cached completion must not count as another observation. Pass explicit sampled/succeeded probe identities into we:scripts/conveyor/health-watch-core.mjs so an unsampled tick does not clear a pending probe-error streak (current clearing loop: we:scripts/conveyor/health-watch-core.mjs:724).
4. Refactor we:scripts/conveyor/health-investigate-dispatch.mjs into lifecycle IO and tick-side projection. The serial job owns investigation ledger changes; the tick reads ledger/findings and alone annotates episodes and reports. Move report acknowledgement into tick-owned state, honoring legacy `reportedAt` values on migration. Make the closed-report investigation section an idempotent replacement keyed by episode/session, then acknowledge it; a crash after the report write but before state persistence must not append it twice. Persist consumed result IDs together with the episode/cadence state, and reject diagnosis results whose episode ID no longer matches the subject's current episode. Keep `dispatch-lane`, recording tokens, one-per-episode admission, running/window/subject caps, wall-clock reap and the dispatch-off default. Persist the episode/session reservation before invoking dispatch; on restart reconcile the deterministic session identity before any retry. An indeterminate launch keeps its slot and is reaped under the existing policy; it must never launch a second investigator. Mechanical job recovery does not resume a bot session. Closed-episode findings still appear once. A lifecycle job ends after a bounded reconcile/admit pass; it does not wait for the investigator to finish. Queue another pass on later ticks even with new dispatch disabled so existing sessions are still reaped. Keep reporting available while that pass is pending, and preserve `--no-investigate` behavior. Use the durable reservation as the replay boundary: mechanical retries reconcile an existing reservation, never repeat its dispatch merely because the job checkpoint was not written. Represent the pre-dispatch reservation as the existing running/indeterminate ledger shape, with deterministic session, token hash and deadline already durable; existing caps and reaping then count it without extending the policy status vocabulary. Re-read current episode IDs, diagnoses, inhibiting episodes and dispatch configuration immediately before admission rather than trusting a possibly delayed job-input snapshot. Preserve pending report delivery when pruning: retain entries with findings awaiting tick acknowledgement in the IO composition, while continuing to apply the existing budget windows and open-episode tombstones from we:scripts/conveyor/health-investigate-plan.mjs:148.
5. Reattach health-owned jobs on the first and subsequent ticks, leaving live handles alone and using the core's stop-before-relaunch/backoff rules. Read other daemons' records without mutating or reattaching them. Preserve the existing `operationRuns` array and its newest-first limits for current consumers; extend discovery with a separate job-evidence result containing owner, corruption, liveness and scan-completeness metadata needed by we:scripts/conveyor/health-smells/daemon-job-health.mjs (planned). Run job-directory discovery as a read-only probe job, with bounded streaming directory reads and bounded result pages; never gather/stat/sort the entire directory in the tick. Persist per-owner progress and deduplicate record identities across scan restarts; a restarted directory walk is incomplete until it reaches the end, not a trustworthy numeric offset into a changing directory. Scan daemon job directories independently of the seven-hour operation lookback so old stalled/failed jobs cannot disappear. Budget records/bytes and handle probes, persist the scan cursor in tick state, and evaluate absence/recovery only after the relevant owner has a complete fresh scan. A truncated, oversized, corrupt or unreadable portion is unavailable evidence, not proof that jobs recovered. Reuse `classifyJob` for heartbeat/launch-grace classifications rather than inventing a duration timeout for all job kinds. Evaluate stalled/dead jobs and exhausted/failed retries; include foreign-host and corrupt-record evidence as unavailable/abnormal, never healthy. Report owning daemon, kind, record ID, attempt and bound. Also cover cap-saturation and orphan-job observations using explicit declared cap/queue and verifiable handle evidence; when another adopter supplies no cap or identity evidence, report that dimension unavailable rather than assuming health; do not infer an orphan merely from an arbitrary Node process. Discovery registers the new smell automatically (we:scripts/conveyor/health-smells/index.mjs:11). A single-shot tick cannot retain `createTickClock` memory between invocations; supply its supported `observation` using persisted wall/host-monotonic samples (not process-relative `performance.now()`), discarding them on boot-identity change, and test the runtime sleep-detection rule across tick processes.
