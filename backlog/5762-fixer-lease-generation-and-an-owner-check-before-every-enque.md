# Fixer lease generation and an owner check before every enqueue

Slice L1 of the async-daemons epic; the only lease change in scope. Every acquire of the fixer's runner lease (normal, expired-TTL takeover, dead-pid takeover) bumps a monotonic `generation` in the lease record. The scheduler requires `owner == me && generation == myGeneration` at tick start and again right before each enqueue; a holder paused past the 15-min TTL (e.g. SIGSTOP) then resumed fails the check and exits without enqueuing. Tick shortening belongs to #5759/#5765; this slice keeps the heartbeat in the tick lifecycle and records `lastTickCompletedAt` only after successful completion. The health daemon alerts when completion falls behind `tickStaleAlertMs` (cascade setting), independently of log growth. Current inline dispatch/resume boundaries receive the same guard that the task scheduler will consume. The drain lease (we:scripts/readiness/drain-lock.mjs) is a separate file and stays unchanged (R4).

## Acceptance

- [A1] **Executable** — the lease record carries `generation` (bumped on every acquire, including TTL and dead-pid takeovers) and `lastTickCompletedAt`; the scheduler checks owner and generation at tick start and before each enqueue; the health daemon alerts on a stale `lastTickCompletedAt`.
- [A2] **Crash test (a)** — SIGSTOP the holder past the TTL; a new holder acquires and the generation goes up; the old holder resumes, enqueues nothing, and exits (J2-0, J2-12).
- [A3] **Crash test (b)** — tasks of an older generation are adopted, not fenced, and their claims stay valid.
- [A4] **Crash test (c)** — a tick that wedges while the process lives: `lastTickCompletedAt` goes stale and an alert fires (J2-18).
- [A5] **Crash test (d)** — the drain lease's behaviour is byte-for-byte unchanged (J2-16).
- [A6] **Live** — the fixer log shows `gen=` across one restart, incrementing by 1.

## Non-goals

- [N1] The drain lease (R4).
- [N2] Blue-green lease transfer (sibling epic).

## Edge cases this change must handle

One line per class: either the handling, or `n/a: <why>`.

1. **Untrusted text** — n/a: the lease record is written only by the daemon; no external text enters it.
2. **Truncated reads** — An unreadable or partial lease record fails the owner check, so the tick stops and enqueues nothing.
3. **Shared state files** — Add serialized generation allocation and publication for the fixer key; the current runner wrapper does not supply that transaction. Preserve generation history across release and restart; never reset on an unreadable counter.
4. **Fail closed** — Any failed owner/generation check prevents new scheduling and stops the loop. It does not undo an already accepted task or invalidate its claim.
5. **Identity scoping** — Add process start time to the fixer ownership token; the current host:pid:kind string does not distinguish PID reuse. Other runner keys retain their existing contract.
6. **State over time** — SIGSTOP past the TTL and a wedged-but-alive tick are both covered by tests (a) and (c).
7. **Who wrote it** — Only the lease holder writes the record; the drain lease file is never touched.

## Design

1. **Opt-in fixer lease capability.** Extend we:skills-src/conveyor/runner-lock.mjs with a generation-aware mode for the fixer key; keep existing callers/other keys on the legacy path. Return a captured token containing key, owner, process-start identity and generation. Compose the existing process-start reader/handle functions from we:scripts/lib/daemon-jobs-runtime.mjs:60 rather than treating `kill(pid, 0)` as proof of identity. Validate the stored handle before probing: `probeHandle` at we:scripts/lib/daemon-jobs-runtime.mjs:78 returns dead for a malformed handle, which must instead be unknown for mutation-mutex reclamation. A failed start-time read refuses new generation-aware acquisition; malformed or unreadable mutex identity never authorizes removal. Keep the owner's role segment parseable by health; put start identity in metadata and the token. Make the owner string unique per acquisition (encode an acquisition nonce in its host segment without adding colon segments, and carry the real hostname separately in metadata for liveness checks); an owner must never recur across generations. The owner-specific heartbeat primitive hashes only owner, not generation, so a generation check before its write alone cannot protect a reused owner. Store immutable generation/identity/acquired-at metadata in the lease's existing `meta` object. The lease view exposes `lastTickCompletedAt` from an owner-and-generation-qualified completion sidecar; do not pretend that the generic parser preserves arbitrary fields.
2. **Persistent, serialized allocation.** Maintain a per-key generation counter outside the disposable lease directory, atomically replace it before publishing a successful new lease, and retain it on release. First creation starts at 1; a legacy lease has no generation and gets one only on legitimate acquisition, never by upgrading another live holder. A clean release/restart advances by exactly 1. A crash after counter reservation may leave a gap, but must never reuse a number. Malformed existing counter state refuses acquisition with a diagnostic, not a reset. Serialize acquire/counter publication and conditional release with a short per-key mutation mutex using existing filesystem primitives. That mutex is process-identity guarded and reclaimed only on confirmed death, never by TTL while its holder may resume; contention returns a bounded refusal. The scheduler lease itself retains TTL/dead-process takeover. No network call, tick, or enqueue holds the mutation mutex. A paused mutation can delay takeover until it finishes or its process is confirmed dead; safety wins over bypassing the mutex.
3. **No stale writer can restore its lease.** For this opt-in path use immutable lease metadata and owner-specific heartbeat writes, composing `heartbeatOwn` from we:scripts/readiness/file-locks.mjs:267. Write completion atomically to a token-qualified sidecar and read only the current token's sidecar. Heartbeat/completion/release all verify the captured generation as well as owner; release is serialized with acquisition. A resumed old holder must neither overwrite the new record nor remove it. Keep we:scripts/readiness/file-locks.mjs and we:scripts/readiness/drain-lock.mjs unchanged; the shared primitive already exposes metadata and owner-specific heartbeats.

The asynchronous CI-heal adapter must likewise rethrow it. Check again after synchronous or asynchronous preparation before calling an enqueue effect. In the fix source, propagate through conflict resume and ordinary round resume to the shared resume spawn, and through native, wrapped, and routed/borrowed fresh launches. Lease loss in round resume must never become a cold-start fallback. Run the assertion before marking a launch attempted, and clean up only this invocation's unsent claim/prompt/reservation when it fails. Standalone callers keep their existing behavior when no scheduler token is supplied. This is a scheduler admission check, not a transactional fence around remote effects; per-PR claim/effect fencing remains independent. #5759 must use this same assertion at each future job enqueue, not only at tick entry.
   In we:scripts/operations/dispatch-lane-io.mjs add an optional admission assertion to `createDispatchSinks`, pass it to native provider/launcher ports, and invoke it after request/settings construction immediately before provider admission.
