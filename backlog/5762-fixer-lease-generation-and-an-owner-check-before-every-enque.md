# Fixer lease generation and an owner check before every enqueue

Slice L1 of the async-daemons epic; the only lease change in scope. Every acquire of the fixer's runner lease (normal, expired-TTL takeover, dead-pid takeover) bumps a monotonic `generation` in the lease record. The scheduler requires `owner == me && generation == myGeneration` at tick start and again right before each enqueue; a holder paused past the 15-min TTL (e.g. SIGSTOP) then resumed fails the check and exits without enqueuing. Tick shortening belongs to #5759/#5765; this slice keeps the heartbeat in the tick lifecycle and records `lastTickCompletedAt` only after successful completion. The health daemon alerts when completion falls behind `tickStaleAlertMs` (cascade setting), independently of log growth. Current inline dispatch/resume boundaries receive the same guard that the task scheduler will consume. The drain lease (we:scripts/readiness/drain-lock.mjs) is a separate file and stays unchanged (R4).

## Acceptance

- [A1] **Executable** — the lease record carries `generation` (bumped on every acquire, including TTL and dead-pid takeovers) and `lastTickCompletedAt`; the scheduler checks owner and generation at tick start and before each enqueue; the health daemon alerts on a stale `lastTickCompletedAt`.
- [A2] **Crash test (a)** — SIGSTOP the holder past the TTL; a new holder acquires and the generation goes up; the old holder resumes, enqueues nothing, and exits (J2-0, J2-12).
- [A3] **Crash test (b)** — tasks of an older generation are adopted, not fenced, and their claims stay valid.
- [A4] **Crash test (c)** — a tick that wedges while the process lives: `lastTickCompletedAt` goes stale and an alert fires (J2-18).
- [A5] **Crash test (d)** — the drain lease's behaviour is byte-for-byte unchanged (J2-16).
- [A6] **Live** — the fixer log shows `gen=` across one restart, incrementing by 1.

## Non-goals

- [N1] The drain lease (R4).
- [N2] Blue-green lease transfer (sibling epic).

## Edge cases this change must handle

One line per class: either the handling, or `n/a: <why>`.

1. **Untrusted text** — n/a: the lease record is written only by the daemon; no external text enters it.
2. **Truncated reads** — An unreadable or partial lease record fails the owner check, so the tick stops and enqueues nothing.
3. **Shared state files** — Add serialized generation allocation and publication for the fixer key; the current runner wrapper does not supply that transaction. Preserve generation history across release and restart; never reset on an unreadable counter.
4. **Fail closed** — Any failed owner/generation check prevents new scheduling and stops the loop. It does not undo an already accepted task or invalidate its claim.
5. **Identity scoping** — Add process start time to the fixer ownership token; the current host:pid:kind string does not distinguish PID reuse. Other runner keys retain their existing contract.
6. **State over time** — SIGSTOP past the TTL and a wedged-but-alive tick are both covered by tests (a) and (c).
7. **Who wrote it** — Only the lease holder writes the record; the drain lease file is never touched.

## Design

1. **Opt-in fixer lease capability.** Extend we:skills-src/conveyor/runner-lock.mjs with a generation-aware mode for the fixer key; keep existing callers/other keys on the legacy path. Return a captured token containing key, owner, process-start identity and generation. Compose the existing process-start reader/handle functions from we:scripts/lib/daemon-jobs-runtime.mjs:60 rather than treating `kill(pid, 0)` as proof of identity. Keep the owner's role segment parseable by health; put start identity in metadata and the token. Make the owner string unique per acquisition (encode an acquisition nonce in its host segment without adding colon segments, and carry the real hostname separately in metadata for liveness checks); an owner must never recur across generations. The owner-specific heartbeat primitive hashes only owner, not generation, so a generation check before its write alone cannot protect a reused owner. Store immutable generation/identity/acquired-at metadata in the lease's existing `meta` object. The lease view exposes `lastTickCompletedAt` from an owner-and-generation-qualified completion sidecar; do not pretend that the generic parser preserves arbitrary fields.
2. **Persistent, serialized allocation.** Maintain a per-key generation counter outside the disposable lease directory, atomically replace it before publishing a successful new lease, and retain it on release. First creation starts at 1; a legacy lease has no generation and gets one only on legitimate acquisition, never by upgrading another live holder. A clean release/restart advances by exactly 1. A crash after counter reservation may leave a gap, but must never reuse a number. Malformed existing counter state refuses acquisition with a diagnostic, not a reset. Serialize acquire/counter publication and conditional release with a short per-key mutation mutex using existing filesystem primitives. That mutex is process-identity guarded and reclaimed only on confirmed death, never by TTL while its holder may resume; contention returns a bounded refusal. The scheduler lease itself retains TTL/dead-process takeover. No network call, tick, or enqueue holds the mutation mutex. A paused mutation can delay takeover until it finishes or its process is confirmed dead; safety wins over bypassing the mutex.
3. **No stale writer can restore its lease.** For this opt-in path use immutable lease metadata and owner-specific heartbeat writes, composing `heartbeatOwn` from we:scripts/readiness/file-locks.mjs:267. Write completion atomically to a token-qualified sidecar and read only the current token's sidecar. Heartbeat/completion/release all verify the captured generation as well as owner; release is serialized with acquisition. A resumed old holder must neither overwrite the new record nor remove it. Keep we:scripts/readiness/file-locks.mjs and we:scripts/readiness/drain-lock.mjs unchanged; the shared primitive already exposes metadata and owner-specific heartbeats.
4. **Guard the real boundaries.** In we:skills-src/conveyor/reconcile-fix-dispatch-daemon.mjs check the token before the wrapped tick (including claim-refresh wrappers), thread an injectable assertion through the all-repo adapters and into both dispatch modules, and check immediately before each resume/new dispatch. Lease loss is terminal, not a routine per-PR refusal swallowed by existing catch blocks; unwind to the daemon's existing exit path. For the fix adapter, use a local loop that rethrows lease-loss errors while retaining ordinary per-repo isolation; do not route the terminal signal through the stringifying shared helper. The asynchronous CI-heal adapter must likewise rethrow it. Check again after asynchronous preparation before calling an enqueue effect. Standalone callers keep their existing behavior when no scheduler token is supplied. This is a scheduler admission check, not a transactional fence around remote effects; per-PR claim/effect fencing remains independent. #5759 must use this same assertion at each future job enqueue, not only at tick entry.
   Cover verify-resume in both the tick fallback and fast child: thread the captured parent scheduler token/root through we:scripts/conveyor/await-verify-loop.mjs, check it at cycle entry and in we:scripts/conveyor/await-verify-pass.mjs immediately before stopping an idle session and again before the actual spawn after the exit wait. Forward it through legacy-pass, cycle, and IO factories; ordinary per-record/cycle catches must propagate lease loss. A supervised child with missing/malformed token fails closed, exits on loss, and cannot be restarted by a stale supervisor: the supervisor passes an explicit supervised marker alongside the token, so a dropped or unreadable token under that marker exits with the distinct invalid-token/`lease-lost` reason instead of falling back to standalone behavior (the explicit missing/malformed token cases are enumerated in the Test plan's "Supervised child with a missing or malformed scheduler token" bullet). Its loop heartbeat must identify the parent token so a new holder cannot mistake an old child for its own. This child schedules resumes; it is not an adopted repair worker. Guard CI-heal's retry request after observation and outside the catch that converts request errors into ambiguous API outcomes; release a fresh unsent reservation before propagating loss, preserving inherited pending requests. Mechanical push/promotion and already accepted work retain their existing effect/claim contracts.
5. **Completion and monitoring.** A successful whole tick stamps completion and refreshes the heartbeat; a thrown/unfinished tick cannot advance completion. Before the first completed tick, acquisition time is the age baseline. In we:scripts/conveyor/health-watch.mjs enrich the fixer's production daemon-status row from the keyed lease view, as well as the explicit fixture lease-scan path. Resolve `tickStaleAlertMs` with `cascadePolicy` from we:scripts/lib/policy-cascade.mjs:176, using the existing health config as the tool layer and logging the selected source. Use the existing silence floor of ten minutes as the initial standard default; validate finite positive overrides. This does not impose the sibling's 15-second tick target. In we:scripts/conveyor/health-smells/daemon-silent.mjs prefer completion age for generation-aware fixer records, irrespective of fresh heartbeat or noisy logs; preserve existing behavior for other daemons/legacy records. Missing or corrupt completion for a new-format lease never counts as fresh. Route through the existing episode/notification settings, without enabling notifications or investigation in shadow mode.
6. **Scheduler generation is not worker generation.** Do not add the scheduler token to worker claim validity or change job-store generation semantics. Existing reattachment at we:scripts/lib/daemon-jobs-runtime.mjs:288 judges worker handles and job state independently. A new scheduler may observe/adopt existing live work without stopping, re-enqueueing, or stealing its claims merely because the scheduler generation changed. This follows we:docs/agent/platform-decisions.md#daemon-jobs. The task-mode integration belongs to #5759/#5765.

## Proof plan

- In an isolated temporary lock/job root, launch holder A with a recording enqueue sink. Stop it with SIGSTOP between tick entry and its next enqueue guard, advance past the injected short test TTL, then launch B and capture its strictly greater generation. Resume A; assert zero subsequent enqueues from A, a lease-lost exit, and unchanged B ownership. Repeat with A stopped during heartbeat/release boundaries. Run the supervised verify child against the same captured token and recording resume sink; after takeover it must schedule no further resumes and exit, while the new holder ignores its stale loop heartbeat. Repeat the supervised child launch once with the token omitted and once with a corrupted token; both must schedule zero resumes and exit before any stop or spawn. Always reap children in cleanup; never suspend the production fixer for this test.
- In the same harness, leave a live worker job and claim from A in place. After B acquires, record adoption without duplicate launch or claim invalidation. Attach the job/claim snapshots and the ordered enqueue log to the implementation review.
- Wedge a tick while its process remains alive; feed its actual lease/completion view through the health shell with a short cascade override. Capture the stale-completion episode even while log output continues, then complete a later tick and show recovery under existing hysteresis. Distinguish an episode in shadow mode from an actually delivered notification.
- After implementation is deployed through the normal runner lifecycle, capture one clean fixer restart with acquisition logs `gen=N` then `gen=N+1`, the resolved threshold/source, and a completed-tick timestamp. Do not claim short-tick performance from this change. Compare drain/shared-lock blobs and attach queued test/gate output. Preparation itself performs no live restart or implementation proof.
