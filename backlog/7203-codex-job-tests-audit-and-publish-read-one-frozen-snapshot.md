# codex-job: tests, audit and publish read one frozen snapshot

## Digest

> Code status: `we:scripts/operations/codex-job.mjs` is not on `main`. It exists only in the closed #5839 seed patch, so every `we:scripts/operations/codex-job.mjs:NNN` reference below is a line in that patch, not in the tree. The seed patch is a delta on the earlier #5839 branch, so function names and line numbers below come from that branch file and cannot be re-checked on `main`; the build must re-verify each at implementation time. Code blocks are sketches: `cleanGitEnv`, `trustedGitDir`, `materializeTree` and `snapshotTreeSha` are proposed names, not seed names. This card decides the redesign before the file is rebuilt.

PR #5839 ran through 18 review rounds and was closed because incremental worktree-based fixes kept uncovering a new break class almost every round: credential capture via inherited helpers and environment variables, time-of-check to time-of-use (TOCTOU) races between diffing and staging, source rewrites in passing `afterAll` hooks or under `.gitattributes` `text eol=lf` normalization, relative `remote.origin.url` paths resolving differently between the primary worktree and the publication clone, and finally a surviving test subprocess alternating file bytes or modes so that Git fingerprints and tests see bytes A while the pre-test snapshot, audit export, and publication export all read bytes B. As long as tests execute inside the mutable lane worktree or share write access to the files later read for audit and publication, a background child process spawned during an earlier step can time its writes between checks and cause untested bytes to be published.

| Fork | Recommended default | Main alternative | Confidence |
|---|---|---|---|
| Fork 1 — Snapshot mechanism | **(a) Raw blobs captured into a temporary index and exported from the resulting Git tree** | (b) Direct filesystem copy of the lane worktree | High |
| Fork 2 — Test isolation and process cleanup | **(a) Run tests inside an isolated disposable copy of the frozen snapshot and kill the whole process group on exit** | (b) Run tests in the lane worktree and verify post-test fingerprints | High |
| Fork 3 — Bounding Codex worker and repair output | **(a) Extract only in-scope paths from the lane into the snapshot tree** | (b) Require Codex to emit a unified diff patch file only | Med-High |
| Fork 4 — Process isolation level | **(a) Same user, process-group kill, tree-SHA binding** | (b) OS sandbox | Med |

## Trust boundary and threat model

The job runner (`we:scripts/operations/codex-job.mjs`) orchestrates untrusted model generations and untrusted test execution before pushing a verified commit to a trusted remote.

- **Trusted:** The runner process itself (`we:scripts/operations/codex-job.mjs`), the initial base commit SHA (`startSha`) resolved once from the remote, the declared `scope` prefixes, the sanitized Git execution wrapper (`trustedGit`), and the runner-owned temporary directories outside the lane worktree.
- **Adversarial:**
  - **Codex worker and repair output:** Can write arbitrary files, symlinks, gitlinks, `.git/config`, hooks, `.gitattributes`, or out-of-scope paths in the lane worktree, and can leave background processes running after the Codex CLI exits.
  - **Test subprocesses:** Can mutate sources during or after tests (e.g., `afterAll`), fork detached background processes that outlive the test runner, watch filesystem access or procfs to alternate bytes A and B between Git fingerprint checks and Node `readFile`/`lstat` exports, or attempt to read credentials from the environment.
  - **Git configuration, remotes, and hooks:** Repository `.git/config`, `.githooks`, system/global gitconfigs, credential helpers, replacement refs, filters (`textconv`, `ext-diff`, `smudge`/`clean`), and relative `remote.origin.url` definitions.
- **Residual risk proposed for v1 (subject to Fork 4 ratification):** a same-user child that escapes the process group (for example with `setsid`) can write anything the runner user can write, including runner code, trusted objects and primary-checkout dependencies. Mode 0700, chmod and a tree SHA do not isolate processes with the same UID. V1 protects publication from ordinary lane/test-directory rewrites, assuming runner code, recorded SHAs and the trusted object store remain trustworthy; it does not protect against targeted same-UID compromise of those assets. Object-integrity checks catch the corruption exercised by DW-objects, but cannot close a same-user check/use race. Network egress and non-environment credential files are also not blocked in v1; an allowlisted child environment and an initially empty runner-owned `HOME` reduce exposure (DW-test-env). Fork 4 (b) is required if hostile same-user execution must be contained.
- **Explicitly out of scope:** Kernel or hardware compromises, root-level attackers on the host machine, availability denial-of-service via infinite loops (bounded only by timeouts), and side-channel attacks across separate OS users.

**The Frozen-Input Rule:** After the Codex worker (or repair step) exits and its process group is killed, the runner captures the in-scope working tree into one content-addressed snapshot. Cleanup does not prove every descendant exited. Validate the captured paths, modes and raw bytes; concurrent reads need not represent a single instant of the lane. Tests start from a disposable materialization of that tree, audit consumes its trusted diff, and publication uses its recorded SHA. No downstream phase re-reads the lane for that attempt (DW-no-read). Each repair is a new attempt with its own capture. This binds initial test inputs and audit/publication identity; arbitrary malicious tests can still rewrite their own executable files during execution. Same-UID attacks on trusted assets remain the Fork 4 residual risk.

| Input | Trust level | Frozen when | Who may read it after |
|---|---|---|---|
| `originUrl` and `startSha` | Untrusted config input, verified once | Bootstrap (`prepareTrustedRepo`) before lane acquisition | `trustedGit` clone, `ls-remote`, and `push` only |
| Allowed `scope` and brief | Trusted caller input | Job initialization (`runJob` start) | Scope validator, snapshot builder, audit prompt builder |
| Lane working tree (`s.lane.path`) | Adversarial | Never trusted directly; scraped once per attempt into a frozen tree object after process-group teardown | Nothing; never read by tests, audit, or publication after snapshot |
| Initial worker workspace | Trusted raw base at handoff; adversarial after worker starts | Materialize `startSha` from trusted raw blobs before the first worker spawn; never inherit a converted checkout as the comparison baseline | Worker, then capture; repairs instead start from the prior snapshot (DW-baseline, DW-repair) |
| Frozen snapshot (`snapshotTreeSha` + trusted objects) | Trusted under the Fork 4 same-UID limitation | Immediately after worker (and once more after repair if tests fail) | Tests via disposable materialization, audit via trusted diff, publication via tree SHA |
| Test failure output (`stdout`/`stderr`) | Adversarial | When the first test run exits red | Repair prompt builder only; escape `&`, `<` and `>` after combining streams, then cap the serialized failure-data body at `failureDataMaxBytes = 65536` UTF-8 bytes without splitting a code point (DW-repair-prompt) |
| Test, worker, repair and audit environments | Adversarial inherited runner environment | Construct an allowlist before every spawn; tests use `cleanTestEnv`, each role starts with its own empty mode-0700 `HOME` | Child receives only declared execution settings and explicitly provisioned model authentication where needed; no inherited secrets, publication credentials or `GIT_*` overrides (DW-test-env, DW-process) |

| Audit verdict (`NOT WEAKENED` / `WEAKENED`) | Adversarial model output | Upon audit process exit | Runner verdict parser (`runAudit`) only; accept only the single final response block with this invocation's runner-chosen delimiter ID, never verdict tokens in data or prose (DW-audit-prompt, DW-missing-verdict) |

No path is linked from the disposable test or repair directory into the primary checkout or trusted store. A symlink is not a read-only mount; hardlinks plus chmod also share writable inodes with a same-UID process.

| Provisioned path | Source and trust | Write behavior and acceptance |
|---|---|---|
| Snapshot source files | Recorded tree blobs, not live lane files | Private regular-file copies plus validated unchanged base links resolving only inside that workspace; mutations do not update trusted objects (DW-writer, DW-materialize, DW-base-links) |
| `node_modules/` | Fresh private installation from the candidate snapshot's `we:package.json` and `we:package-lock.json` | Require manifest/lockfile consistency and successful `npm ci` on a raw materialization of that exact candidate before tests and publication; never substitute primary-checkout dependencies or its lockfile. Use the prior snapshot for repair provisioning, then repeat installation for the repaired candidate. Missing/inconsistent manifests, install failure or attempted manifest/lockfile rewrites refuse publication. Dependencies have distinct inodes from primary/trusted storage; resolve package-manager links only inside the private dependency tree and refuse unresolved/external links (DW-dependencies, DW-inputs). |
| Required untracked generated inputs | Explicit caller manifest of trusted generated inputs with recorded SHA-256 byte digests, never arbitrary lane leftovers | Hash the exact bounded bytes copied into each private regular file and compare with the manifest before test/repair execution; missing, malformed or mismatched digests refuse provisioning. Never verify one source read then copy a second read. Apply explicit per-file and aggregate limits: each read requests at most `min(remainingFileBytes, remainingTotalBytes) + 1`, with cumulative returned bytes at most file-limit+1 and total-limit+1; stop on overflow with an operator-visible limit and retry/reduce-input guidance. Reject links/special files and collisions with snapshot paths; test-only inputs stay out of the published tree (DW-inputs, DW-input-bounds) |
| Repair workspace | Prior recorded tree plus the same private input provisioning | Fresh materialization for the one repair attempt (DW-repair) |

Private copies prevent accidental write-through; they do not deny a same-UID process direct access to primary paths outside the disposable directory.

## Fork 1 — Snapshot mechanism

**Fork-existence justification:** Case (a) forced invariant — reading loose files from a live worktree across multiple passes (diff, hash-object, `readFile`, `lstat`) is broken under concurrent writer races and `.gitattributes` line-ending normalization (`we:scripts/operations/codex-job.mjs:237-358`).

How the runner freezes the post-Codex state into an immutable artifact before running tests, audit, or publication:

- **(a) Capture raw blobs into a temporary index (`GIT_INDEX_FILE`) and export the resulting tree blob by blob (Recommended default).** Before the first worker starts, populate a fresh lane workspace from raw `startSha` blobs and recorded modes, without checkout conversion, then record the Git-metadata baseline (DW-baseline). Read each validated regular file once into a bounded buffer, write those exact bytes using `hash-object -w --no-filters --stdin`, and populate the index using NUL-delimited `update-index -z --index-info` records. Start from `startSha`, include deletions, then `write-tree` and validate the resulting tree/diff. Git never stages a lane filename and therefore cannot apply lane `.gitattributes`. `core.autocrlf=false` and `core.eol=lf` alone do not disable `text`, `ident`, encoding or clean filters. Tradeoff: raw base materialization before the worker, one raw blob ingestion per changed file, one tree write and extraction per attempt, binding content and executable modes (`100644`/`100755`). Preserve only unchanged, safe trusted-base symlinks under the policy below; reject other symlinks and all gitlinks (DW-bytes, DW-base-links, DW-symlink, DW-gitlink).
- **(b) Copy changed files directly from the lane worktree into a temporary directory using Node `fs` (`readFile`/`lstat`/`writeFile`).** *Rejected:* Node-level file copying across multiple syscalls is non-atomic against a surviving process and still requires a separate staging step later to build the published Git commit, reintroducing a two-representation gap between what was copied and what Git commits.
- **(c) Create a `git worktree` or filesystem overlay mounted over the lane.** *Rejected:* A Git worktree shares the repository state and starts from a committed ref rather than uncommitted lane edits, while OS overlay mounts require elevated privileges not portable across developer macOS and Linux environments.

```js
// Fork 1 (a) — capture one immutable Git tree object in trustedDir
const env = { ...cleanGitEnv, GIT_DIR: s.trustedGitDir, GIT_INDEX_FILE: tempIndex };
await trustedGit(['read-tree', s.startSha], { s, env });
const records = [];
for (const entry of await captureValidatedLaneEntries(s)) {
  if (entry.deleted) { records.push(deletionIndexRecord(entry.path)); continue; } // DW-deletion
  const { stdout } = await trustedGit(['hash-object', '-w', '--no-filters', '--stdin'],
    { s, env, input: entry.bytes });
  records.push(nulIndexRecord(entry.mode, stdout.trim(), entry.path));
}
// captureValidatedLaneEntries rejects every out-of-scope change before this point (DW-scope).
await trustedGit(['update-index', '-z', '--index-info'], { s, env, input: Buffer.concat(records) });
const { stdout: treeOut } = await trustedGit(['write-tree'], { s, env });
await validateSnapshotTree(s, treeOut.trim());
s.snapshotTreeSha = treeOut.trim(); // accepted attempt identity
```

The proposed capture helper enumerates the base tree's tracked paths plus actual filesystem entries, without traversing directory symlinks, with only explicit caller-declared test-input exclusions and the separately checked Git metadata boundary. Git status/diff and lane ignore rules cannot decide which files are changed: compare the captured raw blob OIDs, descriptor modes and presence to the base tree, so attributes cannot hide a CRLF-only edit. This comparison is valid because the worker initially sees raw base bytes, including LF, unexpanded ident tokens and repository encodings; ordinary checkout conversion never enters the baseline. Repair sees the prior snapshot's raw bytes (DW-baseline, DW-repair). Reject every raw out-of-scope change, including ignored/untracked paths (DW-bytes, DW-scope). The helper rejects unsupported types before opening them, uses no-follow/nonblocking file opens and validates the opened descriptor and path ancestry; it never opens a FIFO to wait for a writer. Mode is derived from that descriptor. NUL records preserve whitespace/newlines and leading dashes without path-option parsing; deletion records use mode 0 and the repository object format's zero OID. Set explicit per-file/total byte limits and timeouts. Each read request is at most the smaller remaining file/aggregate allowance plus one overflow-detection byte; stop immediately on overflow, with cumulative returned bytes at most file-limit+1 for any file and total-limit+1 across the attempt. Do not use an unbounded `readFile` followed by a size check. Oversized/unreadable input refuses publication with an operator-visible reason (DW-capture-errors).

**Trusted-base symlink policy:** retain a mode-120000 entry only when its path, mode and raw link-target bytes are identical to `startSha`, and its relative target resolves within the candidate snapshot to an existing source path, never Git metadata, runner storage or provisioned inputs. Validate the entire link chain, rejecting absolute/outside, dangling or cyclic targets and unsafe ancestor paths. Capture uses bounded `readlink` data, never opens the target through the link, and preserves the base link OID. Materialization creates validated regular files/directories first and these links last; never write a file through a symlink ancestor (DW-materialize-order). The repository's unchanged `.claude/agent-memory -> ../agent-memory-src` and `.claude/skills -> ../skills-src` are accepted and recreated entirely inside each private worker/test/repair workspace (DW-base-links). New, retargeted, moved, removed or type-replaced links refuse, even in scope; unsafe base links and all gitlinks refuse before worker execution (DW-symlink, DW-gitlink). Link-target buffers share the capture byte limits (DW-capture-errors).

Prepare-time Git spike (2026-10-25): with `* text eol=lf ident`, bytes `$Id: lane-value $\r\nconst x = 1;\r\n` changed under the old `update-index --add` sketch despite both EOL config settings. Raw `hash-object -w --no-filters --stdin` plus `update-index -z --index-info` retained identical bytes: blob `912a2f46b17bcda7604ce255795076ba37983e39`, tree `eff0384ae6025c2b64b74f95a856e28904b415b5` (SHA-1 scratch object store). This probes the plumbing, not the absent job implementation.

`Skeptic: SURVIVES — lane attributes cannot transform raw stdin blobs or index-info OIDs; Done when DW-bytes exercises text/eol, ident, encoding, clean filters and export attributes with byte/OID identity.`

## Fork 2 — Test isolation and process cleanup

**Fork-existence justification:** Case (a) forced invariant — running tests inside the mutable lane worktree (`we:scripts/operations/codex-job.mjs:273-320`) allows test hooks or background children to mutate files in place or survive across phases.

How the runner executes tests and prevents surviving subprocesses from interfering with subsequent steps:

- **(a) Materialize a disposable test worktree from `snapshotTreeSha` for each test run, spawn the runner in a dedicated process group (`detached: true`), and kill that group before returning (Recommended default).** Ordinary test/`afterAll` writes affect private copies; no exports from this mutable directory are staged for publication. Group cleanup kills descendants still in that group on success, failure and timeout (DW-process); escaped children are the Fork 4 limitation. Tests receive `cleanTestEnv` and an initially empty private `HOME` (DW-test-env). Tradeoff: extracting the tree and making private dependency/generated-input copies adds I/O per run (DW-inputs, DW-writer).
- **(b) Run tests in the lane worktree and compare pre-test and post-test `worktreeFingerprint` / `captureAuditExport` hashes.** *Rejected:* This is the exact seed-patch design (`we:scripts/operations/codex-job.mjs:297-358`) defeated in R89: a surviving subprocess can restore bytes A whenever `git diff` or `git hash-object` runs and write bytes B when `captureAuditExport` reads, passing every fingerprint comparison while publishing untested bytes.
- **(c) Make the lane worktree `chmod -R a-w` during tests and run tests in place.** *Rejected:* Any process running as the same OS user owns the files in the lane and can call `chmod` to restore write permissions before mutating them.

```js
// Fork 2 (a) — isolated test checkout + process-group kill
await materializeTree(s, s.snapshotTreeSha, testDir); // cat-file per blob, no attribute processing
const child = spawn('node', testArgs(testDir), { cwd: testDir, detached: true, env: cleanTestEnv });
try { return await waitForExit(child, s.opts.timeoutMs); }
finally { await cleanupPhase(s, child); } // negative-PGID SIGKILL, then recorded-child sweep; fail closed
```

`cleanupPhase` treats ESRCH (already absent) as success for both group signaling and recorded-child cleanup; it still completes the sweep and permits the next phase when no known children remain. Other signal/sweep errors or known live children after the deadline refuse continuation (DW-process, including already-exited success controls). The sketch omits this helper's implementation; swallowing every teardown error is not permitted.

`Skeptic: SURVIVES — conditional on trusted assets remaining intact, a setsid-escaped child's lane/testDir rewrites do not feed publication; Done when DW-writer waits for writes after group cleanup and asserts origin tree identity. Direct trusted-store/runner attacks remain accepted residual risk, not a claimed prevention.`

## Fork 3 — Bounding Codex worker and repair output

**Fork-existence justification:** Case (b) genuine choice — the interface between the untrusted Codex process and the snapshot builder must either harvest in-scope files from a worktree checkout or require Codex to emit a patch artifact; both cannot govern the same handoff.

How the runner bounds what Codex is allowed to contribute to the snapshot:

- **(a) Let Codex edit the raw-base lane worktree, kill its process group on exit, reject any out-of-scope or unsupported path types (`changedFiles` + `pathsWithinScope`), and stage only the verified in-scope paths into `snapshotTreeSha` (Recommended default).** Preserves standard file-editing tools for the Codex worker and repair step while ensuring out-of-scope edits, `.git` tampering, or special files (FIFOs, sockets, device nodes, submodules) cause an immediate fail-closed abort before snapshotting. Both Codex invocations use allowlisted environments and group teardown (DW-test-env, DW-process). Tradeoff: requires enumerating and validating worktree status once before `write-tree`.
- **(b) Run Codex in a read-only tree and require it to write a unified diff patch file applied via `git apply` into the trusted repo.** *Rejected:* LLMs frequently produce malformed hunk headers or line counts in raw unified diffs, causing spurious repair loops on valid code changes that normal file writes handle cleanly.

`Skeptic: SURVIVES — capture can race escaped lane writers, so validate the actual tree rather than claiming teardown eliminates them; Done when DW-scope, DW-special, DW-metadata, DW-symlink and DW-gitlink exercise refusals, while DW-writer exercises lane mutation after capture. Fork 4 limits attacks on trusted assets.`
`Screen: clear`

## Fork 4 — How strongly are the worker and test processes isolated?

**Fork-existence justification:** Case (b) genuine choice — process isolation can be same-user plus cleanup, or an operating-system sandbox; the two have different portability and cost, and both cannot be the default.

- **(a) Same user, dedicated process group, kill the group after every phase, sweep for leftover children, keep runner directories mode 0700, and bind later steps to the tree SHA (Recommended default, with the explicit trust assumption above).** Apply teardown to worker, repair, tests and audit on success, failure and timeout; after group kill, sweep recorded child PIDs and wait within a deadline before entering the next phase. Unresolved known live children or cleanup errors refuse continuation with `process-cleanup-failed` and zero pushes. This sweep does not promise discovery of arbitrary escaped descendants. Create trusted/test/repair/HOME directories as 0700 regardless of umask (DW-process). Portable on macOS and Linux. Ordinary lane/testDir rewrites do not feed publication, but targeted same-UID attacks on runner code, recorded SHAs, objects or dependencies are not contained. Ratifying (a) accepts this integrity and confidentiality risk; it does not assert OS isolation.
- **(b) Run worker, repair and test processes in an unprivileged mount and PID sandbox (Linux namespaces or a macOS sandbox profile).** *Rejected as the v1 default:* the two platforms need different mechanisms, the dev machines lack unprivileged namespaces, and it delays the redesign; file it as a follow-up card once (a) is built.
- **(c) Run everything in a container per job.** *Rejected:* heavier than the heavy-admission pool allows today and does not remove the need for the tree-SHA binding.

`Skeptic: SURVIVES — within the stated v1 trust assumption, Done when DW-writer proves that setsid-escaped lane/testDir rewrites do not change the published tree, and DW-objects proves actual object corruption is refused. Neither test claims protection from a same-UID attacker rewriting the runner or racing the integrity check; that requires option (b).`
`Screen: clear`

## Supported by default (not decisions)

- **Publication uses the recorded `snapshotTreeSha` directly:** `commitAndPush` uses `git commit-tree <snapshotTreeSha> -p <startSha>` in `s.trustedDir`; it never stages the test directory. Assert the created and remote commits' tree equals the recorded tree and each commit has exactly one parent, the bootstrap `startSha`, even if another local ref moves (DW-writer, DW-no-read).
- **Audit reads only a complete trusted text diff:** first inspect both old and new changed blob bytes from trusted objects. NUL-containing or invalid-UTF-8 changed content refuses with `audit-unsupported-content`, zero audit-model calls and zero pushes, even if Node accepts it as JavaScript. Then generate `git diff-tree --no-ext-diff --no-textconv --no-renames --text -p <startSha> <snapshotTreeSha>` in `s.trustedDir` under sanitized config. Bound blob inspection by the capture per-file limit and collected diff bytes by an explicit `auditDiffMaxBytes`; retain at most the applicable limit+1 bytes and cancel the producer on overflow. A binary-summary fallback, incomplete diff, read error or audit-size overflow refuses with an operator-visible reason and retry/split-job guidance; never truncate the audit input and continue. Unchanged binary base files need no audit and do not block a text-only change. The audit invocation receives only the full diff, the brief and sanitized context; it has no lane cwd or file-reading tools. Only an explicit valid `NOT WEAKENED` verdict permits publication (DW-audit-source, DW-audit-binary, DW-weakened, DW-missing-verdict).
- **Scope and mode checks run on captured objects as well as pre-capture inputs:** inspect NUL-delimited `ls-tree -r -z` and `diff-tree --no-renames -r -z` against `startSha`; validate both rename endpoints via delete/add semantics, enforce component-boundary scope prefixes before `write-tree`, and reject unsupported modes, unsafe paths and metadata tampering before tests/publication. Validate paths in both the trusted base (before initial materialization/worker spawn) and captured candidate: reject absolute paths, empty/dot/dot-dot components, Git-metadata paths/host aliases, host separator aliases, and path collisions under the destination filesystem's case/Unicode equivalence rules. Never normalize an unsafe path into an accepted one (DW-paths). The only non-regular exception is an unchanged safe base symlink under Fork 1's policy; check links in both the base and candidate, without dereferencing them. Enumerate untracked files without trusting lane Git config; never silently drop out-of-scope files. Compare lane Git metadata to its bootstrap baseline without executing it (DW-scope, DW-special, DW-metadata, DW-base-links, DW-symlink, DW-gitlink).
- **Materialise raw bytes:** use `cat-file` blob bytes, never `git archive` or a filtered checkout, including the workspace handed to the first worker and fresh repair workspaces. Export attributes do not remove/substitute files; recreate only validated unchanged base links (DW-baseline, DW-bytes, DW-materialize, DW-base-links).
- **Repair starts from the prior snapshot:** fresh materialization plus private dependency/generated-input copies; no primary-checkout links and no reuse of lane leftovers (DW-repair, DW-inputs).
- **Publication verifies actual object payloads:** traverse the recorded tree, rehash raw tree/blob payloads with Git's object type/length framing and compare each digest with the expected OID. Missing, unreadable, wrong-type or mismatched objects refuse with `snapshot-integrity-failed` and zero pushes before `commit-tree`. Comparing the recorded SHA with itself is not a check. TestDir rewrites need no detection because publication never reads that directory. This detects specified corruption, subject to the same-UID limitation (DW-objects, DW-writer).
- **Explicit resolved remote URL and sanitized Git environment:** keep bootstrap-only URL resolution against the primary worktree and pass it explicitly to clone, `ls-remote` and push; strip inherited `GIT_*`, block system/global config, hooks, helpers, replacement refs, external diff and textconv, and use an empty `HOME`. Lane config is never executed (DW-git-env).

**Audit prompt and verdict protocol (DW-audit-prompt):** Content-addressing proves the diff's provenance, not the trustworthiness of its text. Combine the complete diff, including path headers, before escaping `&`, `<` and `>` in that order; enclose it in runner-owned `audit-diff-data` delimiters and instruct the auditor outside that block to treat it only as data. Bound the escaped UTF-8 body by `auditDiffMaxBytes` too; overflow refuses with `audit-unsupported-content` and split-job/retry guidance, never truncation. The runner chooses a fresh invocation ID and requests a final response block of the form `<audit-verdict id="INVOCATION_ID">NOT WEAKENED</audit-verdict>` or the same block containing `WEAKENED`; rationale precedes it. Parse the audit response only, require exactly one well-formed block for that ID at the end (apart from trailing whitespace), and require one exact enum value. Missing, duplicate, conflicting, wrong-ID or malformed blocks, extra trailing text, and verdicts found only in echoed diff/prose refuse with `audit-failed`; there is no substring/last-line fallback. This framing prevents data from supplying structural delimiters; it does not authenticate the model's judgment or eliminate semantic prompt injection. DW-weakened retains a real weakened-test fixture whose correct model result refuses.

## Context

### Prior art

- **Git content-addressed plumbing (`git write-tree`, `git read-tree`, `git commit-tree`):** Git's low-level plumbing separates index manipulation (`GIT_INDEX_FILE`) and tree object creation (`write-tree`) from working-tree checkouts. Once `write-tree` hashes blobs and modes into the object database, `commit-tree` creates a commit directly from that tree SHA without consulting the filesystem again, eliminating worktree-to-commit TOCTOU windows.
- **Nix and Bazel hermetic build/test sandboxes:** Both systems prevent build and test actions from mutating source trees by executing actions inside ephemeral sandboxes populated with read-only inputs or isolated copies, and reaping the action's process group (and PID namespace where supported) before collecting outputs.
- **TOCTOU filesystem race literature (Bishop & Dilger 1996; Dean & Hu 2004):** Classic TOCTOU attacks exploit any check-then-use sequence over mutable filesystem paths by swapping file contents or symlinks between the validation syscall and the consumption syscall. The established fix is to ingest the untrusted bytes into a kernel- or trusted-process-owned immutable object first, then run all validation and consumption against that private object.
- **CI systems pinning commit/tree SHAs and GitHub Actions `pull_request_target` hazards:** In CI pipelines, checking out a mutable branch ref or executing untrusted test scripts in a privileged workspace (`pull_request_target` with checkout of untrusted PR code) allows untrusted code to modify the workspace or exfiltrate credentials. Safe pipelines separate the untrusted execution environment from the privileged publication environment and bind approvals to an immutable tree or commit hash.
- **Reproducible builds (in-toto / SLSA provenance attestations):** Build provenance frameworks bind verification attestations (test results, audit reviews) to the cryptographic digest of the exact artifact or source tree tested, rather than asserting that a mutable directory was unchanged between steps.

### What the seed patch already does

Drawn from `we:scripts/operations/codex-job.mjs` and `we:scripts/operations/__tests__/codex-job.test.mjs` in the closed PR #5839 seed patch:

- **`prepareTrustedRepo(s)` (`we:scripts/operations/codex-job.mjs:177-190`) — KEEP:** Reads `remote.origin.url` once with `--no-includes`, resolves relative filesystem remote paths against `s.opts.repo` (`path.resolve(s.opts.repo, s.originUrl)`), creates a `--no-local --no-checkout --template=` clone in `s.trustedDir`, and resolves `startSha` from the remote ref (DW-git-env).
- **`trustedGit` / sanitized Git environment (`we:scripts/operations/codex-job.mjs` + test matrix lines 125-150) — KEEP:** Scrubs `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, hooks, credential helpers, replacement refs, submodules, and system/global config so hostile lane config cannot hijack Git subcommands or capture credentials (DW-git-env).
- **`changedFiles(s)` and `pathsWithinScope` check in `checkDiffScope(s)` (`we:scripts/operations/codex-job.mjs:215-232, 394-400`) — REPLACE discovery, retain refusal policy:** Git-normalized status can hide raw EOL/ident edits. After raw base initialization, enumerate base tracked paths and actual filesystem entries, compare captured raw OIDs/modes/presence to the base without honoring lane ignore rules, then apply component-boundary scope checks. Keep `no-changes` / `diff-out-of-scope` refusals and NUL-safe names, and validate the actual candidate tree as a second check (DW-baseline, DW-bytes, DW-scope, DW-no-changes).
- **Bounded single-repair loop in `runTests(s)` (`we:scripts/operations/codex-job.mjs:273-338`) — KEEP (adapted to re-snapshot):** Runs Vitest through the heavy-admission queue, handles `tests-deferred`, caps and sanitizes `</test-failure-data>` prompt-injection tags in failure output, allows at most one Codex repair pass, and fails with `tests-red` if the second run fails (DW-deferred, DW-repair-prompt, DW-repair). DW-deferred records queue use as well as refusal status.
- **`worktreeFingerprint(s, ...)` (`we:scripts/operations/codex-job.mjs:234-392`), `captureAuditExport(s)` (`we:scripts/operations/codex-job.mjs:321-355`), and `checkAuditedFiles(s)` (`we:scripts/operations/codex-job.mjs:360-373`) — REPLACE:** These functions attempt to detect mid-test and post-audit mutations by re-reading `git diff`, `git hash-object`, `lstat`, and `readFile` on the live lane worktree and comparing SHA-256 fingerprints (`testedFingerprint`, `testedExportFingerprint`, `auditFingerprint`, `auditExportFingerprint`). Replace all four with a single `captureSnapshotTree(s)` step that writes one Git tree object into `s.trustedDir` before tests run, so tests, `runAudit(s)`, and `commitAndPush(s)` all consume that frozen tree without ever re-reading `s.lane.path` (DW-writer, DW-no-read, DW-audit-source, DW-objects).

## Risks

The snapshot adds one tree write and one extraction per attempt. Required dependencies and generated inputs need private copies in the disposable test directory; missing provisioning causes false reds (Done when DW-inputs). Scope filtering happens before `write-tree`; out-of-scope refusal is a blocking guarantee (Done when DW-scope).
