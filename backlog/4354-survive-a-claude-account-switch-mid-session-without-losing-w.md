# Survive a Claude account switch mid-session without losing work

The 2026-09-28 account-switch incident stopped three in-process background workers; two left unpreserved work in leased lanes, and a follow-up commit needed manual rescue. Preserve the lane lease when its worker disappears but its content is unpreserved, make prior workers and orphan lanes discoverable at resume, and report account provenance. Current release-time salvage and GitHub App status cover parts of the incident, but do not deliver these three guarantees together. This is preparation for a build, not a claim that the account-switch replay has passed.

## Evidence (2026-09-28 ~11:30 AM ET)

- The orchestrating session resumed from local transcripts, but three background workers stopped without completion records available to it.
- Lane-5 held an unpushed commit plus scratch; lane-8 held six uncommitted files. Their leases were lost. The relevant release paths are in we:scripts/lane-pool.mjs and we:scripts/conveyor/lease-reaper.mjs.
- A follow-up commit for the #4337 soak break did not reach PR #2841 and required manual rescue from the abandoned lane's object store. This is historical evidence, not a rescue performed by this preparation.
- The iOS Code tab was slow to surface the resumed session; no repository-side cause has been established.
- Account attribution was unclear. Correction: we:scripts/lib/github-app-token.mjs mints App credentials; it does not select the Claude CLI login. Current per-role App routing and per-caller status mean a shell's personal GitHub login cannot stand in for every daemon's identity.

## Asks

1. A stopped worker's unpreserved content keeps its lane leased through reaping and automatic stale takeover. Empty lanes remain reclaimable under the existing liveness rules.
2. One resume command lists durable worker launch records and reconstructs unmatched lane leases, with content state and honest liveness evidence. Wire it into we:.claude/commands/continue.md. Missing evidence is visible; it must not be reported as a confirmed stopped worker or an empty pool.
3. Show the acquisition-time Claude/GitHub identity beside the current observation, and document how to check each daemon's existing authentication status. A lease stamp describes the acquiring process, not every subsequent worker request.

## Risks

Content holds consume pool capacity until work is preserved. A failed read must keep protection, with the affected lane and recovery route visible ([A1] `4354 failed work reads retain protection and show recovery`). Retain the existing explicit hold-off policy and exact-holder release exception ([A1] controls and [A2] `4354 existing release and recovery controls remain enforced`); this work changes the default protection for non-holders, not those escape hatches. The report is advisory and never restarts workers, deletes records, releases lanes, or changes credentials ([A4] `4354 report remains read only`). New probes have a per-probe 5-second timeout and never fetch ([A6] `4354 probes enforce timeout output and no fetch bounds`).

## Ruling (operator, 2026-10-09 ~13:05 ET)

The open choice from the prepare run (how a resumed session learns which background workers were running) is
ruled **(c) both**:
- **Source of truth: a launch record.** A hook on the agent-launch tool writes each background worker's id,
  purpose, lane and session to a durable record at launch. No caller discipline; the hook does it.
- **Fallback: reconstruction at resume.** The resume command also walks lane leases and lane content-state and
  lists any lane with no matching launch record, so workers started before the hook (or outside it) are not lost.
- Unchanged and not in question: the lease reaper never reclaims a lane carrying unpreserved work (ask 1, safe
  direction only).

## Design

### A. Preserve content through non-holder release and stale takeover

Extend the pure facts of `laneHoldVerdict` and `laneHoldNeedsWorkState` in we:scripts/lib/lane-lease.mjs with `work: { workDirty, unpushedCommits }`. In the existing enforced mode, non-holder `release` and `take-over` require finite nonnegative integer counts. Missing, null, malformed or failed facts yield `work-state-unknown`; a positive count yields `unpreserved-work`; both zero clear this additional hold. Existing await/verify holds still apply. A “verified work already pushed” early return must not bypass positive or unknown work facts. Keep exact-holder release and the existing explicit `mode: off` semantics. Do not add a separate setting or expiration to content protection.

In we:scripts/lib/lane-hold-io.mjs, collect the complete snapshot from we:scripts/lib/lane-history.mjs:357 whenever the new predicate needs it. A supplied `unpushed` boolean is insufficient. Thread the already collected snapshot through `laneHoldRefuses` and release in we:scripts/lane-pool.mjs:1989 and we:scripts/lane-pool.mjs:2980. Other callers must obtain facts themselves. Use `workDirty`, which excludes only the existing allowlisted untracked litter; never treat arbitrary scratch or tracked files as disposable. Keep the existing settings resolver and its provenance logging.

For a clean tree with positive unpushed counts, allow an affirmative preservation proof to clear only the content hold. Reuse `liveRemoteHasRevision` in we:scripts/lib/lane-hold-io.mjs:159 for push-by-URL. For patch-equivalent work, use one bounded `git cherry` against the integration branch and the existing parser in we:scripts/lib/git-patch-equivalence.mjs; corroborate the integration ref's SHA against the live remote before accepting it. Resolve the branch from pool metadata rather than hard-coding main. Reject unhandled merge commits or malformed/partial output as unproven; no per-remote-head loop, no CLI-module import and no fetch. On remote failure the hold remains. Neither proof excuses dirty or unknown work ([A1] remote-proof matrix). Use existing hardened git execution; never execute lane-configured credential/filter programs in a new probe ([A6] `4354 probes never spawn lane configured credential or filter programs`; no-fetch and probe bounds are asserted by its companion case).

All release callers, including the reaper, delivered-lease release and acquire-time terminal-lease cleanup, receive this protection; stale takeover receives it before marker replacement ([A2] caller cases). Retain existing marker race checks. Reset/remove/reclaim retain their existing preservation and liveness gates. Explicit `reclaim --salvage` may preserve eligible stopped work; it must still refuse live or unreadable ownership evidence. Existing exact-holder release salvage behavior remains covered by [A2] `4354 existing release and recovery controls remain enforced`, including marker races and reset/remove/reclaim gates. The automatic reaper does not salvage its way around a hold ([A2] `4354 reaper and acquire cleanup retain unverified work`).

### B. Durable launch records and a read-only resume report

Create we:scripts/operations/worker-launch-record.mjs with `--phase=pre|post`, registered for `Agent|Task` in both hook phases of we:.claude/settings.json. PreToolUse records the launch attempt before the tool runs; PostToolUse enriches the same record with the returned agent identity when available. A pre-only record means “launch attempted; outcome unknown,” not proven running or stopped. Use the actual hook payload captured during the build proof; missing identity fields remain null.

Store one record per validated parent-session/tool-use pair under an operator-home operations directory resolved with `homedir()` and the same workspace convention as we:scripts/operations/handoff-home.mjs:59. Fields: schema version, tool-use id, first launch time, parent session, returned agent id, description, subagent type, background flag, cwd, lane hint, and optional observed lease identity `{pool, lane, holder, acquiredAt}`. Parse a digits-only lane hint but never treat prompt text as ownership evidence. Do not retain the full prompt ([A3] prompt-omission assertion). Validate path components with a leading alphanumeric and only alphanumerics, dot, underscore or hyphen thereafter; reject dot segments, separators, leading option-like strings and overlong ids. Refuse symlinked record targets/directories before using the symlink-following atomic writer.

Use `writeJsonAtomic` and a bounded per-record `withFileLock` from we:scripts/lib/atomic-json-file.mjs so duplicate or delayed pre events never erase a post result or change first launch time. A post-only event creates an explicitly partial record. Limit stdin and stored records to 1 MiB, description to 1,024 characters, and lock acquisition to 1 second ([A3] durability case and `4354 launch record reads enforce byte and lock bounds`). Parse, size, lock and write failures print a sanitized bookkeeping warning and exit zero without a hook decision. Reconstruction is the fallback; a worker with neither a readable record nor a lease remains undiscoverable and must not be counted as successfully reconstructed ([A4] `4354 incomplete evidence never reports all clear`).

Create we:scripts/operations/resume-report.mjs with `--session=<id>` and `--json`. Default to the newest valid launch-record session for the current repository, printing the selected session; an explicit session has no age cutoff. Remove the old proposed silent 14-day omission. Regardless of session selection, scan all pools for unmatched leases, including stale leases, and label them reconstructed candidates rather than claiming they belong to the selected session. When no records exist, still scan leases. Report unreadable records and pool/lease read failures as incomplete evidence.

A row has worker, source, launch outcome, liveness, pool/lane, content state and account comparison. Content classification is `unknown` if any required snapshot count is invalid; otherwise `uncommitted`, `committed-unpushed`, `pushed` (ahead but remotely preserved), or `clean`, in that precedence. Apply the same affirmative preservation proofs as slice A when local refs are stale. No available liveness listing proves an in-process worker dead by omission: missing/failed/truncated evidence yields `unknown`. Positive matching activity can show `alive`; an explicit matching terminal record can show `stopped`. Use the full identity, never a prefix; we:scripts/lib/lane-salvage.mjs:119 supplies lease identity fields and its `liveAgentInLane` is positive evidence, not proof that a particular sibling is alive.

Join a captured lease binding only when pool, lane, holder and acquisition generation still match. Otherwise a returned agent identity matching the declared worker can establish a candidate, but parent-session matches or lane hints alone remain candidates even if only one happens to exist. Multiple matches remain ambiguous and all unmatched leases stay visible. Reacquisition with another holder never attaches to the old launch. A prior bound lease now absent is “lane released”; an unbound record is “lane unknown.” Launches that acquire after the post hook may therefore be ambiguous; this is honest reconstruction, not a fabricated association.

Use we:scripts/lib/lane-pool-scan.mjs with an injected directory reader that records failures before rethrowing to its existing catch; do not interpret its empty-on-error result as complete. Read-only scans must not fetch, release, reset, salvage or write associations ([A4] `4354 report remains read only` and [A6] no-fetch case). Strip terminal control characters as well as applying `foldUntrusted` from we:scripts/lib/jury-core.mjs to displayed text, including JSON string fields ([A4] incomplete-evidence case). Invoke subprocesses with argv arrays through we:scripts/lib/proc-read.mjs; give new probes a 1 MiB output limit and 5-second timeout ([A6] `4354 probes enforce timeout output and no fetch bounds`). Its sub-1-MiB limits fall back to a larger default, so do not specify 64 KiB there. Run one agent listing and one identity read per report, never per row. After 60 seconds, stop starting probes and emit explicit uninspected rows/incomplete status; show `--session` and direct lane-status inspection as the fallback. No completeness claim on a capped or failed scan ([A4] `4354 incomplete evidence never reports all clear`, including call-count, budget and fallback assertions).

Add the report to we:.claude/commands/continue.md after its existing session-reaper step. Surface unpreserved, ambiguous and unknown rows before resuming work. Include a portable invocation and session-selection explanation, not an operator-specific absolute checkout.

### C. Acquisition identity, current identity and existing daemon status

Create we:scripts/lib/account-identity.mjs with injectable read-only probes. Claude uses `claude auth status --json`, matching we:scripts/conveyor/claude-auth-health.mjs:157. Require a positive login and usable identity fields; hash a structured tuple of organization, email and authentication method, and return only a masked label and fingerprint. Never serialize raw probe output, raw email, credentials or errors containing them. API-key/non-account contexts without sufficient identity remain unknown.

GitHub uses the existing throttled reader for `gh auth status --json hosts`, selecting only host, active login and token-source metadata; never request tokens. Reuse `ghAuthProvenance` and `ghBinIsWeShim` from we:scripts/lib/gh-throttle.mjs. A shim-routed invocation or unverified token identity must not be labeled as the shell's stored personal login: expose routing/source and unknown actor where necessary. Use existing per-caller App status to explain daemon routing, not to invent a universal daemon account. No credential minting, account switching or auth policy changes.

Add an optional `account` field to `leaseBody` in we:scripts/lib/lane-lease.mjs:178. Probe once per acquire command and pass the result to the new-lease write in we:scripts/lane-pool.mjs:1712; failures stamp unknown and never block acquisition. Preserve an existing acquisition stamp during idempotent reacquire/renew/adopt; do not relabel old work with the current account. An old lease without a stamp stays unknown. New holder generation gets a new stamp. Internal salvage/reservation writers may omit the optional field and must keep their existing behavior.

The report compares Claude and GitHub separately: known equal identities are `same`, known unequal are `switched`, and missing or incomparable evidence is `unknown`. Combined status is switched if either known identity changed, same only if both comparisons are known equal, otherwise unknown. Label these as acquirer-versus-current observations. In we:docs/agent/dispatcher-runbook.md add the commands for the report, Claude auth status, we:scripts/conveyor/github-app-status.mjs and we:scripts/lib/github-app-identity.mjs, explaining caller/role/owner routing and status timestamps. Shell status is not proof of a running daemon's inherited environment.

## MVP

1. Content protection at non-holder release and stale takeover, with complete work facts, positive remote-proof escape and fail-closed unknowns; preserve current holder/off/recovery semantics.
2. Pre/post launch hooks, durable bounded records, conservative generation-aware report joins and all-pool lease reconstruction; wire `/continue` to the report.
3. Optional acquisition identity stamp, per-surface comparison and the runbook's existing daemon-auth inspection routes.

Deliver in that order within this story. No new daemon, restart automation, salvage policy, credential policy or client-side iOS work. A report with explicit unknown/ambiguous rows satisfies honest visibility; a promise to determine every stopped in-process worker's exact liveness does not have supporting evidence and is not part of the MVP.
