## Operator ruling (2026-10-13 ~13:25 ET) — finding 2

The prepare was blocked with needs-ruling on finding 2: whether to reject ordinary clones by requiring linked worktrees, or keep clone support with a narrower Git-metadata permission. The operator chose (b), "ok. using settings and policies if makes sense":

- **Keep scratch clones and lane clones supported.** Every lane is an ordinary clone today, so requiring worktrees would break all Codex tasks.
- **Narrow what the sandbox may write.** Codex keeps write access to the git objects and refs it needs to commit, but `we:.git/hooks/` and `we:.git/config` are not writable inside the sandbox. Every git invocation in the sandboxed run carries `core.hooksPath=/dev/null`.
- **As a setting/policy.** The protected git-metadata paths and the hooks override are a cascade setting (e.g. `codex.sandbox.gitMetadata { protectedPaths: ["hooks", "config"], disableHooks: true }`). It is documented and logs its source layer. The default is protected, and no layer may widen it without the override being logged.
- **Test.** A hook or config written by the sandboxed run is refused or never executed by a later git call. Also cover a linked-worktree gitdir and a clone gitdir.
- **Later option, not in this card.** Moving lanes to linked worktrees and then requiring them.

Findings 1, 3, 4 and 5 need no ruling and remain required deliverables (this is authorization, not a claim that they have shipped). Prefer a setting wherever a finding names a policy choice, e.g. the env allowlist in finding 3.

## Design

Implement prevention at the actual launch boundary, keeping the public task result and review-mode read-only behavior intact. Keep the ruling's clone support, commit-capable objects/refs, protected metadata and auditable settings together in this story.

1. **Policy resolution.** Add `we:scripts/codex-direct-task-policy.mjs` and `we:scripts/settings/codex-direct-task-policy.json` (new). Resolve `codex.sandbox.gitMetadata` and `codex.sandbox.environment` through the existing standard → platform → tool → env cascade, using `we:scripts/lib/policy-cascade.mjs` and `we:scripts/lib/settings-files.mjs`. Use one JSON env override, `WE_CODEX_SANDBOX_POLICY`, with validation per leaf. Standard defaults protect `hooks` and `config`, disable hooks, and strip credential variable names matching `*TOKEN*`, `*SECRET*`, `*PASSWORD*`, `*API_KEY*` (case-insensitive). The settings file documents keys, defaults and overrides without duplicating model settings. Reject path traversal/absolute protected-path entries. Invalid leaves retain the safe lower-layer value and produce diagnostics. Log effective metadata policy and source layers on every launch; log any widening before spawn even when optional cascade logging is off. Log environment variable names/policy only, never secret values.
2. **Git topology and permissions.** Resolve both the absolute per-worktree Git directory and the common directory using Git, normalize relative answers against the checkout and canonicalize existing paths. For edit jobs construct a strict, named workspace permission profile: grant necessary Git bookkeeping/objects/refs plus the admission and private temp roots; overlay read-only entries for protected paths in both Git directories, deduplicating clone topology. Include worktree-specific config when present. Do not retain the built-in `-s workspace-write` selector alongside the named profile. Preserve network access explicitly in that profile; the policy suite asserts the serialized profile enables it, and the live sandbox suite proves the child can actually reach the network under it. Preserve project-instruction loading; the project-instruction assertion below proves it in `we:scripts/__tests__/codex-direct-task-instructions.test.mjs`. Review mode retains its existing read-only path with no extra roots. TOML values must be encoded, not shell-interpolated. The [official configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) documents named filesystem read/write entries and profile network enablement; actual enforcement is an MVP proof obligation, not established by this preparation.

   **Project-instruction assertion.** In the real-Codex MVP probe, launch an edit job from a nested fixture directory under the named profile, with distinct sentinel instructions in the repository-root and nested `we:AGENTS.md` files. Assert the child follows both applicable instructions without including their contents or sentinel values in the task prompt. Exercise both ordinary-clone and linked-worktree topology; a negative control with project-instruction loading disabled must fail the same assertion. Argument/config snapshots alone do not establish loading.

3. **Hook override.** Apply `core.hooksPath=/dev/null` to launcher-owned Git calls and propagate the equivalent Git config environment through both the Codex process and its shell environment policy so ordinary child Git commands inherit it. Remove conflicting inherited Git config injection before composing it. Prove a pre-existing executable hook never runs on a later sandboxed commit. Environment defaults are not a claim of resistance to a deliberately rewritten Git command/environment; the OS metadata protection must independently prevent mutation, deletion and replacement of protected paths. Do not substitute a PATH shim or prompt instruction for that filesystem control.
4. **Environment and directories.** Copy/filter the supplied env without mutating it. No write-scoped GitHub token is forwarded or relabelled read-only. This edit worker needs no GitHub token by default; an explicitly supplied read-only credential, if needed by a caller, must enter through a named policy exception whose source is logged. Preserve nonsecret process configuration and Codex home authentication discovery. Resolve a temp base from nonempty supplied TMPDIR, then TMP, then TEMP; consult the OS fallback only if none is supplied. Validate the selected base and fail before spawn if unusable. Thread it through scratch-clone setup as well as private edit temp allocation. Recursively create the resolved admission root before the child can run. Preserve private per-job temp allocation and review's lack of edit-only allocation.
5. **Focused prevention lint.** Add `we:scripts/codex-direct-task-guards.mjs` (new), using the existing TypeScript parser dependency, and wire its findings into `we:scripts/check-standards.mjs`. Scan the launcher and new policy module. Flag `some`/`every` without an explicit same-receiver empty/nonempty branch; accept documented, tested zero-input behavior instead of rejecting valid empty optional arrays. Make the launcher's two predicate sites explicit (zero roots is allowed; an executed gate with zero steps cannot report success). Also flag direct ambient temp access in env-accepting launcher functions except the single fallback resolver, and unfiltered env forwarding at the edit spawn. Diagnostics name file, line, rule and remediation; comments/strings are not code. This lint is a regression tripwire, not a security proof or general data-flow analyzer.
