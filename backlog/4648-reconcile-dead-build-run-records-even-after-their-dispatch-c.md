# Reconcile dead build run records even after their dispatch claim disappears

Recover confirmed-dead build attempts from durable run records even when their build-dispatch claim has disappeared. The incident in we:reports/2026-09-30-builder-launch-misread-root-causes.md is historical evidence, not a current live diagnosis. Inspection of this checkout still shows the reconciliation gap.

## Evidence

- Adoption loops only over claims; its run scan remains lazy, and the lookup selects the latest attempt per item: we:scripts/conveyor/build-dispatch-orphan-adopt.mjs:122-134 and we:scripts/conveyor/build-dispatch-orphan-adopt.mjs:532-550. Zero claims means zero run reads.
- Occupancy independently enumerates durable build effects; only preparation effects receive liveness stamping: we:skills-src/conveyor/build-dispatch-daemon.mjs:1271-1294. Unknown build liveness can age out of occupancy without a terminal write through we:scripts/operations/dispatch-lane.mjs:740-748.
- Adoption precedes queue protection and occupancy consumption in we:skills-src/conveyor/build-dispatch-daemon.mjs:473-503, but the live shell supplies snapshots captured beforehand, now from a shared records array: we:skills-src/conveyor/build-dispatch-daemon.mjs:2440-2447.
- Settlement rereads exact run/effect status but suppresses persistence errors: we:scripts/conveyor/build-dispatch-orphan-adopt.mjs:446-461. Claim-backed recovery now also checks real delivery outcomes and charges failed launches to backoff/releases reserved lanes: we:scripts/conveyor/build-dispatch-orphan-adopt.mjs:551-560 and we:scripts/conveyor/build-dispatch-orphan-adopt.mjs:589-600.
- The existing resume reader hides expired markers (we:scripts/conveyor/build-dispatch-claim.mjs:239-247); its underlying reader collapses read/parse failures into absence (we:scripts/readiness/file-locks.mjs:244-255). It cannot implement the sweep's unknown-preserving contract unchanged.

## Design

1. Extend adoption with a durable-row sweep in we:scripts/conveyor/build-dispatch-orphan-adopt.mjs. Enumerate all readable in-flight dispatch effects of build kind once, even with no claims; deduplicate by run ID and effect key. Validate item, identity and handle before probing. Skip unreadable/malformed records without mutating them. Preserve the existing claim-backed pass and its real-outcome, resume, backoff and lease-release behavior. Record each exact identity handled by that pass, including leave/error results, and exclude it from the sweep. Capture identity immediately after lookup, before marker reads can throw; lookup failure protects the claim's entire item for the pass. A row successfully rejected as predating the claim remains eligible, so a newer claim does not hide an older dead attempt. The current rejection and marker binding are at we:scripts/conveyor/build-dispatch-orphan-adopt.mjs:204-222.
2. Introduce an injected tri-state PID probe local to the new sweep. Only ESRCH confirms death; success protects the row, and EPERM, other failures or indeterminate results preserve it. Missing/malformed handles and session handles are unknown; do not apply the claim-owner fallback to claimless rows. Keep the shared boolean probe at we:scripts/operations/detached-dispatch.mjs:90-97 unchanged. A live reused PID remains protected. Wrapper absence does not prove every descendant exited; no descendant termination or process-generation migration is included.
3. Add a separate strict marker-evidence reader local to we:scripts/conveyor/build-dispatch-orphan-adopt.mjs, leaving the claim-backed reader unchanged. Compose the exported resource/root helpers from we:scripts/conveyor/build-dispatch-claim.mjs and lock-directory/parser helpers from we:scripts/readiness/file-locks.mjs:194-195 and we:scripts/readiness/file-locks.mjs:71-86. Read the persisted marker directly: a missing marker directory is absence; an existing directory with a missing entry, invalid/truncated data, or a read failure is unknown. Do not hide evidence by TTL. Snapshot markers before the claim pass can delete another attempt's marker (we:scripts/conveyor/build-dispatch-orphan-adopt.mjs:549), and reread immediately before settlement. Either unknown read protects the row. A marker bound to this exact attempt with a live PID or pending/unconfirmed spawn protects it; a confirmed-dead resume or explicitly failed spawn can permit settlement. Foreign-attempt evidence never substitutes for this row's liveness and is never deleted by the sweep.
4. Settle only an eligible confirmed-dead row, using failed status, the existing `orphan-released` outcome and an explicit diagnostic reason. Reuse the exact-row settlement logic at we:scripts/conveyor/build-dispatch-orphan-adopt.mjs:446-461 through an observable result/error seam while retaining existing callers' behavior. Reread run ID, effect key, type, build kind, item, handle and in-flight status before writing; preserve concurrent terminal results and changed identity. Report persistence failure as an error, never successful reconciliation. Repeated passes are idempotent. The row-only path performs no claim/marker deletion, hold/backoff mutation, resume/spawn or lane mutation.
5. Forward pending-launch item exclusions into the sweep as well as the claim filter at we:skills-src/conveyor/build-dispatch-daemon.mjs:2166-2170. Add an awaited post-adoption refresh seam before queue protection at we:skills-src/conveyor/build-dispatch-daemon.mjs:473-489, including when adoption partially succeeds and reports an error. The live wiring must obtain a NEW records snapshot with the reader at we:skills-src/conveyor/build-dispatch-daemon.mjs:1257-1265 and derive both occupancy and settled-build evidence from that snapshot. Replace both cached readers only once both results are available; never reuse the pre-adoption records array at we:skills-src/conveyor/build-dispatch-daemon.mjs:2440. Surface refresh failure without proceeding to planning with a partially replaced pair. Preserve read-only dry runs, landing-freeze bookkeeping, and the outer paused-tick gate at we:skills-src/conveyor/build-dispatch-daemon.mjs:130-155. Reconciliation itself does not request a restart; ordinary scheduling remains separate.

## MVP

One slice in the four scoped files: conservative durable-row reconciliation and its IO seams in we:scripts/conveyor/build-dispatch-orphan-adopt.mjs, fresh same-tick consumer snapshots in we:skills-src/conveyor/build-dispatch-daemon.mjs, and both matching test suites. Success is one durable terminal write for an eligible dead claimless attempt and no phantom occupancy in that ordinary tick, with live/unknown attempts and other attempts' ownership untouched. No shared lock API change, dispatch provider, global deadline policy, ownership-token migration or lease reaper is needed.
