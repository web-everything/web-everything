# First adopter: the health daemon runs its probes and investigations as jobs

Adopt the delivered shared job runtime for health watch's slow probes, deterministic diagnoses, and per-episode investigation launch. Keep the health tick responsive while these jobs run, and pull every daemon's job records as health evidence. The governing rule is [we:docs/agent/platform-decisions.md#daemon-jobs](../docs/agent/platform-decisions.md#daemon-jobs), ratified on 2026-09-25. Preserve the existing health and investigation policies; this is the first adopter slice, not a replacement daemon or a new dispatch policy.

## Design

1. Declare health job kinds in we:skills-src/conveyor/daemon-manifest.mjs using the existing shared kind contract. Export kind definitions built with `defineJobKind` and `kindRegistry` from we:scripts/lib/daemon-jobs.mjs:60; the health tick must consume them explicitly because manifest registration alone does not run jobs. Declare probe, diagnosis and investigation-lifecycle kinds with pinned `readonly-tree` code, an explicit daemon cap of two, and `serial: true` for investigation lifecycle work. Keep the existing runtime attempt/backoff defaults; these mechanical attempts do not grant another investigator admission. Add we:scripts/conveyor/health-watch-job.mjs (planned) as the child entry composing `runJob`; reuse the shared runtime without copying its handle, retry, snapshot or lock implementation. Introduce per-kind rollout switches, initially retaining inline execution until live proof passes; disabling new job admission must still reconcile already-running jobs before returning that kind to inline execution.
2. In we:scripts/conveyor/health-watch.mjs separate cheap local reads from command/network probes. Queue due slow reads: daemon status, command-backed heavy status/process reads, clone comparison, verification-head and untracked-card reads, GraphQL/REST budgets, credential inventory, PR/agent/stale-state/merged-PR reads and their dependent reads, including `buildSessions`. Preserve each existing cadence and the separate inventory stamp. Leave the side-effecting session-watchdog, clone-ref refresh and maintenance paths under their current owners and include their costs in the tick proof. Keep dependent inputs in the same job input/result generation. Queue deterministic diagnosis commands by episode ID. A due probe with a queued or running job gets no duplicate. Persist absolute state, lane-pool, source-repository and log roots in job input/environment so snapshot-relative defaults cannot inspect an empty snapshot instead of the host. Fixture and dry-run paths must remain isolated from host reads and dispatch. A dry run neither enqueues nor reattaches with side effects. Run existing synchronous probe bodies in a worker beneath the heartbeat-owning job process; the parent job event loop must remain free to heartbeat during a 300-second read. Bound each command, propagate errors, and terminate subordinate work when its owning job stops so a retry cannot overlap an orphan probe.
3. Results belong to the job record/checkpoint and contain scrubbed values, sample time, per-probe errors and a generation/job ID. Only the tick writes health episode state, cursors, cadence stamps and reports. It consumes each completion once, independently per probe, retaining partial-success semantics. Queued/running/failed reads never become healthy empty samples. Missing fresh samples suspend the dependent smell's hysteresis; replaying a cached completion must not count as another observation. Pass explicit sampled/succeeded probe identities into we:scripts/conveyor/health-watch-core.mjs so an unsampled tick does not clear a pending probe-error streak (current clearing loop: we:scripts/conveyor/health-watch-core.mjs:724).
4. Refactor we:scripts/conveyor/health-investigate-dispatch.mjs into lifecycle IO and tick-side projection. The serial job owns investigation ledger changes; the tick reads ledger/findings and alone annotates episodes and reports. Move report acknowledgement into tick-owned state, honoring legacy `reportedAt` values on migration. Make the closed-report investigation section an idempotent replacement keyed by episode/session, then acknowledge it; a crash after the report write but before state persistence must not append it twice. Persist consumed result IDs together with the episode/cadence state, and reject diagnosis results whose episode ID no longer matches the subject's current episode. Keep `dispatch-lane`, recording tokens, one-per-episode admission, running/window/subject caps, wall-clock reap and the dispatch-off default. Persist the episode/session reservation before invoking dispatch; on restart reconcile the deterministic session identity before any retry. An indeterminate launch keeps its slot and is reaped under the existing policy; it must never launch a second investigator. Mechanical job recovery does not resume a bot session. Closed-episode findings still appear once. A lifecycle job ends after a bounded reconcile/admit pass; it does not wait for the investigator to finish. Queue another pass on later ticks even with new dispatch disabled so existing sessions are still reaped. Keep reporting available while that pass is pending, and preserve `--no-investigate` behavior. Use the durable reservation as the replay boundary: mechanical retries reconcile an existing reservation, never repeat its dispatch merely because the job checkpoint was not written.
5. Reattach health-owned jobs on the first and subsequent ticks, leaving live handles alone and using the core's stop-before-relaunch/backoff rules. Read other daemons' records without mutating or reattaching them. Preserve the existing `operationRuns` array and its newest-first limits for current consumers; extend discovery with a separate job-evidence result containing owner, corruption, liveness and scan-completeness metadata needed by we:scripts/conveyor/health-smells/daemon-job-health.mjs (planned). Scan daemon job directories in bounded, persisted pages independently of the seven-hour operation lookback so old stalled/failed jobs cannot disappear. Budget records/bytes and handle probes, persist the scan cursor in tick state, and evaluate absence/recovery only after the relevant owner has a complete fresh scan. A truncated, oversized, corrupt or unreadable portion is unavailable evidence, not proof that jobs recovered. Reuse `classifyJob` for heartbeat/launch-grace classifications rather than inventing a duration timeout for all job kinds. Evaluate stalled/dead jobs and exhausted/failed retries; include foreign-host and corrupt-record evidence as unavailable/abnormal, never healthy. Report owning daemon, kind, record ID, attempt and bound. Also cover cap-saturation and orphan-job observations using explicit declared cap/queue and verifiable handle evidence; when another adopter supplies no cap or identity evidence, report that dimension unavailable rather than assuming health; do not infer an orphan merely from an arbitrary Node process. Discovery registers the new smell automatically (we:scripts/conveyor/health-smells/index.mjs:11). A single-shot tick cannot retain `createTickClock` memory between invocations; supply its supported `observation` using persisted wall/host-monotonic samples (not process-relative `performance.now()`), discarding them on boot-identity change, and test the runtime sleep-detection rule across tick processes.

## MVP

1. **Must 1:** Deliver the job entry and manifest kinds/switches, then convert slow probe and diagnosis execution to enqueue/read-result behavior. Preserve existing cadence, redaction, fixture flags and dry-run behavior.
2. **Must 2:** Convert investigation lifecycle IO with durable reservation/reconciliation and single-writer ledger ownership; retain tick-owned reports and all existing investigation limits.
3. **Must 3:** Add the job-health smell and wire cross-daemon record evidence through the existing probe. Add regression cases in every test path listed in scope; new entry/smell tests are planned files.
4. **Must 4:** Keep this as one adopter PR after #4125. Shared runtime APIs are dependencies, not a new runtime implementation in this slice. Enable job mode by default only after the proof below passes; a failing cold-start or maintenance timing check blocks graduation and must be addressed or explicitly scoped in review.

## Done when

1. **Musts 1–2:** The queue-backed focused test command in the test plan passes with new assertions that fail on the current inline path: a pending probe cannot hold a tick, repeated ticks do not duplicate jobs or observations, and restarting during dispatch cannot duplicate an investigator.
2. **Musts 1, 2 and 4:** A real detached five-minute probe overlaps three completed health ticks, each below the configured tick budget, with launch/finish/reattach records and timestamps captured. Investigation launch has equivalent nonblocking and restart evidence through the declared operation.
3. **Must 3:** Cross-daemon stalled/failed job fixtures open and recover health episodes; absent/incomplete results never close an existing episode as healthy. Rollback preserves ownership of in-flight work.

## Proof plan

Use a disposable state/jobs/log root and a pinned revision containing the implementation. Run the real health CLI and shared detached runtime with a controlled probe that sleeps for 300 seconds; keep all external probes fixture-backed. Set an explicit accelerated health cadence of 60 seconds so three ticks can finish while that probe is running (the production five-minute interval cannot satisfy that overlap). Record scheduled/start/completed times, duration and the configured 60-second tick budget for each tick, plus job ID, handle, attempt and result-consumption time. Repeat at normal cadence to check scheduling without claiming three overlapping ticks from that run.

Restart the health driver while the child is alive and prove the same handle/attempt is retained, then confirm one result ingestion after completion. Capture advancing heartbeats during the long probe and verify its subordinate process is gone before a replacement starts; otherwise a detached sleep proves neither heartbeat safety nor cleanup. Exercise a stalled child and a failed job with bounded test settings and record stop-before-relaunch plus the visible health episode. Exercise investigation dispatch through the declared operation with a controlled sink, then perform the permitted live investigator launch before graduation; verify no duplicate session across the acknowledgement crash window. Retain shadow/dispatch switches and budgets throughout.

Measure both cold snapshot launch and warm launch; also measure stalled-stop reconciliation and ordinary enabled maintenance, clone-ref refresh and session-watchdog passes. Report those costs separately from probe duration. Unit mocks and a detached sleep alone cannot establish production readiness. Attach timelines and record excerpts to the implementation PR; this preparation performs no live dispatch, rollout, or host sleep.
