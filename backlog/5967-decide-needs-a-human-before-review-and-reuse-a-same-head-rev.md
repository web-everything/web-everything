# Decide needs-a-human before review, and reuse a same-head review as the advisory

Held finding 218 (2026-10-10, operator OK). Live #4763: unattended review accepted 17:11 ET, flipped ready-to-merge, drain parked it gate-self at 17:24 (review:human + awaiting-advisory), mutual exclusivity removed review:accepted, then it waited for a second identical advisory run. Fix: (a) compute humanRequired from the touch-set shape before review and label review:human up front; (b) setting review.reuseAcceptAsAdvisory (cascade, default on): when a PR turns human-required, the latest review on the same head counts as its advisory iff its seated lenses/rounds meet what the shape earned, else re-run; (c) status labels follow (no stale status:ready-to-merge).

## Acceptance

- [A1] **Executable** — run from the WE checkout; selects every test file in scope. The new behavior cases fail before implementation and pass after; existing behavior pins may already pass.

Run every scoped test through the host heavy-run queue using the invocation described under Proof plan; select all eight test files explicitly.

- [A2] **Must** — on error (shape unscorable, settings unreadable, advisory comment unreadable) the code refuses to reuse and re-runs the advisory; it never reuses on a failed read.
- [A3] **Must** — the shape scoring and the reuse check treat docs, config, data and backlog paths exactly as `buildShapePlan` does today (no path kind is waived); reuse only ever loosens the re-run, never the `review:human` hold.

## Non-goals

- [N1] Does not let a reused review clear `review:human`; the human ceremony is unchanged (`planRecordDecision` INVARIANT 2, we:scripts/operations/review-pr.mjs:2033).
- [N2] Does not change how `earnedShape` is scored (`buildShapePlan`) or add lenses; it only reads the result earlier.

## Edge cases this change must handle

1. **Untrusted text** — the reused advisory is read only from comments passing `trustedAdvisoryComments` (we:scripts/lib/advisory-labels.mjs:126); its text is parsed for head sha, lenses and rounds only and never reaches argv, a shell or a note unfolded (`foldUntrusted`).
2. **Truncated reads** — the comment list comes from `readCompletePrComments` (we:scripts/conveyor/pr-comments-complete.mjs); a truncated page is an error and means "re-run", never "no advisory found" or "advisory found".
3. **Shared state files** — n/a: no new state file; the setting is read-only from we:scripts/review-settings.json, and labels use the existing label writer.
4. **Fail closed** — an unscorable shape (`assertDeclaredShapeHolds` returns `null`), unreadable settings, or an unparseable advisory means: no early `review:human` guess, no reuse, re-run the advisory; the refusal reason is named in the log line.
5. **Identity scoping** — reuse is keyed by repo + PR + full head sha via `advisoryCoversHead` (we:scripts/lib/advisory-labels.mjs:131); a review of any other head, PR or repo never counts.
6. **State over time** — a new head voids the reuse (the advisory no longer covers it); a daemon restart between review and park re-derives from comments and labels, so no in-memory state is needed; the stale `review:awaiting-advisory` and `status:ready-to-merge` labels are removed in the same park step.
7. **Who wrote it** — only trusted-marker-author comments count (see 1); a comment from anyone else with the same text is ignored, and an operator-added `review:human` label is never removed by this change.

## Design

The review operation currently reads the shape inside `review-pr read` (we:scripts/operations/review-pr.mjs:1325, `assertDeclaredShapeHolds`), and `humanRequired` comes off the LABELS (we:scripts/operations/review-pr.mjs:1390), so a PR whose touch-set earns human review is reviewed as agent-reviewable until the drain parks it later (we:scripts/merge-ai-prs.mjs:871, `decideReviewGate`).

(a) Up-front: keep the pure `planReviewDispatch` untouched. Put the shared preflight in `dispatchReviewByMode` (we:scripts/operations/review-job.mjs), after its stack-skip check and before either mode starts. Its proposed injected `readReviewScope` production reader must obtain the scored net diff, current head and labels using the same net-basis reader as `review-pr read`; it supplies `netChangedFiles` to a pure `decideUpfrontHuman` using `buildShapePlan`, and populates the session's `scopePaths` from that list. Do not assume existing callers supply `scopePaths`: they do not. Default `job` mode must execute this preflight too, before `dispatchReviewJob` launches its worker. Route both branches of the review-dispatch CLI and the direct `dispatchReview` call in we:scripts/operations/land-advance-io.mjs through `dispatchReviewByMode` (preserving the latter's session mode and injected actions). The remaining direct invocation in we:scripts/lib/daemon-live-smoke.mjs:569 is a synthetic launcher probe, not a production PR dispatch; leave that probe and the low-level launcher contract unchanged.

The injected `applyLabels` seam uses the existing label writer and completes before spawn. For a scored human-required shape, ensure `review:human` and `review:awaiting-advisory` are present, even if `review:human` was added by an operator already. Never remove that hold. Empty scope, failed/degraded net reads or null shape mean no early label guess and a named refusal log; preserve existing labels. A failed required label write must prevent launch rather than start a review against stale labels. The downstream review reads the updated labels, so it runs as an advisory.

Give `readReviewScope` a production default, not only a test injection: wrap the existing `createReviewPrReader` export from we:scripts/operations/review-pr-io.mjs in we:scripts/operations/review-job.mjs (no reader-module edit), which resolves the subject checkout and calls `readPr`. Take paths/scored/reason/head from `raw.net.paths`, `raw.net.scored`, `raw.net.reason` and `raw.net.revSha`, and labels from `raw.detail.labels`. This reuses the existing main/stack net basis without substituting the displayed three-dot file list. The wiring test must retain this default adapter and mock its transport inputs; injecting a finished scope object proves only orchestration. The CLI and land caller must forward repo, PR and checkout context to it. Normalize the internal repo key used by land-advance into the subject slug expected by the reader, retaining the original key for dispatch; the existing land caller documents that distinction at we:scripts/operations/land-advance-io.mjs:235. Do not change the synchronous dispatch return contract; adapt the existing synchronous reader and label provider.

(b) Reuse: add `reuseAcceptAsAdvisory` (default `true`) to we:scripts/lib/review-settings.mjs (`BUILT_IN_REVIEW_SETTINGS`, `REVIEW_SETTINGS_ENV`, a boolean parser accepting file booleans and environment strings `true`/`false`) and we:scripts/review-settings.json. Add a diagnostic loading seam in the same settings module that distinguishes successful default resolution from an unreadable/invalid file. The existing loader catches every error and returns defaults (we:scripts/lib/review-settings.mjs:71); a default-on reuse flag must not turn that failure into permission. Preserve the existing resolver contract for other settings; the reuse caller requires successful loading before applying the cascade, even if an environment override enables reuse. `parseAdvisories` consumes `renderAdvisoryNote` and also accepts ordinary `renderVerdictWriteUp` records through its legacy Verdict/Net-basis fallback. The advisory note currently lacks reusable round metadata. Add one shared completed-coverage renderer for explicit completed-lens and completed-round fields to BOTH producers and parse those fields in we:scripts/lib/advisory-labels.mjs. This makes a newly recorded ordinary accept reusable when it later parks, as in #4763. Populate the fields from actual completed judging results, excluding skipped seats; never copy the earned/requested shape as evidence of work done. Derive completed coverage in the reduce step from successfully completed judging answers, before the flattened lens verdict map (we:scripts/operations/review-pr.mjs:3000); that map alone can include a derived verdict without proving seat completion. A single proven judging pass contributes one completed round, never the requested round count or a fix-loop round ordinal. Do not aggregate earlier heads or invent multi-round history; if completed rounds cannot be established, emit zero. This conservatively refuses reuse for shapes earning more rounds than the stored result proves. Legacy/malformed notes with missing fields parse as zero coverage and cannot be reused. Use real output from both renderers for parser fixtures.

Add pure `decideAdvisoryReuse({ advisories, headSha, earnedShape, setting })`: reuse only when the setting is on, the latest trusted advisory is an `accept` covering this head (`advisoryCoversHead`), with both parsed and live heads validated as full 40-hex SHAs and equal (the existing helper alone also accepts prefixes), its completed lenses include every earned lens, and its completed rounds meet the earned rounds. A newer changes/inconclusive note blocks reuse of an older accept. At all three park-to-human sites in we:scripts/merge-ai-prs.mjs (we:scripts/merge-ai-prs.mjs:5531, we:scripts/merge-ai-prs.mjs:5651, we:scripts/merge-ai-prs.mjs:5753), share one reuse/awaiting-label decision using fresh complete comments and the scored net shape; never infer earned shape from the hold label alone. On those paths, successful reuse explicitly removes any existing `review:awaiting-advisory` and omits adding it; failed reuse ensures it is present. No new advisory comment is posted. Also close the existing ordinary-verdict fallback in `planAdvisoryRepairLabels` (we:scripts/lib/advisory-labels.mjs:168): it currently clears awaiting on a prefix head match with no coverage or setting check. Distinguish actual advisory records from ordinary verdict records in the parser. For an ordinary record, require the same successful reuse decision before clearing awaiting or deriving advisory labels; absent decision inputs refuse that repair. The existing sweep caller (we:scripts/conveyor/advisory-label-sweep.mjs:129) supplies no shape/settings, so it must conservatively leave ordinary records alone rather than undo a park refusal. Preserve repair of actual advisory notes, which records an advisory that already ran, independently of the ordinary-accept reuse switch. No sweep edit is required. Preserve `review:human` on both branches, regardless of who added it, and keep merge disallowed (N1).

(c) Labels: `stripReadyOnPark` (we:scripts/merge-ai-prs.mjs:5336, via `decideParkReadyStrip`) already strips `status:ready-to-merge` at all three park sites (we:scripts/merge-ai-prs.mjs:5537, we:scripts/merge-ai-prs.mjs:5657, we:scripts/merge-ai-prs.mjs:5733). The Must here is only a regression test replaying the #4763 order (accepted, ready-to-merge, then a gate-self park) proving the strip and the `review:accepted` removal both happen; if that test is RED, fix `stripReadyOnPark` for the missed case.
