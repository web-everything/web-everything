# Decide needs-a-human before review, and reuse a same-head review as the advisory

Held finding 218 (2026-10-10, operator OK). Live #4763: accepted 17:11 ET, ready-to-merge, gate-self park 17:24 removed review:accepted and awaited an identical advisory. Fix: (a) compute humanRequired before review and label review:human up front; (b) review.reuseAcceptAsAdvisory (cascade, default on): the latest same-head accept counts as its advisory iff one completed pass covers the shape's mandatory floor, else re-run. This satisfies only the advisory wait, retaining the full review shortfall and human hold; (c) strip stale status:ready-to-merge.

## Non-goals

- [N1] Does not let a reused review clear `review:human`; the human ceremony is unchanged (`planRecordDecision` INVARIANT 2, we:scripts/operations/review-pr.mjs:2073).
- [N2] Does not change how `earnedShape` is scored (`buildShapePlan`) or add lenses. Advisory reuse has an explicit one-pass completion target; it does not claim the shape's earned multi-round review is complete.

## Edge cases this change must handle

1. **Untrusted text** — the reused advisory is read only from comments passing `trustedAdvisoryComments` (we:scripts/lib/advisory-labels.mjs:126); its text is parsed for head sha, lenses and rounds only and never reaches argv, a shell or a note unfolded (`foldUntrusted`).
2. **Truncated reads** — the comment list comes from `readCompletePrComments` (we:scripts/conveyor/pr-comments-complete.mjs); a truncated page is an error and means "re-run", never "no advisory found" or "advisory found".
3. **Shared state files** — n/a: no new state file; the setting is read-only from we:scripts/review-settings.json, and labels use the existing label writer.
4. **Fail closed** — dispatch makes no early label guess when its scope read fails, is degraded, or has no valid paths. `assertDeclaredShapeHolds` returns `null` only for an empty/non-array list (we:scripts/operations/review-pr.mjs:1028); it does not itself attest a successful net read. At park time, unscorable or head-mismatched scope, unreadable settings, or an unparseable advisory refuses reuse and ensures awaiting; these later failures must not suppress a human hold already earned by the independent park gate. Name the refusal in the log.
5. **Identity scoping** — the caller scopes the complete-comment read to the subject repo + PR; `advisoryCoversHead` only compares head strings and accepts prefixes (we:scripts/lib/advisory-labels.mjs:131). Reuse additionally requires exact full-SHA equality and a scored net scope pinned to that same fresh head. Never mix comment arrays or checkout evidence across subjects.
6. **State over time** — a new head voids the reuse (the advisory no longer covers it); a daemon restart between review and park re-derives from comments and labels, so no in-memory state is needed; the stale `review:awaiting-advisory` and `status:ready-to-merge` labels are removed in the same park step.
7. **Who wrote it** — only trusted-marker-author comments count (see 1); a comment from anyone else with the same text is ignored, and an operator-added `review:human` label is never removed by this change.

Its proposed injected `readReviewScope` production reader must obtain the scored net diff, current head and labels using the same net-basis reader as `review-pr read`; it supplies `netChangedFiles` to a pure `decideUpfrontHuman` using `buildShapePlan`, and populates the session's `scopePaths` from that list. Do not assume existing callers supply `scopePaths`: they do not. Default `job` mode must execute this preflight too, before `dispatchReviewJob` launches its worker. Route both branches of the review-dispatch CLI and the direct `dispatchReview` call in we:scripts/operations/land-advance-io.mjs through `dispatchReviewByMode` (preserving the latter's session mode and injected actions). The direct invocations in we:scripts/lib/daemon-live-smoke.mjs:577 and we:scripts/conveyor/soak/breaks/review-dispatch-stalls-on-unrelated-clone-lag.mjs:39 are launcher probes, not production PR dispatch; leave those probes and the low-level launcher contracts unchanged.

Empty scope, failed/degraded net reads or null shape mean no early label guess and a named refusal log; preserve existing labels. A failed required label write must prevent launch rather than start a review against stale labels. The downstream review reads the updated labels, so it runs as an advisory.

Give `readReviewScope` a production default, not only a test injection: wrap the existing `createReviewPrReader` export from we:scripts/operations/review-pr-io.mjs in we:scripts/operations/review-job.mjs (no reader-module edit), which resolves the subject checkout and calls `readPr`. Take paths/scored/reason/head from `raw.net.paths`, `raw.net.scored`, `raw.net.reason` and `raw.net.revSha`, and labels from `raw.detail.labels`; also require `raw.diff.scored === true` before trusting the scope. Reject malformed path lists instead of silently filtering them to a smaller shape. This reuses the existing main/stack net basis without substituting the displayed three-dot file list. The wiring test must retain this default adapter and mock its transport inputs; injecting a finished scope object proves only orchestration. The CLI and land caller must forward repo, PR and checkout context to it. Normalize the CLI PR string to a positive integer before calling the reader: its input guard rejects strings (we:scripts/operations/review-pr-io.mjs:231), while the CLI currently forwards `flag('pr')` directly (we:scripts/operations/review-dispatch.mjs:723). Preserve the existing launcher input contract. Treat `raw.net.revSha` as the commit actually diffed, not as an independently observed live forge head (we:scripts/operations/review-pr-io.mjs:364); park reuse must compare recorded coverage against the fresh PR head. Do not change the synchronous dispatch return contract; adapt the existing synchronous reader and label provider.

Add a diagnostic loading seam in the same settings module that distinguishes successful default resolution from an unreadable/invalid file. A missing reuse key in a valid object uses the default; malformed JSON, a non-object root or a present non-boolean reuse key refuses reuse. Keep unrelated setting validation unchanged. The existing loader catches every error and returns defaults (we:scripts/lib/review-settings.mjs:88); a default-on reuse flag must not turn that failure into permission. Preserve the existing resolver contract for other settings; the reuse caller requires successful loading before applying the cascade, even if an environment override enables reuse. `parseAdvisories` consumes `renderAdvisoryNote` and also accepts ordinary `renderVerdictWriteUp` records through its legacy Verdict/Net-basis fallback. The advisory note currently lacks reusable round metadata. Add one shared completed-coverage renderer for explicit completed-lens and completed-round fields to BOTH producers and parse those fields in we:scripts/lib/advisory-labels.mjs. Put coverage and earned-shortfall disclosure before the advisory outcome/footer, preserving the producer outcome slot immediately above the separator consumed by `advisoryOutcomeAtSlot` (we:scripts/conveyor/reconcile-core.mjs:1348). The advisory renderer currently omits `renderEarnedShortfall`; add the same truthful disclosure there as well as updating the ordinary renderer. This makes a newly recorded ordinary accept reusable when it later parks, as in #4763. Populate the fields from actual completed judging results, excluding skipped seats; never copy the earned/requested shape as evidence of work done. Derive completed coverage in the reduce step from successfully completed judging answers, before the flattened lens verdict map (we:scripts/operations/review-pr.mjs:2997); that map alone can include a derived verdict without proving seat completion. Do not aggregate earlier heads or invent multi-round history; if completed rounds cannot be established, emit zero. Legacy/malformed notes with missing fields parse as zero coverage and cannot be reused. Use real output from both renderers for parser fixtures.

The reuse target is explicitly **one completed advisory pass with at least one successfully completed seat for every lens in `earnedShape.mandatoryFloor`**, not completion of the shape's full review plan. Human-required shapes earn care `high` and three rounds; demanding three completed rounds from a record that can prove at most one would make reuse unreachable at every human park. Requiring all five earned lenses is likewise unreachable with the current two mandatory seats: `review-pr` does not wire the full panel (we:scripts/operations/review-pr.mjs:2505). Use the existing `buildShapePlan` mandatory floor (correctness and security for code), never a floor narrowed to whichever seats happened to run. Refuse an empty, missing or malformed floor, a missing completed floor lens, or zero/unknown completed rounds. Keep the scored earned lenses, rounds and jurors per lens unchanged. Update `renderEarnedShortfall` in we:scripts/operations/review-pr.mjs:2167 alongside the shared completed-coverage renderer: it currently hard-codes one juror per seated lens and one round (we:scripts/operations/review-pr.mjs:2182), which cannot prove successful completion. Render earned versus completed coverage from the new reduction evidence, including earned 3 rounds / completed 1 and missing or skipped seats, without upgrading a seated-but-skipped lens to completed. Reuse only satisfies `review:awaiting-advisory`; it never satisfies the remaining review obligation, clears `review:human`, or permits merge. Full-panel wiring and multi-round provenance are not prerequisites for this advisory target.

Add pure `decideAdvisoryReuse({ advisories, headSha, earnedShape, setting })`: reuse only when the setting is on, the latest trusted advisory is an `accept` covering this head (`advisoryCoversHead`), with both parsed and live heads validated as full 40-hex SHAs and equal (the existing helper alone also accepts prefixes), its completed lenses include every lens of the validated nonempty `earnedShape.mandatoryFloor`, and its completed rounds meet the constant one-pass advisory target, `completedRounds >= 1`. That threshold is the same at every care level: `decideAdvisoryReuse` never reads earned rounds and never compares completed rounds with them, so the three rounds a care-`high` human park earns cannot make reuse unreachable. Likewise it never reads earned jurors per lens: one completed seat per floor lens is enough, even though care `high` earns two (and a `thin-jury` style single-juror check must not be applied to this decision). Parse completed rounds as a non-negative decimal integer with no sign, fraction or leading zero; anything else, or a value above 1 (one record proves at most one pass), is malformed and refuses reuse. Compare floor lens names with completed lens names exactly, using the canonical lens ids `buildShapePlan` and the renderers already emit; do not case-fold or trim, and an unknown or differently spelled lens never counts. A newer changes/inconclusive note blocks reuse of an older accept. At all three park-to-human sites in we:scripts/merge-ai-prs.mjs (we:scripts/merge-ai-prs.mjs:5725, we:scripts/merge-ai-prs.mjs:5847, we:scripts/merge-ai-prs.mjs:5948), share one reuse/awaiting-label decision using fresh complete comments and the scored net shape; never infer earned shape from the hold label alone. Preserve each park branch's existing acceptance/clearance decision: in particular, the manifest-tamper branch explicitly passes `keepHumanClearance: true` (we:scripts/merge-ai-prs.mjs:5711). Reuse must neither revoke that preserved clearance nor broaden it into merge permission. Also close the existing ordinary-verdict fallback in `planAdvisoryRepairLabels` (we:scripts/lib/advisory-labels.mjs:168): it currently clears awaiting on a prefix head match with no coverage or setting check. Distinguish actual advisory records from ordinary verdict records in the parser. An unknown, missing or non-accept recorded decision cannot establish an ordinary accepted review.
