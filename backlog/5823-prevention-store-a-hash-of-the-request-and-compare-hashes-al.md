# Prevention — compact saved requests, validate fallback envelopes, and redact judge stderr

Filed mechanically on approval of web-everything/web-everything#4865. Preserve all three owed guards: compact saved judge requests, reject incomplete fallback result envelopes, and sanitize stderr before diagnostics or persistence.

Idempotency key (do not edit): approval-prevention-key:web-everything/web-everything#4865@f6d2033ddc3ce6e788277998028ffb441223f204

## Design

1. **Saved request identity.** In `we:scripts/operations/cli-adapter.mjs`, persist a SHA-256 hex `requestHash` in each saved successful seat instead of its full `request`. Hash the exact JSON serialization used by `sameJudgeRequest` in `we:scripts/operations/parallel-judges.mjs:85`; do not sort keys or omit request fields. Keep full requests for live in-memory batch execution. On resume, compare a valid stored digest with the current request digest, plus the existing step identity and its step index. Missing, malformed, or mismatched identity discards the saved answer and spawns that seat again. Do the discard at LOAD time (the restore loop at `we:scripts/operations/cli-adapter.mjs:1032`) for a missing/malformed digest with no legacy request, so an invalid-identity seat never sits in `prefilled`, blocks re-batching (`we:scripts/operations/cli-adapter.mjs:1107`) or is re-persisted by a later failure; a valid-shaped digest that merely mismatches is still decided at the compare (`we:scripts/operations/cli-adapter.mjs:1117`). **Carry the identity through the loaded entry:** the restore loop must store `requestHash` (derived from the saved digest, or hashed from a legacy `request`) on the in-memory entry, and the save loop (`saveRemainingSeats`, `we:scripts/operations/cli-adapter.mjs:1057`–`we:scripts/operations/cli-adapter.mjs:1062`, which re-saves every `prefilled.values()` entry) must write that stored digest, never hash `seat.request` (undefined for a resume-loaded digest-only seat). The carry-forward filter at `we:scripts/operations/cli-adapter.mjs:1056` only covers saved entries not in `prefilled`, which after the load loop is nearly always empty, so both paths are normalized but the `prefilled` path is the one that matters. Use the UTF-8 serialization and a 64-character lowercase hexadecimal digest. Serialization that throws or returns no string must invalidate reuse, never yield a matching sentinel. Preserve timestamps, result values, and once-only spend accounting. A request carrying its own `skipSpawn.answer` (#4815, short-circuit at `we:scripts/operations/cli-adapter.mjs:931`) spawns nothing; if such a seat is saved, its digest covers the whole serialized request including `skipSpawn`, so a changed pre-supplied answer invalidates reuse like any other field.
2. **Legacy records.** Accept old saved seats containing a request through the existing byte-for-byte comparison, also checking the step index. When retained seats are written again, replace their request with its digest. If both fields exist, the digest is authoritative; an invalid digest cannot fall back to a legacy request. The saved-seat validator in `we:scripts/operations/run-record.mjs:530` currently checks only the list, step name and nonnegative integer step index; it already accepts digest-bearing entries. Preserve that structural validation and test both representations; do not add a record-level digest rejection. Missing/malformed digests or a nonmatching valid step index discard only that answer at the adapter seam. Existing structural failures remain record validation errors. When saving after another failure, normalize every retained legacy entry, including the carry-forward list at `we:scripts/operations/cli-adapter.mjs:1056`; preserve a valid existing digest without trying to hash an absent request.
3. **Fallback envelope.** Tighten only the line-scanning fallback in `we:scripts/lib/judge-spawn.mjs:720`: a candidate must be a non-array object with a non-empty string `session_id` and either an own `structured_output`, own `result` or own `is_error` field (`is_error` stays acceptable because a budget-kill error envelope can omit `result`; the downstream code treats `result` as optional at `we:scripts/lib/judge-spawn.mjs:762`, and rejecting such an envelope would turn a `JudgeBudgetError` into a retried unparseable-stdout failure). Continue scanning past incomplete trailing JSON. Keep the downstream error/budget handling and structured-output object requirement. A standalone whole-document JSON response retains its existing behavior. This is a shape guard, not authentication of subprocess stdout; a forged complete envelope remains outside this guarantee.
4. **Shared redaction.** Reuse `redactCommandLine` from `we:scripts/operations/command-redact.mjs:115`. Apply it to raw stderr before any 160/600/1000-character excerpt, interpolation, retry log, failed-attempt field, timeout partial-stderr field, or telemetry field in `we:scripts/lib/judge-spawn.mjs`. Apply it defensively at `normalizeJudgeTelemetry` in `we:scripts/operations/run-record.mjs:156` and `seatFailureEvidence` in `we:scripts/operations/parallel-judges.mjs:90`, since callers can supply errors independently of the Claude spawner. Retain exit code, signal, attempts and useful sanitized text. Respect the helper's existing 4096-character input bound and truncation marker; do not tail-slice raw text first and lose a credential's marker. Do not promise preservation of the final raw stderr bytes after bounded sanitization. Scope of the defensive batch redaction: `seatFailureEvidence` sanitizes the copied `stderrTail`; `error.message` text of errors supplied by non-judge-spawn callers (printed at `we:scripts/operations/cli-adapter.mjs:902`, `we:scripts/operations/cli-adapter.mjs:1393`, `we:scripts/operations/cli-adapter.mjs:1528`, `we:scripts/operations/cli-adapter.mjs:1546` and stored as `results[k].error`, `we:scripts/operations/parallel-judges.mjs:126`) is out of scope here; judge-spawn errors are sanitized at construction. A3 and guard fixtures for long stderr assert the secret is ABSENT, never that a tail marker survives (the helper keeps only the first 4096 characters). Two known effects of the helper to handle and test: it replaces every C0/C1 control, newlines included, with `?` (`CONTROL_CHARS`, `we:scripts/operations/command-redact.mjs:71`), so collapse whitespace first where a single-line excerpt is wanted, then redact (a credential's marker survives either order); and it keeps the first 4096 characters, so the tail of very long stderr is dropped, which the card accepts rather than tail-slicing raw text.
5. **Prevention gate.** Add a pure source guard in `we:scripts/check-standards-rules.mjs` and wire it into `we:scripts/check-standards.mjs`, following the existing pure-detector guard pattern (file list plus detector, e.g. the lane-journal coverage guard) at `we:scripts/check-standards.mjs:1594`. Inventory the judge stderr sinks in the three modules above; require each to consume the shared sanitizer or a locally sanitized binding. Catch direct raw stderr interpolation, slicing into persisted properties, and removal/bypass of sanitization, with file/line diagnostics. Inspect executable code, not a token's mere presence in comments or an unused import. This first guard covers the named judge persistence/error paths; it is not a claim of whole-program taint analysis for every subprocess in the repository.

## MVP

- Implement digest save/reuse and legacy migration at the adapter seam, with identity helpers in `we:scripts/operations/parallel-judges.mjs` and preserved structural saved-seat validation in `we:scripts/operations/run-record.mjs`.
- Tighten fallback parsing and sanitize all stderr-bearing outputs of `we:scripts/lib/judge-spawn.mjs`; sanitize independently supplied telemetry and batch failures at their boundaries.
- Deliver the wired standards guard and regressions together. No live provider calls, provider-routing changes, health-cap increase, or new record-store migration command.

## Acceptance

- [A1] Saved successful seats contain a fixed-size digest and no request copy; an unchanged resume reuses answers and charges no duplicate spend. Changed or invalid identity respawns only the affected seat.
- [A2] A forged trailing JSON object containing only `structured_output` cannot replace a preceding full result; without a valid envelope the noisy-output path refuses.
- [A3] Supported credential shapes and C0/C1 controls are absent from error messages, retry logs, exposed stderr properties and persisted telemetry after sanitization. Existing diagnostic length bounds remain enforced.
- [A4] The new regression cases fail on the current implementation and pass after delivery; removing a sanitizer at a guarded sink causes the standards guard to fail.

## Non-goals

- No arbitrary stdout authentication, generic secret scanner, record retention policy, global record-size guarantee, or rewriting historical records in place.
- No HTTP receive/write endpoint is introduced; body limits, rate limits, CSRF/origin checks and remote reset protection do not apply.

## Edge cases this change must handle

1. **Untrusted text** — envelope shape checks and the existing shared redactor; unmarked arbitrary secrets remain outside its documented coverage.
2. **Truncated reads** — sanitize before excerpting; preserve truncation indication. Never infer a result from incomplete JSON.
3. **Shared state files** — retain the existing run-store write discipline; no new shared file or lock.
4. **Fail closed** — invalid saved identity respawns, never accepts the stale answer; incomplete fallback envelopes never produce a verdict.
5. **Identity scoping** — compare within the same run and step/index using the entire serialized request; digest equality is not author authentication.
6. **State over time** — legacy records remain resumable and retained seats migrate on write; consumed/discarded seats disappear as before.
7. **Who wrote it** — preserve existing run/session provenance and timestamps; add no claimed authentication to saved data.
