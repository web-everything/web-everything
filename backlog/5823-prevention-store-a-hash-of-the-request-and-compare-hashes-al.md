# Prevention — compact saved requests, validate fallback envelopes, and redact judge stderr

Filed mechanically on approval of web-everything/web-everything#4865. Preserve all three owed guards: compact saved judge requests, reject incomplete fallback result envelopes, and sanitize stderr before diagnostics or persistence.

Idempotency key (do not edit): approval-prevention-key:web-everything/web-everything#4865@f6d2033ddc3ce6e788277998028ffb441223f204

## Design

### Saved request identity and migration

Persist each successful saved seat with `requestHash`, never a full `request`. Add a shared request-digest helper in `we:scripts/operations/parallel-judges.mjs`, beside `sameJudgeRequest` at `we:scripts/operations/parallel-judges.mjs:85`. Hash the UTF-8 bytes of `JSON.stringify(request)` with SHA-256, yielding exactly 64 lowercase hexadecimal characters. Preserve JSON serialization order and every serialized field, including mandate, input, shape, model, `allowedTools` and `skipSpawn.answer`; do not introduce sorting or field selection. JSON's existing omission/coercion rules remain the identity contract. Serialization that throws or yields no string returns an invalid identity, never a reusable sentinel. Require two valid digests before equality: the current `sameJudgeRequest(undefined, undefined)` compares two undefined serialization results as equal at `we:scripts/operations/parallel-judges.mjs:86`. Full requests remain available for live batch execution.

In `we:scripts/operations/cli-adapter.mjs:1052`, normalize restored entries to a stored digest. An own `requestHash` is authoritative: malformed, missing-value or mismatched digests cannot fall back to a legacy request. Only entries with no digest property may derive one from a serializable legacy `request`; this preserves the existing byte-for-byte JSON identity. Invalid identity must be removed from both the restored map and the working record's saved list, so it neither blocks batching at `we:scripts/operations/cli-adapter.mjs:1127` nor survives the carry-forward save at `we:scripts/operations/cli-adapter.mjs:1078`.

At the reuse comparison in `we:scripts/operations/cli-adapter.mjs:1139`, require the same step name, matching pending step index and valid equal request digests. A valid-shaped but stale digest or wrong index discards only that answer and runs that seat again. Keep fresh in-memory batch results reusable through the same identity rule. Failed fresh seats retain their current failure handling.

At `saveRemainingSeats` in `we:scripts/operations/cli-adapter.mjs:1076`, normalize both the carry-forward list and every successful map entry. A loaded digest-only entry must keep its stored digest, not hash its absent request. A fresh seat derives its digest from the request. Omit unidentifiable answers while still recording real spawn spend. Preserve result values, timestamps and `telemetryRecorded`; fail → resume → fail → resume must keep the remaining saved answers reusable without double charging. Legacy entries migrate on the next save; do not rewrite historical records separately. Normalize the working record as well as the map during restore, before any subsequent `store.write`. The sequential failure branch does not call `saveRemainingSeats`: its direct write is conditional on telemetry at `we:scripts/operations/cli-adapter.mjs:1170`, while review observations independently write via `recordSeat` at `we:scripts/operations/cli-adapter.mjs:1041`. Migration and invalid-entry removal must therefore not depend on the saved-seat helper running. Preserve the existing write points; an exception with no write need not rewrite the on-disk record. Exercise both telemetry-bearing and telemetry-free repeated failures, and verify migration on the next actual write.

Keep structural saved-seat validation at `we:scripts/operations/run-record.mjs:530`: non-array lists, absent step names and negative/noninteger indexes remain record errors. Digest validation belongs to answer reuse, so one malformed identity cannot make the entire record unreadable. `driveRun` still defaults to sequential execution at `we:scripts/operations/cli-adapter.mjs:1023`; only the saved representation changes by default. The request-provided answer shortcut at `we:scripts/operations/cli-adapter.mjs:933` still spawns nothing, and its entire request participates in identity.

### Fallback result envelope

Tighten only the reverse line scan in `we:scripts/lib/judge-spawn.mjs:715`. Accept a candidate only when it is a non-array object with a non-empty string `session_id` and at least one own `structured_output`, `result` or `is_error` property. Continue scanning past incomplete trailing objects; if no candidate qualifies, retain the marked unparseable-stdout error and existing retry behavior. A result-less error envelope must remain eligible: `session_id` plus `is_error` and `stop_reason: 'tool_use'` with a supplied budget must still reach `JudgeBudgetError` at `we:scripts/lib/judge-spawn.mjs:757`.

Leave whole-document JSON handling and the downstream structured-output object requirement intact. This checks shape, not authenticity: a forged complete envelope is outside this guarantee.

### Stderr sanitation at producer and consumer boundaries

Reuse `redactCommandLine` from `we:scripts/operations/command-redact.mjs:115` without changing its policy. Pass raw stderr to the helper before whitespace folding, trimming, taking any excerpt, interpolating diagnostics, copying exposed stderr or persisting it. Apply single-line formatting and smaller display limits only to the sanitized result. Folding raw whitespace first is unsafe: the existing vertical-tab fixture at `we:scripts/operations/__tests__/command-redact.test.mjs:117` requires both fragments of a token flag value split by a vertical tab to disappear; replacing the tab with a space before redaction separates the second fragment from the marked value. The helper neutralizes C0/C1/DEL controls, masks supported credential shapes and caps input work at 4096 characters, retreating at the cut and adding a truncation marker. That is an input cap, not a 4096-character output promise: replacement markers can expand short values. `partialStderr` must equal the shared sanitizer's result; other excerpts retain their stated smaller limits. Long diagnostics may lose their original final bytes. The visible truncation marker and retained exit/signal/attempt/timing evidence are the diagnostic fallback; never recover detail by exposing a raw tail. The guarantee covers stderr-derived content, not the formatting newlines of an error message or secrets separately supplied in stdout/result text.

Cover this complete sink inventory in `we:scripts/lib/judge-spawn.mjs`:

- `stderrSnippet` at `we:scripts/lib/judge-spawn.mjs:228`: sanitized 160-character retry/summary excerpts.
- `JudgeUnparseableError` at `we:scripts/lib/judge-spawn.mjs:234`: message's 600-character excerpt, 1000-character `stderrTail`, telemetry, and copied `failedAttempts[].stderrTail`. The constructor must sanitize caller-supplied attempt entries without mutating the caller's array.
- `JudgeTimeoutError` at `we:scripts/lib/judge-spawn.mjs:268`: message excerpt and `partialStderr`; the latter becomes sanitizer-bounded rather than an unbounded raw copy.
- `JudgeBudgetError` at `we:scripts/lib/judge-spawn.mjs:304`: stderr excerpt.
- `parseJudgeOutcome` at `we:scripts/lib/judge-spawn.mjs:727` and `we:scripts/lib/judge-spawn.mjs:775`: unparseable and result-less error excerpts.
- Failed-attempt capture at `we:scripts/lib/judge-spawn.mjs:976` and retry log at `we:scripts/lib/judge-spawn.mjs:983`: sanitize on retry-then-success as well as exhaustion; preserve exit code, signal, attempt count and timing evidence.

Defensively sanitize independently supplied `stderrTail` in `normalizeJudgeTelemetry` at `we:scripts/operations/run-record.mjs:163` and `seatFailureEvidence` at `we:scripts/operations/parallel-judges.mjs:97`, before their 1000-character limits. Batch logs then consume that sanitized evidence. The raw error object retained at `we:scripts/operations/parallel-judges.mjs:128` is outside this stderr boundary. The adapter outcome already applies `redactSpawnText` to error messages at `we:scripts/operations/cli-adapter.mjs:1445`; preserve that separate protection. It does not sanitize the producer stderr fields or persisted telemetry covered here. Also pin the batch log at `we:scripts/operations/parallel-judges.mjs:135` to the sanitized evidence path so a future raw-error substitution cannot bypass it.
