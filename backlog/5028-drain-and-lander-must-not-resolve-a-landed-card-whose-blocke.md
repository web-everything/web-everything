# Drain and lander must not resolve a landed card whose blockedBy are still open

Live on #3834 (card 4374): landing the PR resolved a card whose blockers were still open, because we:scripts/lane-drain.mjs resolveLandedItem (shared with we:scripts/merge-ai-prs.mjs) and we:scripts/backlog.mjs resolve never check the card's blockedBy. Fix: refuse or skip the resolve flip when any blockedBy is unresolved, keep the card open, and report it.

## Scope

- we:scripts/lane-drain.mjs `resolveLandedItem` (the one resolve-on-land home, also called by we:scripts/merge-ai-prs.mjs): before running `we:scripts/backlog.mjs resolve`, read the card's `blockedBy` and look each blocker up; if any is not `resolved`, skip the flip, leave the card `open`, and return `{ flipped: false, blockedBy: [...], reason: 'blockers-open' }`.
- Both callers (the drain and the label lander) print the skip plainly ("card N stays open, blocked by M, K") instead of the success line, and the stranded-sweep (we:scripts/backlog-stranded-sweep.mjs) honours the same check since it resolves through the same function.
- Operator ruling: PR #3834 lands as is; this card is the real fix. The check lives in the drain/lander, not in `we:scripts/backlog.mjs resolve` itself (a human `/resolve` stays allowed).
- Out of scope: auto-resolving the card later when its last blocker resolves (a follow-up if wanted).

## Done when

1. **Executable** — the host-queued Vitest run of we:scripts/__tests__/lane-drain.test.mjs includes a regression for the #3834 / card 4374 shape (a landed card with an open blocker) and fails before the fix, passes after.
2. **Must (refuse)** — a landed card with at least one non-resolved `blockedBy` is NOT flipped to resolved by the drain or the label lander; it stays `open`, no resolve commit is made, and the skip names the open blockers in the drain output.
3. **Must (unreadable blocker)** — a blocker that cannot be found or read counts as open (never as resolved): an unknown blocker never lets the flip through.
4. **Must (no regression)** — a landed card with no `blockedBy`, or with every blocker `resolved`, is still resolved on land exactly as before, for the drain and the label lander alike.
5. **Must (non-source inputs)** — the check reads frontmatter only, so it behaves the same for docs-only, config-only and data-only cards.
6. **Must (named risk tests)** — the risk 3, 5 and 6 cases named in the Test plan table exist under those exact names and are green: `resolve commit touches only the card`, `self-reference refuses`, `same-pass numbering uses rewritten index paths` and `same-pass blocker resolution reads current frontmatter` in we:scripts/__tests__/lane-drain.test.mjs, and `repeated blocked sweeps recover once` in we:scripts/__tests__/backlog-stranded-sweep.test.mjs.

## Edge cases this change must handle

1. **Untrusted text** — `blockedBy` entries come from card frontmatter. Validate the entire trimmed raw token as an ID or an ID with a safe slug before applying the imported canonical helpers; a valid ID prefix cannot hide an invalid suffix (e.g. `43-../../etc`). Only canonical IDs matching `^(\d{1,5}|x[0-9a-z]{6})$` are looked up; rejected raw tokens count as open blockers and are never used in a path or git argv. A slug such as `43-blocker` is accepted, but slugs containing traversal, separators, control characters, quotes, backticks, or invisible/Unicode lookalikes are rejected. The printed skip line folds newlines and backticks via `foldUntrusted` (we:scripts/lib/jury-core.mjs).
2. **Truncated reads** — blocker lookup uses `git ls-files` with an explicit pathspec per id, not a capped listing; a failed or empty read counts as open, never as "no blockers".
3. **Shared state files** — the guard itself is read-only; the only write is the existing resolve commit, unchanged and still scoped to the one card path by its explicit `-- <path>` pathspec (we:scripts/lane-drain.mjs `resolveLandedItem`). Because the guard adds a new early return and new injected options in front of that commit, the single-card write guarantee is pinned by a required planned test: `resolve commit touches only the card` in we:scripts/__tests__/lane-drain.test.mjs, whose committed-path assertions are mapped below.
4. **Fail closed** — unparseable `blockedBy`, missing blocker file, unreadable file, missing `status`, or any status other than `resolved` → open blocker, reason `blockers-open`. An unreadable card body (`body == null`) keeps today's behaviour (out of scope for this card).
5. **Identity scoping** — blocker ids resolve in both spellings (NNN and `xNNNNNN` hash); after same-pass numbering rewrites the reference and filename, lookup uses the rewritten numeric ID. An obsolete hash reference with no tracked match fails closed; this change does not add a hash-alias lookup. A self-reference in `blockedBy` counts as open (a card cannot unblock itself). Required planned tests: `self-reference refuses` and `same-pass numbering uses rewritten index paths` in we:scripts/__tests__/lane-drain.test.mjs; their integration assertions are mapped below.
6. **State over time** — the check runs at land time against tracked paths and current working-tree frontmatter, so a blocker resolved earlier in the same pass is seen as resolved. A skipped card retains its existing non-resolved status; the stranded sweep is the recovery path and re-runs the same check, so it keeps reporting until the blockers resolve (idempotent). Required planned tests: `same-pass blocker resolution reads current frontmatter` in we:scripts/__tests__/lane-drain.test.mjs and `repeated blocked sweeps recover once` in we:scripts/__tests__/backlog-stranded-sweep.test.mjs; their transition assertions are mapped below.
7. **Who wrote it** — n/a: no comment, label or ref grants trust here; the verdict comes only from the repo's own backlog frontmatter.
