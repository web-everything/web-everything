# Health smell when an operator-only hold on a PR passes an age

Add an operator-hold-aged health smell for cap-exhausted, stood-down, review-referrals-pending and ruling-dispute refusals observed by the review daemon. Report repository, PR, kind and continuously observed age at a configurable threshold (default 30 minutes), honour quietHours, and clear on confirmed removal. “Operator-only” names the alert population: existing code can also end some holds after a new head, ruling or send-back. Historical review-side PR-minutes in the coroner-4 window were cap-exhausted 1,106 (#4433, #4478 218 min), stood-down 942 (#4461 218), review-referrals-pending 934 (#4388 315), ruling-dispute 656 (#4361 515; the false-alarm part is held item 141). Those aggregates and the legacy explanation rows in `we:.conveyor/review-daemon.log` do not establish continuous onset or clearance; complete structured observations are required. Found by coroner-4 (held item 192); quiet-hours context is held item 134.

## Acceptance

- [A1] **Executable** — the planned test in `we:scripts/conveyor/health-smells/__tests__/operator-hold-aged.test.mjs` feeds complete review-daemon hold snapshots through the health core: one cap-exhausted hold continuously observed for 45 minutes opens one `operator-hold-aged` episode naming repository, PR, kind and observed age.
- [A2] Covers cap-exhausted, stood-down, review-referrals-pending and ruling-dispute. Below the configured threshold (default 30 minutes), no episode opens; at the threshold it opens.
- [A3] A successful snapshot without the hold clears its episode; a returning hold starts a new age. Unknown input never counts as clearance. Quiet hours suppress delivery, not observation or episode bookkeeping.
- [A4] Live proof on the running health-watch shows an aged open hold and subsequent confirmed clearance, with before/after evidence. Notification delivery uses the existing quiet-hours gate, including in shadow mode.

## Non-goals

- [N1] Does not clear, auto-resolve or dispatch work for a hold; it only alerts.
- [N2] Does not fix the ruling-dispute false alarm (held item 141).
- [N3] Does not reconstruct exact historical hold onset from incomplete legacy logs, change reconciler refusal policy, or replace the aggregate stood-down smell.

## Edge cases this change must handle

1. **Untrusted text** — consume only a configured repository identity, positive safe-integer PR number, allowlisted kind and finite, nonnegative timestamp no later than the consuming tick. Do not copy titles, free-text reasons or commands into the new records or notifications.
2. **Truncated reads** — retain an incomplete last record until its newline arrives; malformed, missing or unreadable snapshots are unknown, never an empty hold set.
3. **Shared state files** — the review daemon appends observations to its existing log; the watch persists hold history in its existing state. No additional shared state file or writer.
4. **Fail closed** — absent, nonnumeric, nonfinite, zero or negative threshold uses 30 minutes. Reject malformed snapshot records atomically.
5. **Identity scoping** — one episode per (repository, PR, hold kind); deduplicate repeated rows and distinguish equal PR numbers in different repositories.
6. **State over time** — use the first valid observation of the current uninterrupted observed hold, not the most recent repeated row. Confirmed removal then return resets age. Unknown intervals do not prove continuous holding or clearance; retain an existing episode without advancing it, and restart onset observation when continuity cannot be established.
7. **Who wrote it** — the daemon emits structured observations from its own reconcile plan; health-watch does not interpret arbitrary PR text as a hold record.

## Design

1. In `we:skills-src/conveyor/review-daemon.mjs`, extract the four allowlisted kinds from the successful final reconcile plan, including nested `reviewRefusal` rows. Append a dedicated `review-daemon: operator-hold-snapshot ` prefix followed by single-line JSON `{version: 1, repo, observedAt, status: 'complete', holds: [{prNumber, kind}]}`; these are proposed record fields. Deduplicate the complete hold list and timestamp the observation with an injectable clock. An empty list is positive clearance evidence. Carry this result through the per-repository aggregation to CLI logging; do not derive it from `pendingNotDispatched`. For failed/skipped/unavailable repository observations emit the same envelope with `status: 'unknown'` and no `holds`, never a successful empty set; a whole skipped tick marks all watched repositories unknown. A promotion/replan failure must not pass off the retained earlier plan as a fresh complete observation (`we:skills-src/conveyor/review-daemon.mjs:368-376`). Preserve existing explanations, dispatch outputs and hold-resolution policy; introduce no extra GitHub read.
2. In `we:scripts/conveyor/health-watch-core.mjs`, parse and fold only those prefixed records, separately from legacy refusal memory. Validate each record atomically against the version, configured repositories, timestamp and allowlisted row shape. Ignore ordinary log lines; reject malformed candidate snapshots as unknown, scoped to their validated repository when possible and otherwise to all watched repositories. Persist per-repository snapshot time and per-key first/last observation in the existing daemon state. Repeated identical holds preserve onset; an authoritative empty/changed set records the absent keys as confirmed removals. Ignore duplicate and out-of-order snapshots. Use record timestamps, never inferred spacing of legacy tick summaries; age is last confirmed observation minus onset, not time extrapolated from the last log mtime. Bootstrap starts at the earliest complete valid retained snapshot, explicitly an observed lower bound on age. Process records in order so a clear-and-return in one read still ends the old episode and resets onset.
3. Retain the previously prepared continuity rule: a gap greater than two expected review intervals makes the observation unknown. Use the review daemon's parsed interval, with its manifest interval as fallback, and check freshness on every health tick even when no new bytes arrive. Explicit unknown records and missing/unreadable review-log input break continuity immediately. Preserve existing episodes while unknown, suppress fresh alerts, and begin a new continuous-age measurement on recovery. If the same hold returns before reaching the threshold again, retain its already-open episode without a new notification; reset age alone is not clearance. A fresh complete snapshot can positively clear an old episode. Keep memory bounded to current snapshot keys and removal evidence needed by unresolved episodes; discard cleared observation history after episode processing.
4. Add `we:scripts/conveyor/health-smells/operator-hold-aged.mjs` with repo scope, every-tick cadence, alert-only action, medium severity, one-sample open/close hysteresis and `missingSubjectsUnknown: true`. Retain the core's existing flapping rules. Read `operatorHoldAgeMinutes` from the existing health configuration, accepting only finite positive numbers and otherwise using 30. Use a stable repository/PR/kind subject and numeric observed age/threshold in the summary/measure. Emit breaches for confirmed aged holds and explicit clean results only for confirmed removals; omit unknown and not-yet-aged subjects. Missing whole-probe input uses the existing skipped-evaluation route. Feed removal evidence through the core context so healthy repositories can clear while other repositories remain unknown; retire an old episode before processing a returning hold from a later snapshot in the same batch.
5. In `we:scripts/conveyor/health-watch.mjs`, supply review-log availability to the fold/evaluation, distinguishing an empty append from a missing log. Reuse the complete-line cursor logic at `we:scripts/conveyor/health-watch.mjs:285-295`; preserve a partial final record across reads and treat known truncation/lost rotation history as a continuity break. Add the new smell to `we:scripts/conveyor/health-smells-notify-list.mjs` so the requested alarm reaches the operator in shadow mode. Reuse ordinary notification cooldown/deduplication and quiet-hours delivery; give this smell no emergency breakthrough tag. Keep observing and clearing during quiet hours.
