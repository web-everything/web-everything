# Health smell when an operator-only hold on a PR passes an age

The four operator-action hold kinds need a per-hold observed-age alarm; some can also end through normal head/ruling transitions. Historical review-side PR-minutes in the coroner-4 window: cap-exhausted 1,106 (#4433, #4478 218 min), stood-down 942 (#4461 218), review-referrals-pending 934 (#4388 315), ruling-dispute 656 (#4361 515; the false-alarm part is held item 141). The coroner reported them on /wip without an age-triggered ping; current source inspection still finds no detector for this four-kind population. Fix idea: one operator-hold-aged health smell (setting, default 30 min) over these hold kinds, reporting PR, kind and age, honouring quietHours (held item 134); it clears itself when the hold clears. Historical evidence: we:.conveyor/review-daemon.log 'no review dispatched — cap-exhausted|stood-down|review-referrals-pending|ruling-dispute'. Found by coroner-4 (held item 192).

## Acceptance

- [A1] **Executable** — the planned test in `we:scripts/conveyor/health-smells/__tests__/operator-hold-aged.test.mjs` feeds complete review-daemon hold snapshots through the health core: one cap-exhausted hold continuously observed for 45 minutes opens one `operator-hold-aged` episode naming repository, PR, kind and observed age.
- [A2] Covers cap-exhausted, stood-down, review-referrals-pending and ruling-dispute. Below the configured threshold (default 30 minutes), no episode opens; at the threshold it opens.
- [A3] A successful snapshot without the hold clears its episode; a returning hold starts a new age. Unknown input never counts as clearance. Quiet hours suppress delivery, not observation or episode bookkeeping.
- [A4] Live proof on the running health-watch shows an aged open hold and subsequent confirmed clearance, with before/after evidence. Notification delivery uses the existing quiet-hours gate, including in shadow mode.

## Non-goals

- [N1] Does not clear, auto-resolve or dispatch work for a hold; it only alerts.
- [N2] Does not fix the ruling-dispute false alarm (held item 141).
- [N3] Does not reconstruct exact historical hold onset from incomplete legacy logs, change reconciler refusal policy, or replace the aggregate stood-down smell.

## Edge cases this change must handle

1. **Untrusted text** — consume only validated repository identity, positive integer PR number, allowlisted kind and finite timestamp. Do not copy titles, free-text reasons or commands into the new records or notifications.
2. **Truncated reads** — retain an incomplete last record until its newline arrives; malformed, missing or unreadable snapshots are unknown, never an empty hold set.
3. **Shared state files** — the review daemon appends observations to its existing log; the watch persists hold history in its existing state. No additional shared state file or writer.
4. **Fail closed** — absent, nonnumeric, nonfinite, zero or negative threshold uses 30 minutes. Reject malformed snapshot records atomically.
5. **Identity scoping** — one episode per (repository, PR, hold kind); deduplicate repeated rows and distinguish equal PR numbers in different repositories.
6. **State over time** — use the first valid observation of the current uninterrupted observed hold, not the most recent repeated row. Confirmed removal then return resets age. Unknown intervals do not prove continuous holding or clearance; retain an existing episode without advancing it, and restart onset observation when continuity cannot be established.
7. **Who wrote it** — the daemon emits structured observations from its own reconcile plan; health-watch does not interpret arbitrary PR text as a hold record.

## Design

1. **Producer contract.** In `we:skills-src/conveyor/review-daemon.mjs`, extract only cap-exhausted, stood-down, review-referrals-pending and ruling-dispute from the final successful plan's refusals, including each row's nested `reviewRefusal`. Deduplicate `(prNumber, kind)` without filtering on current review labels or the human-readable explanation helper. Return and aggregate one snapshot per successfully observed repository, then emit it from the CLI as a single newline-terminated `review-daemon: operator-holds ` record followed by JSON: `{version: 1, repo, observedAt, intervalMs, holds: [{prNumber, kind}]}`. Capture the observation time at plan completion and pass the resolved daemon interval; do not timestamp old data at log-read time. An empty list is affirmative clearance evidence. No success record after PR discovery/reconcile/replan failure, unavailable shared PR data, or a skipped tick. Check the existing replan error in the daemon without changing the promotion helper or the existing `onPlan` callback contract. Preserve dispatch behavior and human-readable output.
2. **Validation and memory.** In `we:scripts/conveyor/health-watch-core.mjs`, recognize only the dedicated record prefix from the review-daemon sample, after existing log timestamp stripping. Require version 1, a validated watched repository slug, positive integer PR numbers, allowlisted kinds, a finite nonnegative observation timestamp no later than the sample time, and a finite positive interval. Validate the whole record before applying any row; deduplicate rows, ignore duplicate/out-of-order snapshots, and treat malformed recognized records as unknown, never as empty. Ignore unrelated legacy lines. Persist per-repository snapshot time/interval and per-key first/last observation in existing health state, separately from legacy refusal memory. Old state without these fields starts unknown. Bootstrap uses only complete retained records and labels age as an observed lower bound; never invent earlier onset from log mtime.
3. **Continuity and clearance.** Retain the earlier design's limit of two expected review intervals, using each producer record's resolved interval. A longer gap, missing/unreadable review log, or malformed snapshot breaks continuity. If the malformed record cannot safely identify a repository, mark the review observation stream unknown; otherwise isolate that repository. Calculate age as last confirmed observation minus first observation, never advance it merely because the watch clock ticks. Recovery starts a new age for a still-present hold, but preserves any already-open episode until confirmed removal; a successful snapshot missing the key is positive clearance even after an unknown interval. A changed kind clears the old identity and starts the new one. Keep cleared identities only until their clean results have completed normal close/flap hysteresis, then discard them; retain unresolved episodes and use the existing bounded closed history.
4. **Detector and episode integration.** Add `we:scripts/conveyor/health-smells/operator-hold-aged.mjs` with scope `repo`, cadence `every-tick`, action `alert`, severity `high`, `openAfter: 1`, `closeAfter: 1`, and `missingSubjectsUnknown: true`. Read proposed `operatorHoldAgeMinutes` from the existing health config; only a finite positive numeric value is valid, otherwise use 30. Declare the log probe dependency. The core supplies folded hold observations and prior unresolved identities so the detector can emit explicit clean results for confirmed removals, breach results at/above threshold, and no result for unknown subjects. A recovered, still-present hold whose episode is already open must not emit clean merely because its new observation clock is below threshold. Omitted subjects remain unchanged under the existing episode logic; a globally missing probe uses its existing skipped-evaluation route. Subject is a stable repository/PR/kind tuple; summary and measure contain only validated identity, observed age and threshold. No PR titles, arbitrary reasons or commands enter the new records or notifications.
5. **Shell and delivery.** In `we:scripts/conveyor/health-watch.mjs`, distinguish a successful empty append from an absent review log or failed read, and convey availability to core folding on every watch tick. Reuse its newline cursor and rotation handling; do not create another log reader or shared state writer. Add the smell to `we:scripts/conveyor/health-smells-notify-list.mjs`; disk discovery already registers the new detector. High severity plus list membership makes the opening notification deliverable in shadow mode. Use the existing privacy scrub, quiet-hours gate/digest, silences, reminder and flap lifecycle; supply no emergency breakthrough tag. Observation and confirmed clearance continue during quiet hours. No generic notification-policy changes are needed.
