## Design

Use behavioral regressions, as the original review permits. Follow the existing daemon job rules in `we:docs/agent/platform-decisions.md#daemon-jobs`; preserve job record formats, retry limits, checkpoints, snapshot keys and retention policy.

In `we:scripts/lib/daemon-job-snapshots.mjs`, keep ensureCodeSnapshot, ensureNodeModulesStore, gitArchiveMaterializer, npmCiInstaller and evictSnapshots synchronous for current consumers. Add asynchronous companions for runtime preparation and eviction. Their argument shapes remain the same; the asynchronous ensure helpers return Promise<string> and Promise<{key, dir}> respectively, and eviction returns Promise<{evicted: string[]}>. Await both synchronous and Promise-returning injected materializers/installers. Publish the completion marker and rename only after the builder resolves; rejection removes staging artifacts and leaves no completed snapshot. Use unique staging directories and coalesce concurrent asynchronous builds of the same destination so yielding cannot make two builds remove each other's staging directory. Retain reuse of a completed winner.

Use the existing asynchronous runBounded helper at `we:scripts/lib/bounded-child.mjs:102` for default archive, extraction and installation children, preserving the current timeout constants. Write the archive to a temporary file using Git's output option, await successful production, then invoke tar separately. Remove the archive in finally. Apply separately checked archive/extraction to the synchronous materializer too, preserving its return/throw contract; no default path should retain the unchecked shell pipeline. Asynchronous eviction reuses the existing selection policy and performs recursive removal asynchronously; synchronous eviction and its dry-run contract remain available.

In `we:scripts/lib/daemon-jobs-runtime.mjs`, prepareJobCode and launchJob become asynchronous, and reattachTick awaits the launch callback's result (including synchronous injected results). Await worktree preparation as well. Keep launchedAt after preparation, and hold no file lock across an await. The default spawner resolves with the pid after the spawn event or rejects on error; attach listeners before returning, close log descriptors on every path, and retain an error listener for the child's lifetime. Record success/error only for the matching attempt; a fast child claim or completion must not be overwritten. Keep counted attempts and launch-grace retry behavior. Re-read each record immediately before classification/stop, handling a missing or newly corrupt record conservatively; keep the post-stop generation check.

Add an optional evict callback to reattachTick, defaulting to the asynchronous snapshot eviction companion; null explicitly means the caller owns housekeeping. After awaited admission, obtain a fresh complete record listing and pass every non-terminal job's snapshotKeys to eviction. Skip deletion and log when that listing contains corrupt records. Catch/log cleanup failure so later ticks retry; preserve non-overlapping ticks. This guards ordinary tick integration without imposing a new retention policy.

In `we:scripts/conveyor/health-watch-job.mjs`, pass evict: null to the shared reattach call because runGhProbeJobs already owns eviction and reports its result. Keep its existing evictToTrash callback, summary.evicted and detached sweeper. Make its own fresh housekeeping listing honor the same corrupt-record deletion hold. Preserve the synchronous snapshotWarm check, detached prewarm, rollback behavior and zero-attempt cold queue. The dependency/rebuild wrappers may retain their existing idempotent housekeeping; their synchronous snapshot consumers require no API migration.
