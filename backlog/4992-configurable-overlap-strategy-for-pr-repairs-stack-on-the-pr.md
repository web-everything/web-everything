# Configurable overlap strategy for PR repairs: stack on the predecessor instead of waiting in line

Operator ruling 2026-10-03: expose `dispatchGate.overlapStrategy` with `queue` and `stack`; default `stack`, `stackMaxDepth: 2`, and `stackReview: incremental`. Review the child's contribution above its predecessor's pinned head, run CI on the full stack, and require a full-diff check before merge. Automatically restack when the predecessor changes or merges. PRs touching statute or gate-self paths, or carrying `review:human`, retain queue behavior. This scheduling exception does not change who may clear a review.

The reported motivating incident was PR #3767 waiting “2nd behind #3787” on we:scripts/__tests__/review-set-label.test.mjs. The hours-long incident is operator-supplied context, not a timing measurement reproduced during preparation; the queue mechanism is observable at we:scripts/conveyor/reconcile-fix-dispatch.mjs:1484-1536.

## Design

1. **Configuration contract first.** Declare the three ruled fields under the dispatch-gate dimension in we:config/defineConfig.ts and we:config/platformDefaults.ts, export through we:config/index.ts, and consume the resolved values in the repair dispatcher. Use a small conveyor adapter (proposed we:scripts/lib/repair-overlap-policy.mjs), not a new general config resolver. Resolve project overrides using the existing dimension contract (we:config/defineConfig.ts:49-70). Missing overrides select the ruled defaults; malformed values produce a visible refusal, never a permissive stack. `stackMaxDepth` counts the root as depth 1, matching we:scripts/readiness/overlap-chain.mjs:18-25. Keep serial-batch defaults unchanged.
2. **Plan before mutation.** Extend the existing ranked queue at we:scripts/conveyor/reconcile-fix-dispatch.mjs:1484-1536. Queue mode preserves its ranking and refusals. Stack mode may admit a child before its predecessor merges only after observing a pushed, same-repository predecessor tip and recoverable stack identity. Use shared locus-aware overlap matching (we:scripts/readiness/overlap-chain.mjs:83-118) across source, docs, config, tests and data. Evaluate every blocker; do not bypass a live build claim, unavailable frontier, unknown identity, cycle, depth cap, or unresolved multi-parent topology. These cases retain a reasoned queue hold. Classify both child and ancestors for the statute/gate-self/human exception using the existing roster, not a new filename list (we:scripts/lib/gate-config.mjs:86-104).
3. **Persist pinned lineage before starting repair.** Carry predecessor repository/PR identity, item identity, immutable head SHA, child head SHA, depth and review basis through dispatch and the worker instructions. The current brief-fill seam is we:scripts/conveyor/reconcile-fix-dispatch.mjs:928-936. Reuse pinned-tip acquisition and manifest `stackParents` machinery (we:scripts/lane-stack.mjs:261-278). Manifest parents are backlog identities, not PR numbers; do not synthesize a numeric parent from a PR number to satisfy the drain (we:scripts/merge-ai-prs.mjs:2097-2102). Missing trustworthy identity means queue. Recheck heads and ownership at execution; a changed head invalidates the plan. Preserve the separate PR claims already acquired at we:scripts/conveyor/reconcile-fix-dispatch.mjs:908.
4. **Restack through the existing repair lifecycle.** On each reconciliation compare durable lineage with observed predecessor heads/status. A changed predecessor schedules an idempotent child rebuild using we:scripts/lane-resume.mjs:274-311,395-412. After a proven predecessor merge, replay only the child's contribution onto current main, including squash-merge cases; never replay the predecessor patch as child work. Pin the old base and guard publication against concurrent head movement. A conflict enters guided repair; a deleted/closed-but-unmerged parent is not proof of landing. Interrupted restacks must resume from recorded state without duplicating repair sessions. Any changed child head requires fresh review/CI evidence.
5. **Separate review scope from merge authority.** Extend we:scripts/operations/review-pr-io.mjs:257-295 to read the incremental text and paths from the same immutable parent/child pair. Record that basis explicitly; incremental acceptance alone must not satisfy final merge acceptance. Keep full-stack CI on the child head. Before merge, require the normal full net diff against current main, independent review on that exact candidate, fresh green CI and all parents proven landed. Preserve the drain ordering at we:scripts/merge-ai-prs.mjs:2097-2102,2132 and its review/acceptance checks; stale or unavailable evidence holds the child.

6. **Provider-native stacks when available, never a hard dependency (operator ruling 2026-10-03).** Our stack model (lineage, depth, admission, restack, drain order) stays provider-neutral. A git-provider adapter may additionally map a stack onto the provider's native stacked-PR support where it exists. On GitHub that is the official `gh stack` extension / Stacked PRs (each PR's base = the branch below it, PRs linked as a Stack, native incremental review, cascading rebase). The adapter is optional and capability-detected; without it (another provider, the extension absent, the feature unavailable on the plan) the same stack runs on our own machinery with no loss of safety. Setting: `dispatchGate.stackProviderNative` = `auto` (default: use native when detected) | `off`. Our lanes forbid local branch switching, so the adapter must use the provider's PR/API surface for base setting and linking, not `gh stack`'s local branch and worktree commands, unless those are shown safe in a lane. Verify the GitHub feature's availability and preview status against current docs before relying on it. Tests: the adapter's capability detection, and identical admission/merge-proof outcomes with native on and off.

## MVP

Deliver one integrated repair path: ruled config defaults and overrides → safe stack admission → pinned lineage/worker handoff → automatic restack → incremental review → final full-diff gate. Demonstrate a depth-2 pair while retaining queue behavior for exceptions and unsupported topology. Keep general build admission unchanged (we:scripts/conveyor/build-dispatch-policy.mjs:270-285). Extending serial batch depth, adding new human-review policy, and broadening stacking to unidentified/itemless predecessors are outside this story.
