# Pass daemons self-sync onto adopted code like the other daemons

Enable pass-daemon self-sync by default through the existing policy cascade, preserving the shared adoption/restart safeguards, and expose a health smell when a running daemon predates its clone's latest adoption. Held finding 215 reported ten pass daemons running pre-86da0b452 code for twenty hours on 2026-10-10 and writing as the operator. That historical incident is motivation, not a live observation made during this preparation.

## Design

1. In we:skills-src/conveyor/pass-daemon.mjs, use `cascadePolicy` from we:scripts/lib/policy-cascade.mjs:176-183 for a boolean `passDaemonSelfSync` policy with standard default `true`, platform preference, optional tool value, then env override. Keep the helper injectable for tests. Introduce `WE_PASS_DAEMON_SELF_SYNC` as the canonical env name; accept boolean spellings `1/0`, `true/false`, and `on/off`. A valid canonical value wins; when canonical is unset or blank, preserve legacy `PASS_DAEMON_SELF_SYNC=1` and nonblank POC-branch opt-in as compatibility inputs before falling through to policy layers. Legacy `0` must not defeat the existing POC opt-in. An explicit canonical false disables the wrapper even with a POC branch. A nonblank invalid canonical value is passed uncoerced to the cascade's boolean validator and falls through to policy layers with its invalid diagnostic; it does not activate legacy compatibility. Pass the parsed scalar as `envValues: { '': value }` with `valid: v => typeof v === 'boolean'` (we:scripts/lib/policy-cascade.mjs:90-118). The optional tool value is an injected resolver argument, undefined in production until an existing caller supplies one; do not invent a settings file. Use its existing source log; no new platform default file is necessary.
2. Extract a small injectable wrapper-selection helper used by main and tests, then wire the resolved setting to the existing wrapper at we:skills-src/conveyor/pass-daemon.mjs:376. Preserve main-only POC refusal, guarded adoption, per-tick version roots, restart debounce/import-closure rules, independent heartbeat, and lease release. No in-flight child is interrupted to adopt code. The underlying shared wrapper remains the authority for whether a change requires restart, including documentation/config/data changes.
3. Extend we:scripts/conveyor/health-watch.mjs with a bounded, injectable process-age probe over the declared daemon inventory. Reuse inventory clone and rebuild state (already returned at we:scripts/operations/daemon-status-io.mjs:560-565), reading `rebuild.state.adopted` only when `rebuild.available` is true and `rebuild.corrupt` is false (we:scripts/operations/daemon-status-io.mjs:434-455). Take one successful bounded launchctl list snapshot per tick, join by full label, and cross-check any lease PID against that live job PID (use the live job PID for lease-free jobs), and obtain its actual start time with a bounded `ps` argv call; never substitute heartbeat or commit time. Correlate by daemon label plus canonical clone identity, not basename. Preserve unknown status for missing PID, unreadable clone/state, invalid timestamps, vanished/reused PID or failed/truncated command output. Validate PID/start identity around sampling, including clone command identity; re-read adoption state after process sampling and discard a sample if adoption changed. A successful lookup showing a stopped job is clean; a lookup failure or mismatch is unknown even if inventory says stopped. Retain raw unreadable inventory rows as unknown for this probe rather than losing identity; keep the existing lease projection and its unreadable-row filtering unchanged. Collect inventory once for the tick and reuse it for both existing leases and the proposed `daemonProcessAdoption` probe. Fixture ticks must use injected data and must never probe the host implicitly: honor the existing fixture flags in we:scripts/conveyor/health-watch.mjs:1182-1187, omitting the new probe unless explicitly injected through tick dependencies.
   Bound the new evidence collection to 15 seconds per tick, 2 seconds per subprocess, 1 MiB per subprocess output and 64 daemon subjects, with sequential IO and no retry inside a tick. On exceeded limits, leave unsampled subjects unknown and publish a scrubbed reason through existing probe-error reporting; the operator can inspect the affected job and adoption state, then retry on a later tick. Never truncate a snapshot into apparently complete evidence. A missing label is unknown; only an explicitly listed job with no PID proves stopped. Compare process start at its available timestamp precision: an adoption later within the same start-time second is unknown, not a provable breach; equality at the interval lower bound is clean because the process cannot precede it.
4. Add we:scripts/conveyor/health-smells/daemon-process-before-adoption.mjs, automatically discovered, consuming the new probe. For a confirmed live process, breach when process start is strictly earlier than a valid, non-future adopted timestamp. Use a stable daemon-label-plus-clone subject, medium severity, alert action, two breaching samples to open and two confirmed clean samples to close. Include PID, start time, clone, adopted SHA/time and age in evidence. A restarted process or confirmed stopped job clears the condition; unknown readings do not close it. Set `missingSubjectsUnknown: true`; omit unknown subjects from results and return explicit `breach: false` only for confirmed clean subjects. Declare `scope: host`, `cadence: every-tick`, and `probes: [daemonProcessAdoption]`. Leave the probe undefined on whole-probe failure so the core skips evaluation (we:scripts/conveyor/health-watch-core.mjs:922-929). Keep existing shadow-mode notification policy. The message says “process predates adoption”; it does not assert that irrelevant changes require restart or that authentication is wrong.

## MVP

- Default-on policy resolution and compatibility handling reach the real pass wrapper, with existing restart/lease cleanup intact.
- The health tick supplies correlated process/adoption evidence for declared resident daemons, including pass daemons and jobs without leases; one discovered smell reports the condition through existing episodes and reports.
- No new updater, force restart, authentication policy, rebuild mechanism, registry list, or notification-policy change. No HTTP/write endpoint is introduced, so request body caps, CSRF and endpoint rate limits are inapplicable.

## Proof plan

Use an isolated disposable daemon clone and a harmless fixture pass, with fake/injected auth and no GitHub writes. Start under a restart-capable supervisor with the setting unset, record PID, boot SHA and lease owner, and hold one fixture pass in flight while a relevant candidate is adopted using the existing mechanism. Observe that the child finishes on its pinned tree, the old daemon releases its lease and exits between passes, and the replacement acquires the lease and runs the next pass on the adopted tree. Capture the policy source log and restart log, timestamped PID/lease observations, adopted SHA, and child version-root observations as proof artifacts. Use an imported-code change and allow the existing restart debounce to expire; a docs-only adoption is a separate no-forced-restart control. Repeat with canonical off to demonstrate the override, and with rejected adoption to demonstrate last-good behavior. Feed matching before/after process observations through the health tick into a disposable state root and inspect the rendered episode, unknown-read preservation, and recovery. This is a future implementation proof, not a claim that production daemons were inspected during preparation.

## Edge cases this change must handle

1. **Untrusted text** — treat process labels, paths and state as data; use argv subprocesses, bounded output and existing report escaping/scrubbing; never shell-interpolate them.
2. **Truncated reads** — invalid process/adoption evidence is unknown, never a fabricated start time or healthy sample.
3. **Shared state files** — health is read-only over adoption/lease state; keep existing atomic report/state persistence and ownership-checked lease release.
4. **Fail closed** — keep shared smoke/adoption refusal; invalid settings follow validated cascade fallback; unavailable probes cannot establish recovery.
5. **Identity scoping** — correlate daemon label, live PID/start and canonical clone, including lease-free jobs and multiple passes sharing a clone.
6. **State over time** — sample hysteresis tolerates normal between-pass delay; preserve shared restart debounce and import relevance; age evidence does not prove stale loaded modules.
7. **Who wrote it** — leave per-spawn App environment refresh unchanged; no credentials enter health evidence and no diagnostic performs GitHub writes.
