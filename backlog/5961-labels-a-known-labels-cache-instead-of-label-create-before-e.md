# Labels: a known-labels cache instead of label create before every edit

Held finding 227 (coroner-5). 4,118 label create calls in 12 h (merge-ai-prs 3,083, review-daemon 709, fix-procedure 134, pr-land 111); 295/h after the 18:30 ET fix. Each is an idempotent ensure-exists. These are historical incident counts, not a current measurement. Fix: a per-repo known-labels cache (24 h TTL, invalidated on an exact missing-label application diagnostic); ensure on a cache miss or expiry, and invalidate/re-ensure once when label application reports that exact label missing. Evidence: the conveyor calls ledger, op label create.

## Acceptance

- [A1] **Executable** — the ensure-label unit test (`we:scripts/lib/__tests__/ensure-label.test.mjs`, run with vitest) fails before this item lands (module absent) and passes after: a second `ensureLabelCached` for the same (repo, label) within the TTL issues zero `gh` calls; a missing-label failure invalidates the entry and re-creates once.

- [N1] No change to label colors/descriptions (still single-sourced from `REVIEW_LABEL_META` / `CI_LIFECYCLE_LABEL_META`); no cross-host cache sharing; no edits to the `we:scripts/pr-land.mjs` call sites (they ride the land-provider change below); no `--force` added to the no-`--force` creates, so existing label colors/descriptions are never rewritten.

## Design

New `we:scripts/lib/ensure-label.mjs` exports `ensureLabelCached({ repo, name, create, now })`. State is one JSON file named known-labels in the user Claude home conveyor directory (JSON format; env override `WE_KNOWN_LABELS_FILE`) keyed by an unambiguous encoded (repo, name) tuple with `{ at: <epoch ms> }` values. If the entry exists and `now - at < TTL` (24 h), return without calling `create`. Otherwise call `create` (the caller-provided create operation, retaining its existing force/no-force argv), then record the entry. Use `withFileLock` + `writeJsonAtomic` from `we:scripts/lib/atomic-json-file.mjs`, with the cache hit rechecked under the lock before calling create and updating state. This serializes concurrent cold misses for the same key as well as merging different keys. The create callback stays synchronous to match all three callers. Inject cache path and clock for hermetic tests. On a cache read/lock/write failure, perform the original uncached ensure if it has not already run; never suppress a required create or run it twice merely because persistence failed. Only definitive create success or a specific existing-label response records a positive entry; preserve other create errors for the caller.

Call sites: (1) `we:scripts/merge-ai-prs.mjs:4769` and `we:scripts/merge-ai-prs.mjs:5467` replace the raw `execFileSync('gh', ['label','create', …])` with `ensureLabelCached`, replacing the process-lifetime `ensuredLabels` skip with TTL-aware cache checks, so a long-running watch also observes expiry. (2) `we:scripts/lib/review-label-provider.mjs:184` `ensureLabel` wraps its `exec` in `ensureLabelCached` (covers review-daemon and fix-procedure). (3) `we:scripts/lib/forge-land-provider.mjs:197` `ensureLabel` wraps its `exec` the same way (covers pr-land's five sites). The merge-ai-prs and land-provider creates have no `--force`, so on an existing label `gh` exits non-zero with "already exists": `ensureLabelCached` treats a failure whose `e.stderr ?? e.message` is the label-create already-exists diagnostic for the exact requested name (not an arbitrary `/already exists/i` substring) as SUCCESS and records it; any other failure records nothing and rethrows (call sites keep their existing swallow). Creation of a genuinely new label also records. `--force` stays only where it already is, so the 24 h TTL delays only the review provider's metadata update-on-force, which is accepted.

Invalidation on need: `invalidateKnownLabel(repo, name)`. The review provider keeps a per-name map of the last `ensureLabel` opts; `setLabels` (`we:scripts/lib/review-label-provider.mjs:180`) catches a failure whose `e.stderr ?? e.message` matches the concrete missing-label diagnostic and names an exact label being added, invalidates that entry, calls the (cache-wrapped, so it now creates) `ensureLabel` with the remembered opts (default `ededed`/empty when none), and retries once; any other failure (rate limit, PR not found) propagates unchanged. Apply the same one-retry contract to the land provider's `addLabel` (`we:scripts/lib/forge-land-provider.mjs:188`) and the drain's direct label application, using the metadata already available at their ensure sites. The invalidation must also remove any in-process memoized hit. Match a concrete missing-label response for an exact requested label, not a generic HTTP 422 or arbitrary “not found” substring; unrelated PR/repository/auth/rate-limit errors never retry. Capture metadata before the ensure attempt, including attempts satisfied from cache. Review may use its existing defaults when no options were supplied. Land must use remembered caller metadata; if none exists, propagate the original error without retry. Drain uses the existing metadata tables. Removal-only edits never trigger creation or recovery.

Resolve an implicit cwd repository lazily once per land adapter instance using `localRepoSlug({ cwd })` from `we:scripts/readiness/drain-lock.mjs:118` (inject the resolver in tests); the drain already resolves it at `we:scripts/merge-ai-prs.mjs:4432`, and include the resulting full repo slug in every key. If resolution fails, bypass persistent caching and retain the original uncached operation; never share a null/empty-repo key. Use nested maps or collision-safe tuple encoding for exact repo/name keys, not ambiguous concatenation. Reject malformed or future-dated timestamps as cache misses. Do not persist credentials or error bodies.

Expose one shared synchronous apply/recover wrapper in the new helper: execute an apply callback, recognize an exact requested missing label, invalidate under the same file lock, force one uncached ensure even if invalidation persistence fails, and retry the original apply callback once. Preserve return values and leave existing caller catch/log behavior outside the wrapper. Reuse it at both provider methods and all eight drain application sites listed in Progress; keep dry-run outside both cache mutation and forge operations. Match the requested label as a literal, not interpolated regex syntax. Neither generic HTTP 422 nor unrelated not-found errors qualify. Record successful creation time after the callback completes. Separate callback exceptions from persistence exceptions so a thrown create is never rerun by the cache-failure fallback. Create the parent directory before locking. Lock timeout can degrade to uncached creation; the one-create concurrency guarantee applies only when acquisition succeeds.

## Edge cases this change must handle

1. **Untrusted text** — keys encode the exact (repo, name) tuple; names come from constant tables (`REVIEW_LABEL_META`) or `review-round:<N>` (numeric N); a name starting with `--` is rejected before argv; the JSON key is only a data key, never a path, shell or regex.
2. **Truncated reads** — n/a: the cache reads only its own small JSON file; not-found detection reads the single `gh` failure text, not a paged list.
3. **Shared state files** — written by several processes: `withFileLock` + `writeJsonAtomic`, re-read and merge inside the lock; stale-lock steal is already guarded in `withFileLock`.
4. **Fail closed** — unreadable/corrupt cache means "unknown", so we create (never skip); a failed `create` records nothing; a failed cache write after a successful create is swallowed (the next process just re-creates).
5. **Identity scoping** — key includes repo slug (`null` resolved to the cwd repo slug or caching bypassed, never a bare shared key) and exact label name.
6. **State over time** — 24 h TTL bounds drift from hand-deleted labels; the not-found invalidate-and-retry covers deletion inside the TTL; a restart mid-write leaves the old or new file (atomic rename).
7. **Who wrote it** — n/a: the file grants no trust, it is only a "created recently" hint; a forged entry can at worst delay a create, and the not-found retry repairs that.
