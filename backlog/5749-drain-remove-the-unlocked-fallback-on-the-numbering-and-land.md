# Drain: remove the unlocked fallback on the numbering and land locks

Slice S6b of the async-daemons epic; held item 203. Drain numbering and landing can run unlocked after contention. Remove that fallback, wait within a bounded budget, and defer without invoking the protected callback. Renew the clone reader slot throughout asynchronously yielding `withSelfSync` ticks. This preparation changes the plan only; the runner owns stamping and checks.

## Acceptance

- [A1] **Executable** — a contended numbering/land lock waits within its budget or defers; it never runs the callback unlocked (R1).
- [A2] **Test (a)** — two landers contend: exactly one runs, the other defers.
- [A3] **Test (b)** — kill the numbering holder: the next run reclaims its lock without waiting for TTL and does not duplicate numbering already completed by that holder.
- [A4] **Test (c)** — an asynchronously yielding tick longer than the reader-slot TTL keeps its reader slot through renewal. Separately expose the synchronous-event-loop-stall limitation; timer renewal cannot cover a blocked event loop.
- [A5] **Live** — capture `deferred: numbering-lock-held`, and no unlocked callback execution over 24 h of observed drain activity.
- [A6] **Fallback end state** — lock refusal creates no local merge and changes neither local nor remote BASE; an explicit retry after release publishes the merge.
- [A7] **Idle recovery** — pending hashes on synchronized main trigger numbering on the next pass with no new lands, including after restart; resolution still requires delivery evidence.
- [A8] **No opt-in bypass** — explicit `runUnlockedOnContention: true` cannot execute either wrapper callback under contention; production true-option sites fail the standards gate.
- [A9] **Acquisition faults** — error returns and thrown acquisition exceptions defer without throwing or calling the callback; callback exceptions after acquisition still propagate and release the lock.

## Non-goals

- The whole-process drain lease (R4), splitting the shared land/numbering key, changing lease TTLs, and replacing synchronous waits with asynchronous waits.
- Redesigning corrupt-entry reclamation or making the numbering filesystem transaction crash-atomic at every individual write.
- Process-external reader renewal during an event-loop stall. The existing timer-based renewal pattern covers yielding ticks only.

## Design

**Lock interface and acquisition.** In `we:scripts/readiness/drain-lock.mjs:200`, remove the unlocked execution branch altogether. Keep accepting the old option for compatibility, but true, false, and omitted all have the same refusal behavior. `withLandWriteLock` shares this contract and the existing numbering key. Return `{ result: undefined, ran: false, held: false, contended: true, heldBy, reason }` whenever acquisition does not succeed. Preserve `lockResultOr` (`we:scripts/readiness/drain-lock.mjs:261`) as the safe accessor and update permissive comments, including the inherited POC-wrapper documentation.

Add proposed `resolveNumberingLockWaitMs(env = process.env)` in `we:scripts/readiness/drain-lock.mjs`: retain the previous plan's `WE_DRAIN_NUMBERING_LOCK_WAIT_MS` setting, default 60,000 ms, accept non-negative safe integers including zero, and use the default for absent/invalid values. Explicit `waitMs` remains the injection/override seam. Poll only while budget remains and cap each sleep to the remaining budget. This is an environment resolver in the style of `we:scripts/lib/daemon-clone-lock.mjs:109`, not a claim that a settings-cascade entry already exists.

Keep root setup, the clock/deadline, and initial/subsequent acquisition calls inside an acquisition-only error boundary. Add a narrow injectable acquire seam for error-return and later-poll exception tests. A non-contention error returns a diagnostic refusal immediately; normal held/initializing results poll until the deadline. Real filesystem failure (a regular file used as the lock root) must also defer, despite the existing best-effort root setup. Put callback execution outside this catch and retain release in `finally`: callback exceptions must propagate. Do not change the shared primitive's initialization-grace, dead-PID, or TTL policies.

**Land refusal.** At `we:scripts/merge-ai-prs.mjs:6671`, remove the enqueue-only option distinction and the unlocked-success diagnostic. Preserve the under-lock already-merged recheck. The existing refusal branch at `we:scripts/merge-ai-prs.mjs:6679` skips the candidate; make its message/report strategy-aware so inline land refusal is not described as a failed enqueue. The PR remains open and this callback performs no merge or publication. The next ordinary candidate scan supplies the durable retry trigger.

Already-merged remote hashes remain pending and unresolved, not reported as successfully numbered.

For the inline strategy, discover pending hash paths from freshly fetched main on every non-dry-run pass, independently of `landedLocal`. Before writing, require a tracked-clean tree at fetched main, with no unpublished/divergent commits; refresh and recheck under the acquired lock because the pre-lock discovery can go stale. Never autostash user edits into a numbering tree. Retain the existing detached/stale-lane safety checks in `we:scripts/merge-ai-prs.mjs:4137`. Failed/unsafe sync leaves hashes on remote main for another pass and creates no numbering commit.

Select one numbering owner per pass. A successful follow-up handoff suppresses inline numbering **and** idle queue repair. Otherwise the queue strategy keeps its existing idle `repairHashOnMain` path; record that the repair was attempted and do not fall through into a second numbering path even if it refused.
