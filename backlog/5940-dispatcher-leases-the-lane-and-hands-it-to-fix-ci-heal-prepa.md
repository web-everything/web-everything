# Dispatcher leases the lane and hands it to fix/ci-heal/prepare workers; review jobs never lease a PR own lane

Reserve the actual worker checkout before launching a fresh fix, CI-heal, scope-prepare, or prepare-item worker, and hand that lease to the worker without a second allocation. Read-only reviews must use a free checkout other than the PR's own lane. Historical motivation: held finding 224 (coroner-5) reported 52 lane-already-leased events across 61 of 254 sessions during October 9–10, including jobs cf57089e, 872b486d, ad057938, 095515ac, 5506fbff and CI-heal session 001f51be. Those counts are incident evidence supplied with this card, not re-measured during preparation. Related #5439 supplies the build-reservation precedent.

## Design

1. Extend the reservation boundary in `we:scripts/operations/dispatch-lane-io.mjs:1374` to fresh fix, ci-heal, prepare and prepare-item launches; preserve the existing build switch and behavior. The `WE_DISPATCH_RESERVE_LANE` switch keeps gating build only; fresh fix, ci-heal, prepare and prepare-item reservation does not depend on it, and a payload missing its lane or session refuses instead of skipping reservation. Reserve after admission/claim checks but before any worker process starts. Share this mechanism with the separate fix launcher in `we:scripts/conveyor/reconcile-fix-dispatch.mjs:1367`. A free-list result is only a candidate: actual acquire must win before spawn. A busy candidate produces a bounded, retryable no-lane refusal, never a worker started to discover contention.
2. Carry a structured handoff containing repository/pool identity, canonical lane number/path, lease session, generation identity (`acquiredAt` plus `holder`), expected base ref and acquired HEAD SHA. Reuse the existing identity tuple compared by `sameLease` at `we:scripts/lane-pool.mjs:3709`; there is no existing numeric generation field. Return this data from the successful acquire, rather than reconstructing it from a later unguarded read. The current JSON result at `we:scripts/lane-pool.mjs:2467` includes lane/path/session/holder but omits acquiredAt, pool identity and HEAD; extend that result under the acquisition protection. Use a version-1 handoff with required repository identity, canonical pool root, lane number/path, session, acquiredAt, holder, base ref, HEAD SHA and scope array (including an explicit empty array). Treat the handoff as a closed versioned contract: reject unknown versions, missing fields, invalid lane/path pairs and mismatched scope; compare canonical filesystem identities so symlink aliases cannot create a second pool identity. Validate it against the caller’s independently resolved target repository/pool and requested scope, not just against values supplied inside the handoff. Repair reservation uses the PR head ref; prepare uses its existing base and card-only scope; prepare-item uses fresh fetched `origin/main` and card-only scope, as required at `we:scripts/lane-pool.mjs:1983` and `we:skills-src/conveyor/prepare-item-agent-brief.md:106`. Dispatch reservation means an ordinary lease, never the pool's permanent `--reserve` mode. A repair launcher must compare the reserved HEAD with the PR head it reads before work; a changed head defers without resetting the adopted lane or taking another. Thread the repair base through `we:scripts/operations/ci-heal-pr-dispatch.mjs:293` into the sink. Preserve current scope derivation, including the existing empty-scope CI-heal behavior and grouped prepare-item dispatch. The latter already derives the lead-plus-members card-only scope at `we:scripts/operations/dispatch-lane.mjs:1100-1112` and forwards group members at `we:scripts/operations/dispatch-providers/probation-worker.mjs:148`; carry that exact array through reservation, provider and adoption. A singleton remains one card. Do not substitute the cards’ implementation scopes, collapse a group to its lead card, or broaden authorizations. Source, documentation, configuration and data paths receive the same lease protection.
3. Extend adoption in `we:scripts/lane-pool.mjs:4325` with expected lease identity validation and a race-safe check/update coordinated with release/reclaim. Existing adoption checks lease staleness and the recorded occupant, not process liveness or the expected dispatch lease. Handoff adoption must reject stale, replaced, wrong-repository or wrong-session leases; never force a takeover. Preserve the original holder and release identity. Coordinate marker writes and removals with a per-lane mutation lock inside `we:scripts/lane-pool.mjs`, covering acquire/self-refresh, adoption, release, reap, reclaim, salvage and trim; the move-aside helper at `we:scripts/lane-pool.mjs:3716` is not an existing lock around adoption. Keep the valid lease marker present during adoption, re-read and compare under the lock, and replace it atomically; a failed comparison must leave the replacement lease untouched. Bound lock acquisition and refuse on uncertain lock ownership. The worker declares its own durable occupant, not the dispatcher's session. Re-adoption of the same handoff is idempotent and must not reset checkout contents.
4. Update the four active brief templates in scope (fix, CI-heal, prepare-scope and prepare-item) to consume a supplied handoff and adopt before edits. Retain explicit standalone acquisition when no handoff was supplied; a malformed supplied handoff must not fall back to acquiring another lane. Update the briefing contract in `we:scripts/operations/dispatch-lane.mjs` and test real template expansion. The Codex fix and routed Codex CI-heal paths must forward the handoff through `we:scripts/operations/dispatch-providers/fix.mjs` to `we:scripts/operations/fix-run.mjs:612`. The probation provider maps `prepare-item` to `we:scripts/operations/probation-build-run.mjs:368` and `ci-heal` to the live `we:scripts/operations/probation-heal-run.mjs:328`; both must accept the handoff and use the same acquired lane before starting the sandbox worker. The latter is distinct from the absent legacy mechanical CI-heal runtime. Keep launchers responsible for lease operations where sandbox workers cannot perform them. The routed Codex CI-heal adapter at `we:scripts/lib/fix-slot-borrow.mjs:112-126` already spreads the sink request into the fix provider; verify handoff forwarding through that adapter without changing its routing policy. The probation prepare runner currently acquires with `--base=main` and a probation purpose at `we:scripts/operations/probation-build-run.mjs:1013-1017`; use the prepare-item purpose and fetched `origin/main` contract for prepare handoffs, while retaining the existing standalone non-prepare build behavior. Preserve the existing light-revalidation branch and its full-prepare fallback at `we:scripts/operations/probation-build-run.mjs:485-531`: both run inside the adopted checkout, including the second preparation attempt, with no refresh or second acquisition. Likewise, the repeated-finding route at `we:scripts/conveyor/reconcile-fix-dispatch.mjs:1461-1468` and scope reset at `we:scripts/operations/fix-run.mjs:777-790` must validate/adopt before any checkout reset; preserve their current routing and reset policy. Pass a versioned, validated handoff as one JSON argv value to launchers and as a shell-quoted argument in agent briefs. Validate before any edits or reset. The shared sink currently receives an already-filled prompt: render a fixed handoff preamble only after reservation with a shared helper in `we:scripts/operations/dispatch-lane.mjs`, using validated JSON and one shell-quoted argument. Both dispatchers prepend that preamble to the already-filled brief; the four templates explicitly consume its supplied handoff before their standalone-acquire branch. Never re-expand arbitrary filled PR prose or leave a placeholder in a launched prompt. Keep the handoff as structured request data for providers as well as rendered instructions for agent consumers. Cover both existing Claude execution modes: the separate fix dispatcher branches to a detached wrapper at `we:scripts/conveyor/reconcile-fix-dispatch.mjs:1603-1619`, and the shared Claude provider wraps fix/CI-heal at `we:scripts/operations/dispatch-lane-io.mjs:1981-1998`. Build the handoff-bearing prompt before these branches so their existing argv conversion preserves it. The wrapper helper is a transport dependency, not another lane allocator; no change to `we:scripts/operations/worker-wrapper-launch.mjs` is planned. Preserve its current default-on roles and opt-out. Tests must explicitly select both modes: `we:scripts/operations/worker-wrapper-launch.mjs:39-53` disables the default under tests, so an unconfigured unit run would miss the production wrapper branch.
5. Release only the exact reservation on a provably pre-launch failure. Cover every operation after acquire, including the new post-reservation prompt expansion and scratch-cwd creation (the latter currently sits outside the provider catch at `we:scripts/operations/dispatch-lane-io.mjs:1556-1585`). Conditional release validates the full expected tuple under the same mutation coordination as adoption, release and reclaim, not just the reusable session slug. Once launch may have happened, retain the lease and report any observed handle, or the explicit unknown/in-flight state with reservation identity, for existing reconciliation; never free a potentially occupied lane. After adoption, retain each route’s existing terminal cleanup policy: `we:scripts/operations/fix-run.mjs:882-885` releases on launcher completion; `we:scripts/operations/probation-build-run.mjs:62-65`, `we:scripts/operations/probation-heal-run.mjs:27`, and all four agent briefs retain lanes for downstream drain/reaper cleanup. A started probation launcher refusing its handoff does not authorize dispatcher-side release. Provider fallback after a definite pre-launch refusal must reuse the same reservation; release only after the whole launch attempt is definitively refused, and never retry after an uncertain launch. A resume uses its already owned checkout and allocates no new lane. Keep PR dispatch claims distinct from checkout leases.
6. Remove the preferred-lane-first behavior in `we:scripts/operations/review-job.mjs:768`. Resolve the PR's own lane identity from existing PR/lane metadata and exclude it from auto-selection, rather than merely dropping the preference (auto-pick could select that same lane). Add an exclusion option to the pool's acquire selection and apply it on every retry/growth selection. Scope the exclusion to its repository/pool. If an own-lane identity is supplied but invalid or its lookup fails, defer rather than silently ignore it. If the PR has no local mapped checkout, ordinary auto-pick is valid. Preserve job-slot and bounded-wait protections. Resolve ownership immediately before the acquire branch, after the existing eligible verdict-carry shortcut at `we:scripts/operations/review-job.mjs:730-753`; a carried review must continue to acquire zero lanes and must not require a new ownership lookup. `preferLane` is a free candidate assigned by the daemon (`we:skills-src/conveyor/review-daemon.mjs:492`, `we:skills-src/conveyor/review-daemon.mjs:553`), not the PR-own lane identity: never reinterpret that value as ownership. Add an injected own-lane lookup in the review IO boundary, backed by PR attribution and repository-scoped local lane/session metadata; distinguish a successful no-mapping result from an unreadable or ambiguous result. Resolve the PR head ref and item attribution, then join the item-to-lane entries written at `we:scripts/lane-pool.mjs:607-614` and local author/repair lease metadata within the resolved pool. Reuse the parsers at `we:scripts/conveyor/lease-reaper.mjs:219-228` and `we:scripts/conveyor/lease-reaper.mjs:299`; a branch’s item number is not a lane number, and review/inspect sessions are not author-lane evidence. Return an explicit mapped / unmapped / error result. Read mapping evidence strictly in the review IO boundary: the existing registry reader at `we:scripts/lane-pool.mjs:568-576` collapses malformed data to an empty map and cannot establish “unmapped”. No metadata-parser source change is needed; add lookup and its injected readers in the already-scoped review module. Keep the existing caller argument accepted but do not acquire it preferentially. Permanent own-lane exclusions must survive the retry loop's `excluded.clear()` calls at `we:scripts/lane-pool.mjs:2307` and `we:scripts/lane-pool.mjs:2332`.

7. Harden the authoritative ownership reads before any acquire/adopt mutation. `readLease` at `we:scripts/lane-pool.mjs:762-774` currently accepts incomplete objects and collapses corrupt/unreadable records into no lease. Distinguish absence from invalid evidence and refuse the latter before the acquire reaper or reset can act. A cached free list is only a hint; a candidate still needs complete authoritative lease evidence and an atomic claim. Inject truncated cache/state data in tests and require refusal for that dispatch attempt, without globally redefining unrelated status/reporting behavior. Concretely, the free-list read at `we:scripts/lane-pool.mjs:2193-2198` and scan-cache read at `we:scripts/lane-pool.mjs:3197-3205` currently rebuild on malformed input. In the handoff acquisition path, classify those reads before the acquire-time reaper or any marker mutation: absent cache → normal authoritative selection; complete stale cache → discard and rescan; present but malformed/incomplete/unreadable cache → refuse this attempt. Use strict reads in the pool module and the existing cache parser rather than adding an unscoped cache-library change. Validate the raw free-list envelope and every raw row before normalization: `we:scripts/lib/free-lane-list.mjs:69-89` drops malformed rows and substitutes nulls, so successful parsing alone is not proof that the original input was complete. Keep absent, invalid and complete-but-stale results distinct; reject any reader result explicitly marked incomplete before selection or reaping. An explicit candidate still requires authoritative lease validation; do not make a cache sufficient proof of ownership. A syntactically valid payload missing fields is detectable; a bounded reader must also report incompleteness explicitly, since well-formed complete-looking JSON alone cannot reveal omitted records.

## MVP

**Must:** Deliver one lease lifecycle across the active fresh Claude fix/CI-heal/prepare/prepare-item routes (both direct and detached-wrapper execution for fix/CI-heal), the Codex fix and routed Codex CI-heal routes, and probation prepare-item/CI-heal routes (including the already-supported grouped prepare-item request): admission → acquire → launch → adopt/use → existing terminal cleanup (release or retained lease for drain/reaper). Include the review exclusion and failure cleanup in the same change. Do not ship a path that reserves one checkout and subsequently allocates another. A prepare group uses one checkout and one lease covering all its requested card bodies, with the existing per-member refusal/restoration behavior intact. Keep the unavailable legacy mechanical prepare/CI-heal runtimes unavailable; their restoration is separate work, not a prerequisite. The existing build reservation is a regression case, not a new rollout decision. The existing light-revalidation/full-prepare fallback and repeated-finding mechanical reset consume the same lease as their ordinary route; they are existing consumers, not new modes. Deliver pool identity/exclusion first, then both dispatch boundaries, all active consumers and briefs, and finally route/proof coverage in one coordinated change so no intermediate route reserves one lane and acquires another. **Could / follow-up:** restore legacy runtimes only under their own graduation work and measure incident-rate changes after comparable live observation.

## Edge cases this change must handle

1. **Untrusted text** — pass refs/scopes/identities as validated argv data; no shell interpolation of PR or card prose.
2. **Truncated reads** — incomplete pool/lease/handoff data refuses dispatch; never guess a free lane. Enforced by [A6] and the four named `truncated` tests in the Test plan.
3. **Shared state files** — acquire, adopt and conditional release must coordinate against competing release/reclaim; no read-then-overwrite of a replacement lease.
4. **Fail closed** — invalid handoff or ambiguous launch cannot trigger takeover or premature release.

6. **State over time** — retries, process death, delayed adoption and resumes preserve ownership and existing reconciliation behavior.
7. **Who wrote it** — distinguish dispatcher lease holder from worker occupant and retain that lineage in observable lease/journal records.
