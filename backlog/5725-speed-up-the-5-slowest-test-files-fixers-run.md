# Speed up the 5 slowest test files fixers run

The 2026-10-10 fixer work-time study reported 184 fix/ci-heal sessions since 2026-10-09, with local tests consuming 28% of active time. Its five historical targets were `we:scripts/conveyor/__tests__/health-watch-jobs.test.mjs` (108 s/call, 28.7 min total), `we:scripts/conveyor/__tests__/session-reaper-cli.test.mjs` (117 s/call, 19.5 min), `we:scripts/operations/__tests__/review-loop-cli.test.mjs` (141 s/call, 16.4 min), `we:scripts/lib/__tests__/review-loop-policy.test.mjs` (85 s/call, 18.4 min), and `we:scripts/conveyor/__tests__/pr-stack.test.mjs` (44 s/call across 35 calls, 25.5 min).

Keep those five targets and reduce their measured invocation time without losing regression coverage. The historical numbers are motivation, not current isolated baselines or proof that all five spend their time waiting on subprocesses. All five now exist in this checkout. Profile execution and collection separately, remove incidental host reads through existing seams, and retain real boundary checks where they are the assertion's subject.

## Acceptance

- [A1] **Executable** — matched before/after isolated runs through `npm run test:unit -- <repo-relative-test-file>` show a repeatable wall-time reduction for each original target, with its original cases still passing. Report child runtime separately from heavy-queue wait. Compare at the same worker count, Node version, fixture data and cache conditions on a quiet host; do not compare against the historical session averages.
- [A2] No test is skipped or deleted to obtain the speed-up. Every original case and behavioral assertion survives; added checks may increase the count. If cases move, record their old-to-new mapping and measure the complete replacement group, including every file's startup cost.
- [A3] Preserve real CLI/default-wiring, filesystem safety, failure and state-transition coverage. Demonstrate one relevant red-to-green regression probe per changed original suite; source extraction additionally preserves export identity and behavior.

## Non-goals

- [N1] No changes to verify selection, heavy-admission behavior, worker limits, suite exclusions, production retry delays, retention policy, review decisions, or stack policy.
- [N2] No blanket filesystem/process mocks, timeout increases, or arbitrary splitting to make one file's timing look smaller. Splitting is deferred unless the measured total cost falls without changing selection.

Alternate comparable before/after batches to expose host-load drift. Measure the admitted child interval, recording queue wait separately. If noise overlaps the claimed gain, collect more matched evidence; a single fast run is insufficient.
2. Record both invocation wall time and summed assertion durations. 3. For each optimized seam, show observed call counts or a focused profile before/after: health status/process children, review backlog reads, stack settings/Git/claim calls, policy import collection, and reaper child launches/sleep requests. A code inspection alone is not a performance diagnosis.
4. Run a temporary behavioral mutation per original suite: duplicate health job/incorrect consumption; accept after failed prevention filing; ignore a stack trust or hold condition; auto-confirm a human review; omit reaper `--all` or mis-map an enable/disable flag. The relevant retained tests must fail, then pass after restoring the mutation. Use the heavy queue for every red and green run; never commit the mutations.
5. Publish original-to-final case mapping, counts, targeted source coverage and retained real-boundary probes alongside the timing table. ## Edge cases this change must handle

1. **Untrusted text** — retain sidecar validation and review finding/publication-guard cases; fixture speed-ups must not mock their validators.
2. **Truncated reads** — retain existing oversized/non-regular-file rejection and output/JSON assertions; no new truncation policy.
3. **Shared state files** — every writable fixture remains per-test, with explicit cleanup; ordinary unit cases never enumerate the live backlog or claim store.
4. **Fail closed** — retain failure/unknown distinctions and demonstrate the red-to-green behavioral probes above.
5. **Identity scoping** — preserve session handles, PR head/fingerprint identity, actor ownership and branch-name checks.
6. **State over time** — preserve retries, cadence, receipt expiry and hold aging using injected clocks/sleep where appropriate; restore timers and memo state.
7. **Who wrote it** — preserve existing human/agent confirmation and stack actor checks; no policy changes.
