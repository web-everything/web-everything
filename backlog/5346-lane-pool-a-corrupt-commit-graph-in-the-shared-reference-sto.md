Shared primary store commit-graph names objects gc pruned; every lane git op fails and ci-heal 4368 blocks. Regenerate only that derived cache under the pool lock, log, retry.

## Edge cases this change must handle

One line per class: either the handling, or `n/a: <why>`.

1. **Untrusted text** — n/a: no external text is interpreted; git error text is only pattern-matched.
2. **Truncated reads** — verify output is capped to two lines; a failed regeneration leaves the store graph-less, which git treats as valid.
3. **Shared state files** — the primary's commit-graph is the shared file: moved aside (kept), regenerated by git's atomic temp+rename, under a mkdir lock with dead-owner reclaim; re-verified under the lock.
4. **Fail closed** — lock not obtained or heal throws means log and rethrow the original fetch error; nothing else is changed.
5. **Identity scoping** — the lock lives in the repo's own pool dir, so repos do not block each other.
6. **State over time** — idempotent: a clean graph is never touched; old `.corrupt-*` copies are inert.
7. **Who wrote it** — n/a: derived cache, no authored content.
