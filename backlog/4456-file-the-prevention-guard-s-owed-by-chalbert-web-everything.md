## Design

Add a pure retired-field validator in we:scripts/check-standards-rules.mjs accepting parsed raw frontmatter. Detect own-key presence of `workItem`, regardless of value or accompanying `kind`. Emit an error with the card path, field, and a stable `backlog-retired-field` descriptor; explain that the author must retain or supply canonical `kind` and remove `workItem`. Do not infer a new classification from conflicting fields.

Wire it into the existing raw-frontmatter loop in we:scripts/check-standards.mjs before any scope-related early return. Apply to all successfully parsed cards, including resolved cards and cards without scope, consistent with that loop's existing full-collection behavior even under local mode. Keep existing required-kind/enum checks and parse-error reporting. Malformed YAML must still fail the gate rather than being treated as evidence of valid schema; unreadable files must not silently become a clean retired-field result. Today that loop's single `catch { continue; }` at we:scripts/check-standards.mjs:1061 swallows read errors (EISDIR, ENOENT from a dangling link, EACCES) as well as YAML parse errors, so under local mode an unselected unreadable card is read by nothing else and passes clean. The retired-field message likewise carries its `backlog-retired-field` token in the message text. The raw loop is not the only reader, so a per-loop catch is not enough. In full mode the unquoted-colon/parse scan at we:scripts/check-standards.mjs:1000 reads first with no guard and crashes the whole gate with a path-less "EISDIR: illegal operation on a directory, read". Later readers fail the same way: the cached scans at we:scripts/check-standards.mjs:1474, :1517 and :1559 rethrow through the scan cache, and the caught scans at :1741, :1799 and :1956 add errors that do not name the card. Fix it once, upstream: before any backlog reader runs, probe every card in the backlog folder once (every mode, the whole collection). Each card that cannot be read as a file emits one `backlog-unreadable-card` error naming the card path, and the descriptor token is also written into the message text, because text output prints only the message. Every backlog reader in we:scripts/check-standards.mjs, including the raw loop, `scopedReaddir` and the scan helpers above, then takes its list from that filtered listing. No reader adds its own catch-and-continue for read errors. In the raw loop, the existing catch keeps only the YAML parse-failure `continue`, because the parse scan already reports that. (gray-matter caches by input text, so a second parse of malformed text can return empty data instead of throwing; the parse scan's error still fails the gate either way.) If a reader cannot be routed through the filtered listing without touching a file outside the declared scope, report it for scope adjustment rather than widening scope silently. Mode outcome, stated so tests pin the real contract: in full mode the finding blocks (nonzero exit); under `--local` with the card outside the selected files, `partitionLocal` (we:scripts/readiness/claimScope.mjs:265) demotes it to a printed note and the merge gate's full run enforces it. The guarantee is pinned by A5.

The changed default is that previously tolerated `workItem` now fails standards validation. Remove only that field from we:backlog/1683-implement-the-js-first-token-runtime-webinjectors-resolves-t.md. Preserve its canonical classification and all other content. No new runtime settings, parser, epic sizing rule, or broad obsolete-field policy is introduced.
