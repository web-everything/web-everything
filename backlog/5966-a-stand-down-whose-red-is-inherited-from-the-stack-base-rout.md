## Design

### Record evidence where the diagnosis is made

Use the existing child escalation and base-note markers as the durable incident record; add versioned structured fields without a new store. Separate delivery acknowledgement from repair progress: delivered means a matching trusted base note was read back, repair means the ordinary base fixer owns the work, refresh owed means the base moved, and recovered means refreshed child ancestry plus fresh successful required checks were observed. Neither successful posting nor a changed base SHA closes the incident. Retain the original diagnosed pair alongside refreshed tips so a restart can find the obligation even after the old escalation becomes stale.

Extend the existing inherited escalation in `we:scripts/conveyor/ci-heal-escalation-mark.mjs` and its producer instructions in `we:skills-src/conveyor/fix-agent-ci-brief.md`. Record a versioned payload with repository, child PR and full examined head SHA, base PR and full examined head SHA, failed required-check identity, implicated repository-prefixed paths, and base reproduction evidence. The evidence must identify the test/gate, scan inputs, failure signature and immutable log or artifact that demonstrates the same failure on the recorded base tree. Include the child net-diff basis and, for reclassifying an earlier stand-down, its exact comment identity. Treat the worker's attribution as a candidate to verify, not authorization by itself.

Preserve legacy marker parsing and waiting behavior. An old prose-only note must not authorize a new base repair. Tighten the brief's existing “reproduces or untouched” wording for this automatic route: an untouched filename alone does not establish causality. Source, documentation, config and data paths receive the same checks. Never execute a command taken from a PR comment; reproductions use the named repository gate/test through the existing worker and heavy queue.

### Deliver and validate the base request

Add inherited-incident reconciliation to the existing sweep in `we:scripts/conveyor/ci-red-recovery-watch.mjs`, including its injectable CLI orchestration and JSON/text results. Discover candidates from durable child escalations independently of missing-run candidates. Use the existing complete-comment reader at `we:scripts/conveyor/ci-red-recovery-watch.mjs:694`; resolve a unique same-repository open parent and reread both heads and the child base relationship before a write. A capped/incomplete PR listing requires a complete targeted parent read or deferral; a branch-name first match is insufficient.

Post the structured base request under the existing inherited-note marker. Key it by repository, child PR/head, base PR/head and failure identity. A matching trusted note read back from the complete base thread acknowledges delivery, including after a post succeeded but its response was lost. If delivery fails or is ambiguous, preserve the child escalation and reconcile again; do not mark it delivered from an attempted write. Implement one injectable delivery wrapper in `we:scripts/conveyor/ci-heal-escalation-mark.mjs`, shared by the CLI and watch. Reserve the incident key under a host-shared lock root using `we:scripts/readiness/file-locks.mjs`; use a process-unique owner and owner-checked release in a finally path. Under the reservation, reread complete comments and current identities, then post only if no matching trusted request exists. A busy or lost reservation defers; a post exception remains ambiguous until read-back. The transport alone does not provide this transaction. Keep the CLI's immediate base post on the same validation, payload and key as watch retries, including explicit `--base-pr` inputs, so it cannot bypass parent/identity checks. Never infer authorization from a forged (non-trusted) author, from quoted markers, or from a statement in an arbitrary PR body.

In `we:scripts/conveyor/reconcile-pass.mjs`, enrich current child/base snapshots with verified request facts before calling the pure planner. Verify the leading marker and trusted author, full identities, complete comments and net diff, current parent relationship, and the referenced reproduction artifact's head and failure signature. Reject syntactically valid but semantically wrong attribution, including an implicated path changed by the child. Missing evidence, truncated reads, forks, multiple possible parents or moved heads are deferrals, never permission to dispatch. Reuse the existing complete-read helpers without changing their contracts.

### Route the repair through the existing fixer

In `we:scripts/conveyor/reconcile-core.mjs`, route a verified base request as `kind: fix` on the base PR through the existing scope, owner/claim and ordinary fix-round gates. A verified local failure may produce this fix even when the base's hosted checks are green; do not falsify the CI rollup or impersonate an operator send-back. Preserve the normal budgets, and coalesce requests for the same base head into one fix. An active claim, exhausted cap, unrelated stand-down or human-required disposition still refuses it.

Thread the incident through both the entry-to-planned mapping and `withPlannedContext` in `we:scripts/conveyor/reconcile-fix-dispatch.mjs`. The launched or resumed base fix must receive the exact reproducer, attributed paths, both head identities and waiting child identities. Resolve the base's own authorized scope; the request grants no scope expansion. Recheck current identities at dispatch so a once-valid plan cannot start against a different base head.

Keep the child waiting on the named base. The stand-down guard currently runs before the inherited escalation branch (`we:scripts/conveyor/reconcile-core.mjs:2290`); account for that ordering explicitly. Only an exact, trusted machine stand-down identified by the verified incident, with no additional unresolved question, can be classified as inherited waiting. Preserve the original comment and all unrelated holds; never broadly clear stand-downs by searching prose for a base name.

### Refresh the child before healing it again

A moved base invalidates old repair authorization, but retains the obligation to refresh the child. The watcher must inspect the recorded incident before discarding its stale-head verdict. After validating the new tips and waiting for claims to release, reuse `restackStackedPr` in `we:scripts/conveyor/ci-red-recovery-watch.mjs`. It refreshes the chain root-first; honor claims and same-repository checks on every link, its existing depth bound, conflict refusals and fast-forward push safety. Record the resulting tips and attempt outcome durably under the incident, reusing existing recovery caps without granting extra attempts.

While that refresh is owed, the live enrichment and planner suppress child healing. After refresh, observe fresh checks on the resulting child head. Passing checks close the incident; still-red checks require a new diagnosis against the new base/head pair. Base movement alone never means fixed. On a restart after a push but before its receipt, use fresh ancestry and tip observations to reconcile the completed refresh rather than pushing again. The existing missing-run helper treats an all-current stack as failure; for this incident, already-proven refreshed ancestry means await current checks, not “needs a human look.”

## MVP

Must ship together:

- A newly diagnosed inherited failure carries complete head-bound reproduction evidence from the worker brief through the durable child escalation and retried base note.
- One eligible base fix receives that evidence under existing scope, claims and budgets; the child remains waiting. Incomplete attribution and genuine human questions retain their existing holds.
- Base movement triggers guarded refresh before child healing. Fresh child checks determine recovery, with restart reconciliation and bounded attempts.
- A reproducible lint parity fixture demonstrates full-tree/scoped behavior, with the historical cause reported only if the original tree and run inputs can be recovered.

Could follow separately: historical prose-only incident migration, cross-repository stacks and additional operational metrics. None is required to route and refresh a newly recorded, fully evidenced same-repository incident.
