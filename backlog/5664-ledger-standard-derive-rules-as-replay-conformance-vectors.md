# Ledger standard: derive rules as replay conformance vectors

Publish language-neutral replay vectors in we:conformance-vectors/verdict-ledger-derive.vectors.json and a thin we:conformance-vectors/verdict-ledger-derive.vectors.ts wrapper (both proposed). Inputs include events, scoped PR facts, settings and fixed now; expected output includes lifecycleState, clears, hold codes and next. Derive merge readiness from the existing READY-TO-MERGE state, not a fabricated canMerge export or clears alone. Seed from the current carry-forward and same-head replays; preserve behavior.

Run each criterion after adding its named regression cases (red before, green after). Queue helper, from the repo root:

## Non-goals

- [N1] No new hold/merge policy, label rendering redesign, store changes, or serialization of JavaScript getters/Proxy attack fixtures; keep those in the existing JS suite.

## Edge cases this change must handle

1. **Untrusted text** — Include JSON-valid but semantically wrong events (forged clears and invalid payload); never accept claimed clearance as authority.
2. **Truncated reads** — Represent unreadable events as null distinctly from an empty array; partial/malformed rows must hold as the current derive does.
3. **Shared state files** — n/a: a pure replay runner reads checked-in fixtures and writes no shared ledger or queue.
4. **Fail closed** — Unknown scope/head and corrupt rows hold; custom settings cannot replace built-in deny rules.
5. **Identity scoping** — Fixtures carry explicit repo/PR/head and finding keys; foreign events do not close local referrals.
6. **State over time** — Pin now and ordered timestamps; exercise carry-forward across heads, same-head block persistence, expiry and send-back release by SHA rather than clock.
7. **Who wrote it** — Keep source and actor data as event inputs, not authentication proofs. No receive/write endpoint: HTTP size/rate/origin/CSRF controls or state-reset protection are n/a.
