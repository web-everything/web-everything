# Per-item task core: exclusion, timeout, outcomes, effect declarations and a recording accessor

Slice S2a of the async-daemons epic. Add we:scripts/lib/daemon-item-tasks.mjs on the existing detached-job core, preserving the model in we:docs/agent/platform-decisions.md#daemon-jobs. The missing work is per-item exclusion across sequence numbers, bounded task execution, semantic outcomes, declared/probed effects, recorded fact reads and a result sidecar. This is a reusable core plus an isolated process proof; no production daemon adopts it here.

Task inputs are `{daemon, repo, item, snapshotPath, snapshotAt, schedulerGeneration}`; generation is diagnostic, never a cancellation fence. A kind uses `defineJobKind`: planning is `readonly-tree`, rebase/push is `mutates-tree` with an explicit worktree provider. The logical task identity is `<kind>:<repo>:<item>:<seq>`; its filesystem-safe run ID is derived separately because the existing run store rejects colons and slashes. Exclusion comes from a locked lookup of non-terminal records on `(kind, repo, item)`, not ID equality.

Execution is read -> plan -> claim -> (per effect: probe -> fence -> act -> mark). Persist intent before act. Each effect declares its inputs, authoritative applied-probe and server-side precondition (explicitly none where unavailable). Local worker dispatch probes the owning run store by `effectId = taskId:effectName`; it never substitutes a GitHub reread. Each effect's live fence rechecks its declared inputs before acting. A mismatch ends `superseded`. The core supplies recording/claim/effect ports; W1 (#5757) supplies the production worker hand-off and claim lifecycle.

Task `timeoutMs` defaults to 300000 through `cascadePolicy`; enforcement belongs to `reattachTick` (we:scripts/lib/daemon-jobs-runtime.mjs:325), using `stopHandle` (we:scripts/lib/daemon-jobs-runtime.mjs:279) and positive confirmation of death. Scheduling composes `admitJobs` with the shared `admit({kind})` service; acting concurrency defaults to one per repo (O14). Outcomes are `acted | nothing-owed | superseded | deferred-claim-held | deferred-read | failed`; only `failed` consumes the semantic task failure budget. Existing launch-attempt identity remains separate. Publish `{v:1, outcome, effects[], recordedReads[], timings, gh}` atomically and emit one `task-timing` line per completed attempt.

## Effects: declared inputs, applied-probe, server-side precondition

| Effect | Fence re-reads live | Already-applied probe | Server-side precondition |
|---|---|---|---|
| Fix / ci-heal worker dispatch | head sha, base sha, open, draft, `review:*` and hold labels, required checks, latest review id, claim | run store: worker run with this `effectId` in launching/running/done | none (the claim covers it) |
| Promote draft (`gh pr ready`) | head sha, draft, every required check green on that head, withdrawal mark | live `isDraft == false` | none |
| Label write | open, the label set the decision relied on | live label present/absent | none (idempotent) |
| Comment | open, the marker comment id | marker comment with the `effectId` exists | marker dedupe |
| Rebase / push (mutates-tree) | head sha, base sha | remote head equals the planned result sha | `--force-with-lease=<ref>:<expected-head-sha>` |
| Drain merge (S6a) | live fix or ci-heal claim | already merged | `--match-head-commit` |

Residual window, stated plainly: fence-then-act is a check followed by an action, not an atomic guard, except where a server-side precondition is named. Other daemons are kept out by the per-PR claim; humans and CI changes are today's risk; the next tick reconciles.

## Edge cases this change must handle

One line per class: either the handling, or `n/a: <why>`.

1. **Untrusted text** — Logical identities contain validated kind, canonical repo slug, positive item and sequence numbers; storage IDs and lock keys use a bounded digest of those structured values; PR titles and bodies never reach an id or path.
2. **Truncated reads** — A missing snapshot, one older than `snapshotMaxAgeMs`, or an unreadable sidecar ends the task `deferred-read`; nothing acts on a partial read.
3. **Shared state files** — Enqueue runs under the per-item file lock; records are written atomically (tmp + rename) under ~/.claude/daemon-jobs/<daemon>/ (R2).
4. **Fail closed** — A fence mismatch ends `superseded`; an authoritative effect-probe error ends `failed` without attempting that effect or any later one. Already-applied effects remain recorded. Unreadable fact inputs end `deferred-read`.
5. **Identity scoping** — The exclusion key is `(kind, repo, item)`, so the same PR number in two repos never collides; the handle is host:pid:procStart so pid reuse does not match.
6. **State over time** — Timeout escalates SIGTERM -> SIGCONT -> SIGKILL with confirm-gone; tasks from an older process or generation are adopted on reattach, not fenced.
7. **Who wrote it** — Only the role holding a run record resumes it (R14); records carry the launching handle.

## Design

1. **Declarations and records.** Extend kind definitions and the optional task metadata on the job block with validated timeout, acting/repo admission metadata, logical identity, failure count and result reference. Old job records without task metadata retain their existing behavior. Persist resolved task policy with its source layers at enqueue so restart adopts the same deadline/budget. A finite positive timeout is mandatory for item tasks, default 300000 ms; snapshot age and per-effect GitHub budgets are explicit caller policy passed through the cascade, not guessed from absent fields. Keep generic launch attempts monotonic and use task failures for item-task retry exhaustion. Classifying a crash, launch failure or timeout charges that launch once under the record lock; a recorded non-failure outcome does not charge it.
2. **Enqueue exclusion.** Add a task enqueue wrapper using the existing atomic file-lock primitive. Under a short lock keyed by the canonical `(kind, repo, item)` tuple, reread the owning daemon's job store, refuse a queued/launching/running match even with a different sequence, then allocate/create the new record. Use a stable digest for the lock name and storage ID, retaining the full tuple/logical ID in validated metadata. Reject invalid identities; fail closed on unreadable records instead of interpreting them as absence. Use a consistent tuple-lock then record-lock order; no network call or process wait belongs inside either. This exclusion is within the owning daemon store; cross-role effect exclusion remains the per-PR claim, not a new cross-daemon scheduler.
3. **Recording accessor and planning.** Expose fact reads through an accessor that records field path, source, observed timestamp and age; callers never receive an untracked mutable snapshot. Check complete snapshot identity, timestamp and required fields before planning. Missing, stale, mismatched or unreadable facts return `deferred-read`. The planning input provider must honor the existing flags-only snapshot restriction: any richer mutation facts come from its live per-PR read. Freeze a serializable plan with stable effect names and values relied upon. Validate that every fact read for the plan is covered by the fence declarations of the effects that depend on it; reject missing probes, duplicate effect names and uncovered reads before claims or writes. Conservative coverage of all plan reads by every planned effect is acceptable for the first implementation.
4. **Claim and effect execution.** Inject ownership-aware claim acquisition, assertion and release ports. Claim contention ends `deferred-claim-held`. Revalidate the planned inputs under the acquired claim before each effect. Persist a stable intent/checkpoint containing `effectId`, input values and precondition, then call the declared act and persist applied evidence. On restart, probe incomplete intents before any repeat; applied marks skip the effect. A positive probe repairs the applied mark; only a conclusive negative permits fence/act. Unknown or throwing probes stop with `failed`. Keep already-applied effects when a later effect fails or is superseded. The live per-PR fence reads the complete declared GitHub input set once per effect; local claim/run facts use their authoritative local ports. Recheck claim ownership at the act boundary. An effect's own successful write may change later facts, so subsequent effects must use an explicitly recorded updated expectation or be superseded and replanned next tick; never silently ignore mismatches.
5. **Deadlines and ownership.** Classify an elapsed task deadline independently of heartbeat freshness, measured from the persisted launch time of each execution attempt; queue/backoff time is excluded. A restart or scheduler-generation change does not reset a running attempt's deadline. The sleep grace still applies to heartbeat staleness, not an elapsed task deadline. Reuse SIGTERM -> SIGCONT -> SIGKILL stopping, but require `probeHandle == dead` for confirm-gone: the existing `stopHandle` treats every non-alive response as gone (we:scripts/lib/daemon-jobs-runtime.mjs:287), including foreign handles. Foreign/unprobeable owners must retain exclusion, claim and occupied slot with a visible stop-failed diagnostic. Compare current handle and launch attempt under the record lock before recording timeout failure, releasing a claim or requeueing; a concurrent finish/new owner wins. Core tests use a recording claim port; production CAS/quarantine and health integration are W1, not a lease rewrite here.
6. **Admission and results.** Extend `admitJobs` to count all launching/running acting tasks for the same repo, while preserving existing serial-kind and total daemon limits. Default acting cap is one; independent repos and read-only planning can progress within the total cap. At the runtime launch boundary invoke shared resource admission with the declared resource kind; refusal leaves the task queued without a launch/failure charge. Keep task-kind and resource-kind names distinct. Route GitHub operations through a metered port with declared read/write budgets, including probes and fences; deny an over-budget call before executing it. Finish through the owning record update: retain authoritative outcome/effect/read/timing data, atomically publish the versioned sidecar, then mark the job terminal. Recovery from a publication failure repairs the sidecar without replaying already-applied effects. Non-failure outcomes complete successfully at job level while retaining their semantic outcome; `failed` follows bounded retry/backoff. Timeout/crash completion data is synthesized by reattachment after confirm-gone. Include task identity, launch attempt, semantic failures, phase durations and `gh` counters in timing output; dedupe by identity plus attempt when collecting logs.

## Proof plan

For **double-schedule**, race two enqueue processes on the same kind/repo/item with different sequences; capture one accepted record, one explicit exclusion and one actual child start/effect. 2. For **over-time**, start a child that keeps heartbeating and ignores SIGTERM; use a short injected timeout, longer heartbeat-stale threshold and a single permitted failure. Capture deadline classification, SIGTERM/SIGCONT, one SIGKILL, confirmed handle death, then claim-port release and terminal failure, in that order. A negative-confirmation control must retain the claim and slot and launch no replacement. This proves deadline enforcement rather than the harness's existing stale-heartbeat recovery.
3. In the same queued integration wrapper, interrupt a task after a durable local effect but before its applied mark. Restart the daemon/core against the same store and capture probe success, repaired mark and no duplicate effect. Preserve a representative result sidecar, intent/applied record, task-timing output and metered call counters as review evidence. The per-effect recording-port matrix proves the other table contracts without production writes.
4. Attach queued test/gate output and process timelines to implementation review. These are isolated core proofs, not evidence of production daemon adoption, GitHub exactly-once guarantees or fixer performance. Always clean up fixture processes; never stop a host daemon.
