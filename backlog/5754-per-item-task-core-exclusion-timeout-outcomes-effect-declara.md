# Per-item task core: exclusion, timeout, outcomes, effect declarations and a recording accessor

Slice S2a of the async-daemons epic. Add we:scripts/lib/daemon-item-tasks.mjs on the existing detached-job core, preserving the model in we:docs/agent/platform-decisions.md#daemon-jobs. The missing work is per-item exclusion across sequence numbers, bounded task execution, semantic outcomes, declared/probed effects, recorded fact reads and a result sidecar. This is a reusable core plus an isolated process proof; no production daemon adopts it here.

Task inputs are `{daemon, repo, item, snapshotPath, snapshotAt, schedulerGeneration}`; generation is diagnostic, never a cancellation fence. A kind uses `defineJobKind`: planning is `readonly-tree`, rebase/push is `mutates-tree` with an explicit worktree provider. The logical task identity is `<kind>:<repo>:<item>:<seq>`; its filesystem-safe run ID is derived separately because the existing run store rejects colons and slashes. Exclusion comes from a locked lookup of non-terminal records on `(kind, repo, item)`, not ID equality.

Execution is read -> plan -> claim -> (per effect: probe -> fence -> act -> mark). Persist intent before act. Each effect declares its inputs, authoritative applied-probe and server-side precondition (explicitly none where unavailable). Local worker dispatch probes the owning run store by `effectId = taskId:effectName`; it never substitutes a GitHub reread. Each effect's live fence rechecks its declared inputs before acting. A mismatch ends `superseded`. The core supplies recording/claim/effect ports; W1 (#5757) supplies the production worker hand-off and claim lifecycle.

Task `timeoutMs` defaults to 300000 through `cascadePolicy`; enforcement belongs to `reattachTick` (we:scripts/lib/daemon-jobs-runtime.mjs:385), using `stopHandle` (we:scripts/lib/daemon-jobs-runtime.mjs:279) and positive confirmation of death. Scheduling composes `admitJobs` with the shared `admit({kind})` service; acting concurrency defaults to one per repo (O14). Outcomes are `acted | nothing-owed | superseded | deferred-claim-held | deferred-read | failed`; only `failed` consumes the semantic task failure budget. Existing launch-attempt identity remains separate. Publish `{v:1, outcome, effects[], recordedReads[], timings, gh}` atomically and emit one `task-timing` line per completed attempt.

## Effects: declared inputs, applied-probe, server-side precondition

| Effect | Fence re-reads live | Already-applied probe | Server-side precondition |
|---|---|---|---|
| Fix / ci-heal worker dispatch | head sha, base sha, open, draft, `review:*` and hold labels, required checks, latest review id, claim | run store: worker run with this `effectId` in launching/running/done | none (the claim covers it) |
| Promote draft (`gh pr ready`) | head sha, draft, every required check green on that head, withdrawal mark | live `isDraft == false` | none |
| Label write | open, the label set the decision relied on | live label present/absent | none (idempotent) |
| Comment | open, the marker comment id | marker comment with the `effectId` exists | none (marker dedupe is an applied-probe, not an atomic guard) |
| Rebase / push (mutates-tree) | head sha, base sha | remote head equals the planned result sha | `--force-with-lease=<ref>:<expected-head-sha>` |
| Drain merge (S6a) | live fix or ci-heal claim | already merged | `--match-head-commit` |

Residual window, stated plainly: fence-then-act is a check followed by an action, not an atomic guard, except where a server-side precondition is named. Other daemons are kept out by the per-PR claim; humans and CI changes are today's risk; the next tick reconciles.

## Edge cases this change must handle

One line per class: either the handling, or `n/a: <why>`.

1. **Untrusted text** — Logical identities contain validated kind, canonical repo slug, positive item and sequence numbers; storage IDs and lock keys use a bounded digest of those structured values; PR titles and bodies never reach an id or path.
2. **Truncated reads** — A missing snapshot, one older than `snapshotMaxAgeMs`, or an unreadable sidecar ends the task `deferred-read`; nothing acts on a partial read.
3. **Shared state files** — Enqueue runs under the per-item file lock; records are written atomically (tmp + rename) under ~/.claude/daemon-jobs/<daemon>/ (R2).
4. **Fail closed** — A fence mismatch ends `superseded`; an authoritative effect-probe error ends `failed` without attempting that effect or any later one. Already-applied effects remain recorded. Unreadable fact inputs end `deferred-read`.
5. **Identity scoping** — The exclusion key is `(kind, repo, item)`, so the same PR number in two repos never collides; the handle is host:pid:procStart so pid reuse does not match.
6. **State over time** — Timeout escalates SIGTERM -> SIGCONT -> SIGKILL with confirm-gone; tasks from an older process or generation are adopted on reattach, not fenced.
7. **Who wrote it** — Only the role holding a run record resumes it (R14); records carry the launching handle.

## Design

1. **Declarations and records.** Extend kind definitions and the optional task metadata on the job block with validated timeout, acting/repo admission metadata, logical identity, failure count and result reference. Old job records without task metadata retain their existing behavior. The task wrapper attaches the optional metadata to the ordinary record before `store.create`; validate it in we:scripts/operations/job-record.mjs without changing the shared run-record factory. Persist resolved task policy with its source layers at enqueue so restart adopts the same deadline/budget. A finite positive timeout is mandatory for item tasks, default 300000 ms; snapshot age and per-effect GitHub budgets are explicit caller policy passed through the cascade, not guessed from absent fields. Keep generic launch attempts monotonic and use task failures for item-task retry exhaustion. Classifying a crash, launch failure or timeout charges that launch once under the record lock; a recorded non-failure outcome does not charge it.
2. **Enqueue exclusion.** Add a task enqueue wrapper using the existing atomic file-lock primitive. Under a short lock keyed by the canonical `(kind, repo, item)` tuple, reread the owning daemon's job store, refuse a queued/launching/running match even with a different sequence, then allocate/create the new record. Use a stable digest for the lock name and storage ID, retaining the full tuple/logical ID in validated metadata. Reject invalid identities; fail closed on unreadable records instead of interpreting them as absence. Use a consistent tuple-lock then record-lock order; no network call or process wait belongs inside either. This exclusion is within the owning daemon store; cross-role effect exclusion remains the per-PR claim, not a new cross-daemon scheduler.
3. **Recording accessor and planning.** Expose fact reads through an accessor that records field path, source, observed timestamp and age; callers never receive an untracked mutable snapshot. Check complete snapshot identity, timestamp and required fields before planning. Missing, stale, mismatched or unreadable facts return `deferred-read`. The planning input provider must honor the discovery-only snapshot restriction: cached fields may nominate a candidate, while facts authorizing a mutation come from live per-PR reads. A comment-dependent decision or marker probe must read the complete paginated thread; a short cached comment array does not prove completeness (we:scripts/lib/pr-snapshot.mjs:16). Freeze a serializable plan with stable effect names and values relied upon. Validate that every fact read for the plan is covered by the fence declarations of the effects that depend on it; reject missing probes, duplicate effect names and uncovered reads before claims or writes. Conservative coverage of all plan reads by every planned effect is acceptable for the first implementation.
4. **Claim and effect execution.** Inject ownership-aware claim acquisition, assertion and release ports. Claim contention ends `deferred-claim-held`. For each effect, run its authoritative applied-probe first; a positive result repairs/skips the effect even when its own earlier write changed the planned inputs. Only a conclusive negative proceeds to revalidate the planned inputs under the acquired claim. Persist a stable intent/checkpoint containing `effectId`, input values and precondition, then call the declared act and persist applied evidence. On restart, probe incomplete intents before any repeat; applied marks skip the effect. A positive probe repairs the applied mark; only a conclusive negative permits fence/act. Unknown or throwing probes stop with `failed`. Keep already-applied effects when a later effect fails or is superseded. The live per-PR fence reads the complete declared GitHub input set once per effect; local claim/run facts use their authoritative local ports. Recheck claim ownership at the act boundary. An effect's own successful write may change later facts, so subsequent effects must use an explicitly recorded updated expectation or be superseded and replanned next tick; never silently ignore mismatches.
5. **Deadlines and ownership.** Extend the existing deadline branch at we:scripts/lib/daemon-jobs-runtime.mjs:402: task records derive their attempt deadline from persisted launch time and timeout; records without task metadata continue using the caller-supplied `deadlineAt` callback unchanged. Preserve its hard absolute cutoff for the nightly-coroner caller at we:scripts/conveyor/nightly-coroner-job.mjs:123, including expiry while queued. Task timeout failures use the semantic retry budget rather than unconditionally terminating on the first deadline. Classify an elapsed task deadline independently of heartbeat freshness, measured from the persisted launch time of each execution attempt; queue/backoff time is excluded. A restart or scheduler-generation change does not reset a running attempt's deadline. The sleep grace still applies to heartbeat staleness, not an elapsed task deadline. Reuse SIGTERM -> SIGCONT -> SIGKILL stopping, but require `probeHandle == dead` for confirm-gone: the existing `stopHandle` treats every non-alive response as gone (we:scripts/lib/daemon-jobs-runtime.mjs:287), including foreign handles. Preserve process-group signaling, declared stop grace and the guarded dead-group reaper; do not replace them with bare-pid cleanup. Foreign/unprobeable owners must retain exclusion, claim and occupied slot with a visible stop-failed diagnostic. Compare current handle and launch attempt under the record lock before recording timeout failure, releasing a claim or requeueing; a concurrent finish/new owner wins. Core tests use a recording claim port; production CAS/quarantine and health integration are W1, not a lease rewrite here.
6. **Admission and results.** Extend `admitJobs` to count all launching/running acting tasks for the same repo, while preserving existing serial-kind and total daemon limits. Default acting cap is one; independent repos and read-only planning can progress within the total cap. At the runtime launch boundary invoke shared resource admission with the declared resource kind; refusal leaves the task queued without a launch/failure charge. Keep task-kind and resource-kind names distinct: the declared resource kind must be one of the existing exported kinds in we:scripts/lib/resource-policy.mjs:24. Interpret the returned verdict explicitly; admission returns an observation, not an acquired concurrency slot (we:scripts/lib/resource-admission.mjs:97). Apply the per-repo cap within the owning daemon store under the existing single-scheduler model; cross-role mutation exclusion still belongs to the PR claim. Mark any task capable of effects as acting independently of its code mode; a readonly-tree task can still write to GitHub. Route GitHub operations through a metered port with declared read/write budgets, including probes and fences; deny an over-budget call before executing it. Finish through the owning record update: retain authoritative outcome/effect/read/timing data, atomically publish the versioned sidecar in a results child directory keyed by safe run ID and launch attempt, then mark the job terminal. Keep the authoritative result payload and publication state in the run record; do not reconstruct them from a missing/truncated sidecar or place sidecars among root run records. Recovery from a publication failure repairs the sidecar without replaying already-applied effects. Non-failure outcomes complete successfully at job level while retaining their semantic outcome; `failed` follows bounded retry/backoff. Timeout/crash completion data is synthesized by reattachment after confirm-gone. Include task identity, launch attempt, semantic failures, phase durations and `gh` counters in timing output; dedupe by identity plus attempt when collecting logs.

7. **Child integration and recovery.** Extend `runJob` in we:scripts/lib/daemon-jobs-runtime.mjs:473 with opt-in task lifecycle hooks: supply the task core an ownership-checked record read/update port, and let task completion persist its semantic outcome and publication state before ordinary success can be stamped. Check both handle and launch attempt for task writes. Reuse the existing child claim and heartbeat lifecycle; ordinary steps without task hooks keep their current behavior. The task core owns read/plan/claim/effect execution and uses this port to persist an intent before invoking an act, rather than waiting for the ordinary post-step checkpoint. On reattachment, recover a persisted completion before deciding crash/retry: repair an unpublished sidecar and finish that same attempt without rerunning the planner or charging another failure. An unconfirmed live/foreign owner must still retain its claim and slot.
8. **Harness seams.** In we:scripts/operations/daemon-jobs-proof/run-proof.mjs, we:scripts/operations/daemon-jobs-proof/demo-daemon.mjs and we:scripts/operations/daemon-jobs-proof/noop-job.mjs, expose callable scenario/entry functions with guarded CLI entry points. Importing a suite target must not start a loop or exit the test process. Keep the copied-code materializer, but explicitly supply fixture-only policy and a temporary coordination snapshot to the shared admission reader. In a `finally` path, close log descriptors, stop fixture daemon children and confirm detached fixture job handles are gone, including when a wait or assertion fails. Never use broad process-name cleanup.
