# Collector ruling filer routes ruling cards into the ruling stream and enables it

Decision 6940 fork 1 skeptic amendment: a card must wire the ruling filer to the collector, otherwise ruling stays declared and unused and rulings keep being hand-batched (lane/rulings-1018-cards). After 6947 declares ruling disabled, add the ruling-card filer and flip the shipped default to enabled. No ruling filer exists today (rulings are hand-batched), so this card creates one: we:scripts/operations/land-ruling-card.mjs, the caller that files a ruling card through we:scripts/operations/card-batch-file.mjs with kind ruling. Flipping the default changes two of 6947's planned cases that assert the shipped defaults, and this card replaces both:
- `ruling is declared with disabled 8/60 defaults` (we:scripts/lib/__tests__/card-batch-policy.test.mjs) becomes `ruling ships enabled with 8/60 defaults`, which keeps its prevention 10/120 and filing 10/60 assertions.
- `disabled ruling refuses kind-disabled, not unknown kind` (we:scripts/operations/__tests__/card-batch-file.test.mjs) keeps its assertion but sets `enabled: false` through an explicit setting override, so the disabled-stream refusal stays covered.

The cards in the ruling stream are ordinary cards (for example `kind: story`, `status: open`) filed as the outcome of an operator ruling; the hand-batched ruling PRs carry exactly such cards. Provenance therefore lives in the filing call, not in the card: the caller passes the id of the decision the card comes from, and the filer accepts the card only when that decision card exists on main with `status: resolved` and a `## Ruling` section quoting the operator. A missing, unknown or unresolved decision id is refused before the card reaches the collector.

Both requirements are checked mechanically:
- **Decision id.** The id must match the backlog id shape (`^x[a-z0-9]{6}$` or `^[0-9]+$`) before it is used in any path. Anything else (a `/`, `..`, a glob character, whitespace, upper case) is refused.
- **Exists on main.** The filer runs `git fetch origin main`, then lists `git ls-tree --name-only origin/main backlog/` and requires exactly one file named `<id>-*.md`. It reads that one file with `git show origin/main:<path>`, never from the working tree or the caller's branch. The read is fail-closed: a failed fetch, a missing `origin/main` ref, any git error, zero or two-plus matching files, or empty output is refused. A decision that is resolved only in a lane, an unmerged branch or an uncommitted edit is refused, even when the local copy looks resolved. When main and the working tree disagree, main wins in both directions: resolved on main is admitted even when the working tree has it open or missing. Trust limit: the filer runs inside the caller's clone, so a caller that rewrites its own `origin/main` ref can defeat this read; the check stops honest mistakes and branch-only rulings, not a hostile local caller.
- **Quotes the operator.** The Ruling section (the first heading matching `^## Ruling\b`, so `## Ruling (2026-09-25)` and `## Ruling (operator, 2026-10-03)` count) must hold a verbatim operator quote. A line names the operator when it contains the word `operator` (any case) or the operator's name as written in the ratified rulings (`Nicolas Gilbert`). The quote is a quoted string (straight `"…"` or curly `“…”` quotes) holding at least one non-whitespace character, on that line, on the next non-blank line, or in the list items or `>` block that follow it before the next blank-line-separated paragraph. This accepts the layouts already on main, for example card 4862 (`Operator, 2026-10-03 …, verbatim:` then a bullet holding the quote) card 6239 (`by the operator (Nicolas Gilbert) … Verbatim: *"Ok for your picks"*`), card 4120 (`Operator, in session: *"I ratify"*`) and card 4772 (`Operator: "Ok to wait, …"`). A line that starts a sentence with a speaker label (one to three words then a colon, after any list or `>` marker, such as `Reviewer:`, `- Agent (fixer):` or `> Judge:`) is attributed to that speaker. Its quote counts only when the label names the operator: `Operator` or the operator's name (any case, markdown emphasis ignored), optionally preceded by `The` and followed by a comma- or parenthesis-separated date, channel or `verbatim` (for example `Operator, in session:`, `The operator, 2026-09-01:`, `Operator (Nicolas Gilbert):`). This holds even when the labelled line follows an operator line: an operator line followed by `Reviewer: "ship it"` is refused. Once another speaker's label appears in the block that follows an operator line, the rest of that block no longer counts for the operator. A Ruling that only summarises the outcome, that quotes nobody, that holds an empty quote, or whose only quote sits under another speaker's label is refused. Text inside a code fence does not count as a quote. Limit: attribution written in free prose is not parsed. A quote the prose credits to someone else (for example `Reviewer, replying to the operator: "ship it"`, or a skeptic's quote in an unlabelled bullet under an operator line) is admitted; the backstop is that the Ruling reached `origin/main` through a reviewed PR.

## Non-goals

- [N1] No change to how rulings are made or ratified; this only batches cards filed from an already-resolved ruling.
- [N2] No new collector mechanics: admission, sealing and retirement are the other slices'.

## Edge cases this change must handle

One line per class: either the handling, or `n/a: <why>`.

1. **Untrusted text** — the card's frontmatter and the cited decision's Ruling section are parsed; a card that fails to parse is refused, never filed (case `unparseable or partial card is refused`). The caller's decision id is checked against the id shape before it reaches any path or git call (case `malformed decision id is refused`).
2. **Truncated reads** — an unreadable or partial card file is refused, never filed (case `unparseable or partial card is refused`). The decision read from `origin/main` is fail-closed too: a failed fetch, a missing ref, a git error, zero or several matches, or empty output is refused (case `failed or ambiguous read of the decision on main is refused`).
3. **Shared state files** — the filer goes through `card-batch-file`, so the existing per-kind lease covers the collector state; the filer itself keeps no state.
4. **Fail closed** — no provenance, a parse error or a coordinator refusal leaves the card unfiled and reported, never admitted (cases `ruling card without operator provenance is refused`, `unparseable or partial card is refused`, `coordinator refusal leaves the ruling card unfiled and reported`).
5. **Identity scoping** — the ruling stream is its own kind, keyed by repo; a ruling card never lands in the filing batch (case `ruling cards are admitted into the ruling batch, not filing`).
6. **State over time** — n/a: the filer is stateless; batch lifecycle is 6941's.
7. **Who wrote it** — a card is accepted only when it cites a decision resolved on `origin/main` whose `## Ruling` section quotes the operator; a mechanical caller cannot file into the ruling stream without one, and a ruling that sits only on its own branch or working tree is refused (cases `decision not on main is refused`, `ruling without an operator quote is refused`). A quote under a speaker label other than the operator's is refused, even right after an operator line (case `reviewer quote following operator line is refused`). Trust limit: the read runs in the caller's clone, so a caller that rewrites its own `origin/main` ref is out of reach of this check. Attribution written in free prose rather than a speaker label is not checked.
