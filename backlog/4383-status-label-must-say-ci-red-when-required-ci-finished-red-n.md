## Design

1. Extend `PR_STATE_FIELDS` in we:scripts/lib/review-label-provider.mjs:67 with `statusCheckRollup`. Preserve the provider's read-failure behavior and single-read shape. The daemon already passes a snapshot; do not add a per-PR network read there.
2. In we:scripts/conveyor/review-status-tag.mjs, prepare the CI facts before deriving the legacy status, so standalone calls as well as calls with planner rows receive them. Reuse the injectable required-check input/cache reader and existing head-bound merge-gate excusal seam. Resolve required checks and head-bound excusal once per invocation and share those facts with the newer status path. Keep settings loading conditional on planner rows as today; the legacy reducer does not adopt newer display settings. Accept only a nonempty array of nonblank string requirement names for legacy reduction; explicit null, empty/malformed arrays, unavailable provenance, or a thrown cache read retain the legacy fallback. Preserve cache-only reads and the newer path's existing fallback behavior.
3. Pass an optional reduced CI state into `deriveReviewStatus`. Use `reduceCheckState` from we:scripts/operations/pr-status.mjs:172 with the known nonempty required set; it already collapses reruns, handles implied requirements, and gives pending precedence over failure. First collapse raw rows with `collapseRollupToLatestPerName` from we:scripts/lib/rollup-collapse.mjs:66, preserving its CheckRun-versus-StatusContext precedence. Locally map surviving legacy contexts to reducer inputs: `context` → `name`, `PENDING` → running, `SUCCESS` → completed/success, and `FAILURE` or `ERROR` → completed/failure; leave unknown states unreadable. The collapse utility itself does not normalize status contexts. Unknown requirements or absent/unreadable rollup must not manufacture completed-red evidence; preserve the previous legacy fallback in those cases. Do not use the reducer's unfiltered fallback to classify an optional failure as required.
4. Preserve precedence: existing head-scoped escalation, live reviewer/fix claim/fixer/CI healer, and stacked-base draft waiting continue to win. After those cases, reduced required CI `red` yields `{ role: 'draft', state: 'needs-human' }` for a draft and `{ role: 'ci', state: 'ci-red' }` for a non-draft. Pending, unchecked, or green retains the existing fallback: default-branch draft `awaiting-ci`, otherwise `null`. The proposed `ci` role is informational and must not masquerade as a live fixer.
5. Add `ci-red` to the legacy enum and return-type documentation in we:scripts/conveyor/review-status-tag.mjs. Reuse `planStatusLabelChange` to remove stale labels, including `ci-red` after a rerun, without touching unrelated labels. Its durable withdrawal override remains authoritative. With legacy writes disabled, continue removing legacy labels except withdrawal; keep `status:*` derivation unchanged by passing the pre-CI `deriveReviewStatus` result to `derivePrStatusLabel`, not the new legacy result. In particular, a draft legacy `needs-human` must not introduce `status:escalated` when newer settings exclude the failed review gate. Preserve the original raw/newer-subject handling and settings behavior; normalize a separate legacy reducer input.
