# Judge clearance decision core: protected list and provider independence check

A pure decision function says whether the independent judge may clear review:human on a PR: only when reviewers accepted for the current head and only the human gate remains, never when the diff touches the protected list (merge/approval logic, credentials and secrets, security-check weakening), never when the judge shares the author provider or actor, and never when the kill switch is on or the wait has not elapsed.

Builds rules 1–3 of `we:docs/agent/platform-decisions.md#independent-judge-clears-review-human-outside-protected-list` (decision xne1udi, operator 2026-10-03). No I/O, no spawn, no label write — those belong to `xq3kn88`.

## Design

New pure leaf `we:scripts/lib/judge-clearance.mjs` exporting `decideJudgeClearance(input)` → `{ allowed, refusal, detail }`. `refusal` is one of a closed, frozen set `JUDGE_REFUSALS`:

- `kill-switch` — `input.switches.judgeEnabled !== true` (the switch state from `x6e8z3o`, passed in; this module reads nothing).
- `wait-not-elapsed` — `input.switches.waitHours > 0` and less than that many hours have passed since `input.parkedAt`, the time the PR was parked on `review:human`. With `waitHours` 0 or absent the check is skipped (default off, so a clear is immediate). **Input source for `parkedAt`:** the GitHub issue timeline, the `labeled` event for `review:human` that is the **latest one not followed by an `unlabeled` event for it** (the runner reads it with `gh api repos/<repo>/issues/<n>/timeline`; this module only receives the timestamp). If the timeline cannot be read or holds no such event, `parkedAt` is `null`, and with `waitHours > 0` that is refused as `wait-not-elapsed` (detail `parked-time-unknown`) — never treated as "long enough". The label timeline is written by GitHub, not by the PR author, so the author cannot backdate it.
- `not-human-gated` — the PR does not carry `review:human`.
- `reviewers-not-accepted` — no `advisory:accepted` covering the current head (reuse `advisoryCoversHead` and `latestAdvisory` from `we:scripts/lib/advisory-labels.mjs`), or a live `review:changes`, or red CI.
- `protected-list` — a changed path matches the protected list (below); the matching paths go in `detail`.
- `secret-in-diff` — an added line matches `SECRET_PATTERNS` or a high-entropy token from `we:scripts/lib/secret-scrub.mjs`.
- `independence-unknown` — the author provider or author actor cannot be read from a **trusted source**. **The author's provider is never taken from text the PR author can edit:** not the PR body (so not the delegation marker in it, `parseDelegationMarker`), not the PR title, comments or labels, and not a commit trailer inside the PR's own commits (the lane agent writes those commits). The trusted source is the **dispatch run record**: the record the dispatcher writes in the coordination root (`resolveCoordinationRoot()`, `we:scripts/operations/coordination-root.mjs`) when it chooses and spawns the delivery agent, outside the repo and outside the PR, keyed by the PR's head ref (`lane/*`) and carrying the **executed** provider (the provider that actually ran, as `we:scripts/operations/dispatch-lane.mjs` already distinguishes "chosen" from "executed"). The build's first step confirms which existing dispatch record carries the executed provider; if none does, adding that one field at the dispatcher's write site is part of this story (widen `scope:` in the PR). The runner reads the record and passes `authorProvider` in; this module reads nothing. No record for the head ref, an unreadable record, or a record with no provider → unknown. **The record is bound to this repo, this lineage and this run, not only to a ref name.** A head ref name alone is not an identity: a fork PR can use any `lane/*` name, and a ref name can be reused after an earlier Codex-dispatched lane — and in that reuse the old record's `baseSha` is still an ancestor of the new head and the new PR is still created after the old `startedAt`, so ancestry and a lower time bound alone prove nothing. So the record also carries `repo` (the target repo's slug), `baseSha` (the commit the lane was reset to when the dispatcher spawned the agent), `startedAt`, and `endedAt` (written by `we:scripts/operations/deliver-item-wrapper.mjs` when the agent process exits; a record with no `endedAt` is read as running until `startedAt` plus `DISPATCH_RUN_CEILING_HOURS`, 12, the same ceiling the dispatcher kills a hung run at). Today `we:scripts/operations/dispatch-lane.mjs` writes none of these four (nor, possibly, the executed provider): adding them at its record-write site, with a case in `we:scripts/operations/__tests__/dispatch-lane.test.mjs`, is part of this story (the dispatcher, the wrapper and the dispatch-lane test are all in `scope:`). A PR belongs to a record only if the PR was **created inside that record's run window** — the agent that opened it was running then. Several records may exist for one ref (one per dispatch); the runner collects every record for this repo and ref and passes them all, and the module picks the single record whose window contains the PR's `createdAt` (none or more than one → `independence-unknown`, detail `record-mismatch`). A later PR on a reused ref name was created after the old run ended, so it matches no old record. The pure export `deriveRecordBinding({ records, pr, baseShaIsAncestor })` in `we:scripts/lib/judge-clearance.mjs` returns the chosen record and `recordBinding: { headIsSameRepo, repoMatches, baseShaIsAncestor, prCreatedInRunWindow }`; the runner passes in only the raw facts (the live PR's `isCrossRepository`, `headRepository` and `createdAt`, the records, and the result of `git merge-base --is-ancestor <baseSha> <head-sha>` per record). Any of the four false or missing → `independence-unknown` with detail `record-mismatch`: a fork head, a reused ref name with a new history, or a record from another repo can never lend its provider to a PR. **The derivation itself is tested on a realistic reused lineage** (see the test plan), not only with the four flags supplied as fixtures. The PR-side signals (delegation marker, co-author trailer via `isAiCommit` in `we:scripts/lib/ai-pr-authorship.mjs`) may only **add** doubt: if the trusted record says `codex` but the PR carries a Claude co-author trailer, refuse as `independence-unknown` (the sources disagree); they can never turn an unknown into a known. The author actor comes from `parseAuthorActorId` in `we:scripts/lib/review-independence.mjs` and is likewise cross-checked against the run record's session id.
- `same-provider` — the judge provider equals the author provider.
- `same-actor` — the judge actor id equals the author actor, or any reviewer actor recorded on the PR (`cleared-by-actor` markers and the advisory reviewer id).

`input.changedPaths` is the **complete** set of paths the PR changes, computed by the runner from git (the net diff against the base, see `xq3kn88`), never from the capped `gh pr view --json files` list. The module refuses (`protected-list`, detail `changed-paths-incomplete`) when `changedPaths` is missing, not an array, or flagged `truncated`, so a truncated list can never read as "nothing protected touched".

Checks run in that order; the first refusal wins. Any error thrown inside the function is caught and returned as `refusal: 'error'`, `allowed: false` (fail closed).

**One protected-list check, shared.** The module also exports `protectedPathsTouched({ changedPaths, decisionCardResolves, addedLines })` → `{ touched: boolean, paths, detail }`, the single function that applies `JUDGE_PROTECTED` and `RATIFICATION_PROTECTED` (and refuses on an incomplete `changedPaths`). `decideJudgeClearance` calls it for its `protected-list` check, and the arbiter (`x6prrg3`) calls the same function, so the clearance boundary and the arbitration boundary cannot drift.

**The protected list lives in the leash, not in the new module.** Add `JUDGE_PROTECTED` to `we:scripts/lib/gate-config.mjs`. That file is on the `POLICY_SPEC` floor, so every later edit to the list is itself human-gated and judge-protected:

- **(a) merge/approval logic** — every `TRUST_CHAIN` member (`isTrustChainPath`), plus `we:scripts/review-set-label.mjs`, `we:scripts/pr-land.mjs`, `we:scripts/operations/record-verdict.mjs`, `we:scripts/operations/review-dispatch.mjs`, `we:scripts/lib/advisory-labels.mjs`, `we:scripts/lib/verdict-ledger.mjs`, **the merge gate's workflows and appliers** (every file under `we:.github/workflows/` — `we:.github/workflows/review-gate.yml`, `we:.github/workflows/apply-review-request.yml`, `we:.github/workflows/ci.yml`, `we:.github/workflows/deploy.yml` and any workflow added later, so the folder rather than a name list — plus the cloud-VM label applier and gate checkers `we:scripts/apply-review-request.mjs`, `we:scripts/check-review-gate.mjs` and `we:scripts/collect-review-requests.mjs`; the statute names "the review gate" in this class, and a PR that weakens a required check in a workflow must never reach the judge's discretionary reading alone), and **the judge's own inputs and control modules**, so a PR cannot rewire the judge and get itself cleared. The judge's modules are defined **by pattern first, then by a named list for the ones the pattern misses**, so a module a later card adds is covered the day it lands rather than the day someone remembers to list it:
  - the **pattern**: `JUDGE_MODULE_PATTERNS` in `we:scripts/lib/gate-config.mjs` — every `scripts/**/judge-*.mjs` and every judge test (`scripts/**/__tests__/judge-*.test.mjs`; weakening a test that pins the judge weakens the judge). It covers the files below that start with `judge-`, including `we:scripts/lib/judge-verdict-record.mjs` (the module the label home trusts to prove the judge answered `clear`; `xq3kn88`), `we:scripts/lib/judge-facts.mjs` (the one live-recompute gatherer the runner and the label home share; `xq3kn88`) and `we:scripts/lib/judge-trusted-paths.mjs` (the one exported path list both guard hooks read; this story);
  - the **clearance decision**: `we:scripts/lib/judge-clearance.mjs`;
  - the **runner and its siblings**: `we:scripts/operations/judge-clear.mjs`, `we:scripts/operations/judge-arbitrate.mjs`, `we:scripts/conveyor/judge-pass.mjs`, `we:scripts/conveyor/judge-digest.mjs`, and the seat spawners the runner uses (`we:scripts/lib/judge-spawn.mjs`, `we:scripts/lib/codex-judge-spawn.mjs`);
  - the **arbiter's answer code** (`x6prrg3`): `we:scripts/conveyor/stand-down-answer-core.mjs` (the tamper-evident arbiter answer record), `we:scripts/conveyor/stand-down.mjs` (the stand-down marker and reasons the arbiter reads) and `we:scripts/lib/finding-bounce.mjs` (the finding id and twice-bounced detection);
  - the **switch store** code: `we:scripts/lib/judge-switches.mjs` and `we:scripts/conveyor/judge-switch.mjs` (the store file itself lives outside the repo, see `x6e8z3o`);
  - the **provider-identity source** and independence inputs: `we:scripts/lib/review-independence.mjs`, `we:scripts/lib/delegation-marker.mjs`, `we:scripts/lib/ai-pr-authorship.mjs`, `we:scripts/lib/dispatch-provider-availability.mjs`, `we:scripts/operations/dispatch-lane.mjs`, `we:scripts/operations/dispatch-lane-io.mjs`, `we:scripts/operations/dispatch-provider-registry.mjs`, `we:scripts/operations/deliver-item-wrapper.mjs`, and `we:scripts/operations/coordination-root.mjs` (the code that writes or locates the dispatch run record the author provider is read from).
- **(b) credentials and secrets** — `we:scripts/lib/github-app-token.mjs`, any env file (a basename starting with a dot and containing `env`), and any path whose basename matches `secret|token|credential|password|pem|key` outside the `backlog/`, `reports/` and `src/` content trees.
- **(c) security checks** — the guard hooks (`we:scripts/guard-bash.mjs` and its `guard-*` siblings in the same folder), `we:.claude/settings.json`, the git hooks folder `we:.githooks`, `we:scripts/lib/secret-scrub.mjs`, and `we:scripts/rust-scan/src/secret_scrub.rs`. Path matching is the deterministic floor; the judge prompt (`xq3kn88`) adds the judgment half ("does this weaken a security check?") and must refuse on doubt.
- **(d) ratification surfaces — the rules layer and every file that records a ruling.** Ruled by the operator on 2026-10-04 ("send back to fix (block)": add a protected class for the rules layer and other ratification surfaces, so a PR touching them is never judge-clearable and always needs the human ceremony); rule 3 of the statute carries it as class (d). A PR cannot rewrite the judge's own authority, or forge a ruling, and then clear itself. The class is `RATIFICATION_PROTECTED` in `we:scripts/lib/gate-config.mjs`:
  - **the rules layer:** every `STATUTE_PATHS` entry (`isStatutePath`: `we:docs/agent/platform-decisions.md` and any `docs/agent/*statute*` doc), **and its future per-ruling files** — any path under `we:docs/agent/platform-decisions/` and any `docs/agent/*decision*` or `docs/agent/*ruling*` doc — so splitting the statute into one file per ruling later does not open a gap;
  - **any file that records a ruling:** (i) any `kind: decision` backlog card the diff sets to `status: resolved` or gives a `codifiedIn:` line — the runner reads the head blob's frontmatter from git, never the PR text, and passes `decisionCardResolves: <paths>`; the core refuses `protected-list`, detail `decision-card-resolved`; (ii) any markdown file in the diff with an **added line** that matches `RULING_MARKERS` (`**Ratified `, `**Operator ruling`, `Operator, verbatim`, `codifiedIn:`, or a statute anchor `{#…}`); the core refuses `protected-list`, detail `ruling-recorded`, naming the file. The marker check reads the added lines the runner already computes for the secret scan.
  - The leash already parks a statute edit on `review:human`; without this class the judge could lift that park on the one edit that rewrites its own authority.

Also register `we:scripts/lib/judge-clearance.mjs` as a policy-tier `TRUST_CHAIN` member so its own edits escalate.

**The trusted inputs are guarded against the lane agent that builds the PR.** The dispatch run record, the `judge-verdicts` folder (`xq3kn88`) and the judge switch store (`x6e8z3o`) all sit in the operator's account, which a lane agent also runs as, so "outside the repo" does not by itself keep them out of an author's reach. Add a deterministic deny to both agent hooks — `we:scripts/guard-bash.mjs` (any Bash command that writes, moves, deletes or truncates a path under the coordination root's `judge-switches`, `judge-verdicts` and dispatch-record locations, or runs the `judge-switch` CLI's write verbs) and `we:scripts/guard-lane.mjs` (any Edit or Write to those paths) — for every session that is not the dispatcher, the judge runner or the operator's own shell. The path set is one exported list so the two hooks and their tests read the same one. **Who counts as a lane session:** the hooks already know the lane the caller works in (`laneRootFromCwd` in `we:scripts/guard-bash.mjs`, the same test `guard-lane` uses), so the deny applies to a caller whose working directory is inside a `.lanes/` clone or which is an agent session; the judge runner and the dispatcher run from the daemon checkout and the operator's own shell has no hook, so neither is affected. **The path set is fixed, not derived from the environment:** the judge readers (this module's runner, `xq3kn88`'s label home) locate the dispatch record, the `judge-verdicts` folder and the switch store under `<os.userInfo().homedir>/workspace/.operations/coordination` as one exported constant, and ignore `WE_COORDINATION_ROOT` (the variable `resolveCoordinationRoot()` honours, which a lane process can set to a scratch folder holding a forged record) — the same rule `x6e8z3o` states for the switch store. If the dispatcher itself ran with that override, its record is simply not found at the fixed path and reads as unknown (fail closed). Reads stay allowed (the runner and `status` need them). The honest limit: a hook is not a sandbox, so a session that defeats its own hook can still write; the guard closes the accidental and the casual path, and the stronger fix — the dispatcher signing the record with a key lane sessions cannot read — is filed as a follow-up. The guard files are on the protected list (class (c)), so loosening this rule is itself human-only.

## MVP

1. Must refuse with `protected-list` when any changed path is in class (a), (b), (c) or (d), naming the paths.
2. Must refuse with `same-provider` when the judge provider equals the author provider, and with `same-actor` when the judge actor is the author or a recorded reviewer.
3. Must refuse with `independence-unknown` when the author provider or actor cannot be read from the trusted dispatch run record — never assume independence, and never read the provider from the PR body, title, comments or the PR's own commit trailers. Must also refuse when a PR-side signal contradicts the record.
4. Must refuse with `kill-switch` when the judge is off, and must apply no wait when `waitHours` is 0 or absent. With `waitHours > 0`, must refuse `wait-not-elapsed` when the park time (`parkedAt`, from the label timeline) is missing.
3a. Must refuse with `independence-unknown` (detail `record-mismatch`) when the dispatch record is not bound to this PR: head repository is not the base repo, the record's repo differs, the record's `baseSha` is not an ancestor of the PR head, or the PR was not created inside the record's run window (`startedAt` to `endedAt`, or the running ceiling when `endedAt` is absent), or no record or more than one record covers the PR's creation time — a fork head or a reused ref name never borrows a provider, even when the old record's base is still an ancestor of the new head.
3a2. Must carry `repo`, `baseSha` and `startedAt` (and the executed provider) on every new dispatch run record, written at the dispatcher, with a test in the dispatch-lane suite; and must locate the record, the verdict records and the switch store at the fixed account-home path, ignoring `WE_COORDINATION_ROOT`.
3b. Must deny lane sessions any write to the judge switch store, the judge verdict records and the dispatch run records, in both `we:scripts/guard-bash.mjs` and `we:scripts/guard-lane.mjs`, from one shared path list; reads stay allowed.
4a. Must refuse with `protected-list` when the diff touches the ratification class (d): any statute-layer path (`isStatutePath`) or per-ruling file, a `kind: decision` card set to `status: resolved` or given a `codifiedIn:` line (`decision-card-resolved`), or a markdown file with an added ruling-marker line (`ruling-recorded`) — a PR cannot rewrite the judge's authority or forge a ruling and clear itself, and always needs the human ceremony.
4b. Must refuse with `protected-list` when the diff touches any of the judge's own inputs and control modules — every `judge-*` script or test by pattern (including `we:scripts/lib/judge-verdict-record.mjs`, `we:scripts/lib/judge-facts.mjs` and `we:scripts/lib/judge-trusted-paths.mjs`), the named non-matching control modules (the seat spawner for Codex, the arbiter answer code, the provider-identity source) — a PR cannot rewire the judge and clear itself.
4c. Must refuse with `protected-list` when the diff touches anything under `.github/workflows/` or the cloud-VM label applier and gate checkers — a PR cannot weaken the merge gate and then rely on the judge's discretionary reading.
4d. Must export `protectedPathsTouched` as the one protected-list check, used by both the clearance decision and the arbiter.
5. Must refuse (`error`) on any internal error — fail closed. Must treat docs, config, data and backlog files in the diff the same as code for the protected-list and secret checks (no "it is only prose" exemption).
6. Must return `allowed: true` only when every check passes.
