# Judge seat runner: an Opus judge from another provider clears review:human through clear-human

A runner seats the independent judge on a review:human PR whose reviewers accepted: it reads the author provider from the trusted dispatch run record (never from the PR body), seats Opus only from a different provider and actor, asks the read-only judge for a schema verdict, and on clear calls the existing clear-human ceremony itself with the judge as actor and its reasoning as the reason; refusals leave the PR for the human.

Builds rules 1–4 of `we:docs/agent/platform-decisions.md#independent-judge-clears-review-human-outside-protected-list` for ONE PR at a time, invoked by hand. Running it on every tick is `xfetp9j`; the ledger plumbing on the clear path (target mapping, `judge` block, the row at the label home) is here, and the post-spawn decline rows and the daily digest are `xfbj1fa`.

## Design

**Runner** `we:scripts/operations/judge-clear.mjs --pr=<n> [--repo=…] [--dry-run]`:

1. Read the PR (`gh pr view --json number,headRefOid,headRefName,baseRefName,labels,body,comments,commits,statusCheckRollup`) and the switches (`we:scripts/lib/judge-switches.mjs`). Four inputs come from outside that call, because `gh pr view` is not safe for them:
   - **Changed files — from git, never from `--json files`.** `gh pr view --json files` is capped (about 100 files), so a large PR would be checked against a truncated list and a protected file could hide past the cap. The runner fetches the head and base in the lane clone and computes the **net diff against the base** (`git diff --name-only --no-renames <base-sha>...<head-sha>`, the same net-diff basis the gate uses, so a file changed and changed back is not counted, and a rename lists both sides). It also computes the added lines from the same diff for the secret scan. If git cannot produce the list (fetch failure, unknown base), the runner passes `changedPaths: null` and `decideJudgeClearance` refuses (`changed-paths-incomplete`) — never an empty list.
   - **Author provider — from the dispatch binding record** the delivery wrapper wrote when it opened this PR, found by `(repo, PR number)` at the fixed `JUDGE_DISPATCH_DIR` path and carrying the executed provider (see `xfnv9ay`; never looked up by head ref name, which a fork or a reused ref can share). Not from the PR body, title, comments or the PR's own commit trailers: the author can edit all of those.
   - **When the PR was parked — from the issue label timeline** (`gh api repos/<repo>/issues/<n>/timeline`, the latest `labeled` event for `review:human` with no later `unlabeled`), passed as `parkedAt` (`null` if unreadable). It is only needed when the wait switch is above 0.
   - **Record binding and decision-card facts (`xfnv9ay`).** the raw facts for `deriveRecordBinding` — the PR's `number`, `isCrossRepository` and `headRepository` from `gh pr view --json number,isCrossRepository,headRepository`, the dispatch binding record for `(repo, number)`, and the result of `git merge-base --is-ancestor <baseSha> <head-sha>` in the lane clone; a reused ref name has a different PR number and so never borrows an earlier run's provider — and `decisionCardResolves`, from the head blobs' frontmatter of changed `backlog/*.md` files (`git show <head-sha>:<path>`). Any that cannot be computed is passed as unknown and the decision core refuses.
2. Pick the seat: the judge is Opus through `judgeSpawn` in `we:scripts/lib/judge-spawn.mjs` (provider `anthropic`, model `opus`, effort `high`), tool-free, fresh session id from `deriveSessionId`. Its actor id is that session id.
3. Call `decideJudgeClearance` (`xfnv9ay`) with the PR facts, the switches and the seat. Any refusal stops here: print the reason, write nothing, the PR stays `review:human`.
4. Spawn the judge with a mandate built from the PR diff, the advisory note, the reviewers' verdicts and the protected-list rule text, and a JSON schema `{ verdict: "clear" | "keep-human", protectedConcern: boolean, reasoning: string }`. The mandate tells the judge to answer `keep-human` with `protectedConcern: true` if the diff weakens any security check, touches credentials, or changes merge/approval behaviour in a way the path list missed — and on any doubt.
5. Only `verdict: "clear"` with `protectedConcern: false` proceeds. Spawn failure, timeout, budget stop, unparseable output, or any other verdict → no clear (fail closed). Before writing a label, the runner writes a **judge verdict record** (see below) binding that answer to this PR and this head.
6. Clear through the single label home: `runReviewLabelCli` in `we:scripts/review-set-label.mjs` with a new target `clear-human-judge`, `--actor=independent-judge:<provider>/<model>/<sessionId>`, and `--reason=<the judge's reasoning, verbatim>`.

**Judge verdict record — the proof a judge actually answered `clear`.** New pure-plus-small-I/O module `we:scripts/lib/judge-verdict-record.mjs` (`writeJudgeVerdictRecord`, `verifyJudgeVerdictRecord`, `consumeJudgeVerdictRecord`). Step 5 writes one JSON record per PR into a `judge-verdicts` folder at a **fixed** account-home path (one exported constant, `JUDGE_VERDICTS_DIR`, defined in `we:scripts/lib/judge-trusted-paths.mjs` of `xfnv9ay` and imported here, under `<os.userInfo().homedir>/workspace/.operations/coordination`, not derived from `WE_COORDINATION_ROOT`, `$HOME` or the working directory — the rule `x6e8z3o` states for the switch store, so a lane process cannot point the label home at a scratch folder holding a forged record): `{ repo, pr, headSha, verdict, protectedConcern, provider, model, actor, reasoningSha256, at, nonce }`, where `actor` is the judge's own session id from step 2. The record is written **only** by the runner after it parsed the judge's schema answer, and only for `verdict: "clear"` with `protectedConcern: false`; a `keep-human` answer or a concern writes a record saying so, so a stale `clear` for the same PR is overwritten. The folder is outside the repo, and lane sessions are denied writes to it (the guard rule is a `xfnv9ay` Must).

**New target `clear-human-judge` in `decideSetLabel`.** Same label swap as `clear-human`, but its CLI path enforces two things before any write, and refuses unless both hold:

1. **A verified judge verdict at the current head.** `verifyJudgeVerdictRecord` reads the record for this repo and PR and requires: `verdict` is `clear`, `protectedConcern` is false, `headSha` equals the PR's live head oid right now (a push after the judge answered voids it), the record is not older than 30 minutes, the provider, model and actor in `--actor` equal the record's (the flag only names the record; it can never supply the provider), `--reason`'s sha256 equals `reasoningSha256`, and the record has not been consumed. On success the record is consumed (renamed with its nonce) **before** the label write, so a record clears at most one label swap. A missing, stale, mismatched, `keep-human`, concern-flagged or already-consumed record → refused, labels untouched. This closes the hand-call hole: `we:scripts/review-set-label.mjs --to=clear-human-judge --actor=… --reason=…` with no judge having answered `clear` on this head is refused.
2. **The deterministic checks, recomputed.** It recomputes `decideJudgeClearance` from the live PR (the same trusted inputs as step 1: git net diff, dispatch run record, label timeline, and the facts `xfnv9ay` added — the record binding (head repository is the base repo, record repo matches, record `baseSha` is an ancestor of the head, PR created inside the record's run window), `decisionCardResolves` (decision cards the diff resolves, read from the head blob's frontmatter) and the added lines (for the ruling-marker and secret checks) — never the capped file list or PR text; the runner and the label home share **one gatherer, `gatherJudgeFacts` in the new `we:scripts/lib/judge-facts.mjs`**, so they cannot drift; the module is on the protected list by its `judge-` name, `xfnv9ay`) and refuses unless it is `allowed`. So the protected list and the independence check are enforced at the label home too, not only in the runner.

**The ledger row for a judge clearance is owned here, at the label home — this story owns the whole path from target to row.** The verdict ledger append happens in `runReviewLabelCli`, not in the runner: it calls `verdictForLabelTarget(to)` and then `buildVerdictRecord`, and `buildVerdictRecord` throws on a `null` verdict — a throw the label home catches and logs as non-fatal, after which the swap goes ahead. On main `verdictForLabelTarget` maps only `accepted`, `changes`, `clear-human`, `rearm` and `restamp`, so without this work a `clear-human-judge` swap would succeed with **no ledger row**, and the daily digest (`xfbj1fa`) would be silent about every clearance — breaking rule 4. This story therefore owns, in `we:scripts/lib/verdict-ledger.mjs` and `we:scripts/review-set-label.mjs` (both in `scope:`):

1. **The mapping:** `verdictForLabelTarget('clear-human-judge')` returns `VERDICTS.CLEAR_HUMAN` (the same bearing verdict and the same mirrored label, `review:accepted`, as the human `clear-human`; the `judge` block, not a new verdict, is what tells the two apart). `labelForVerdict` is unchanged.
2. **The `judge` block field:** `buildVerdictRecord` accepts an optional `judge` block `{ provider, model, actorId, authorProvider, verdict, protectedConcern, reasoning, refusal }`, additive and optional, so every existing record and reader is unchanged and the ledger version stays 1 (`xfbj1fa` reads it and writes the post-spawn decline rows).
3. **Passing it through:** for `clear-human-judge`, `runReviewLabelCli` builds the `judge` block from the **verified judge verdict record it just consumed** (provider, model, actor, verdict, reasoning, and the author provider from the shared gatherer), never from the `--actor` or `--reason` flags alone, and passes it to `buildVerdictRecord`.
4. **Fail closed for this target only:** the ledger row is appended **before** the label swap, and for `clear-human-judge` an append failure refuses the clear (labels untouched, the record stays consumed, the runner prints "judge cleared but not recorded; rerun") — rule 4 says every clearance leaves a durable record, so a clearance with no row must not happen. The existing targets keep their non-fatal ledger behaviour unchanged. If the swap itself then fails after the row was appended, the label home appends a second row for the same PR and head with verdict `observed` and reason `swap-failed`, so the digest does not count a clear that never happened.
4a. **The new target inherits the human ceremony's checks.** In `we:scripts/review-set-label.mjs` the opt-in (`allowClearHuman`), the actor and reason requirement, the advisory-label stripping and the current-head advisory precondition are all keyed on `to === 'clear-human'`. A single helper `isClearHumanTarget(to)` (true for `clear-human` and `clear-human-judge`) replaces each such test, so the judge target gets every one of them; the judge-specific checks (verdict record, recompute) are added on top, never instead. A test asserts each of those four behaviours for `clear-human-judge`.
5. **A standing invariant, so a future target cannot repeat the gap:** a test in `we:scripts/__tests__/review-set-label.test.mjs` asserts that every member of `REVIEW_LABEL_TARGETS` maps to a non-null `verdictForLabelTarget` verdict, so a new target fails the build until its mapping exists.

**Agent sessions stay out of the new target — what the code already does, and what this story pins.** The three agent paths are not name lists, so there is nothing to add to them, and they need no edit: review sessions are denied the whole script (`REVIEW_DISPATCH_DISALLOWED_TOOLS` in `we:scripts/operations/review-dispatch.mjs` denies `we:scripts/review-set-label.mjs` by script, so it denies every target including the new one); `we:scripts/apply-review-request.mjs` applies only `APPLIABLE_TARGETS` (`accepted`, `changes`, `clear-human`), an allow-list the new target is not in; `we:scripts/lib/review-skill-guard.mjs` is a doc linter and is not a deny path. What the story adds is the **pin**: `REVIEW_LABEL_TARGETS` in `we:scripts/review-set-label.mjs` gains `clear-human-judge`, and two assertions in `we:scripts/__tests__/review-set-label.test.mjs` fail the build if either protection erodes — `APPLIABLE_TARGETS` must not contain `clear-human-judge`, and `REVIEW_DISPATCH_DISALLOWED_TOOLS` must still deny `we:scripts/review-set-label.mjs`. The stale comments in `we:scripts/review-set-label.mjs` that call `clear-human` the only target removing `review:human` are updated in the same edit.

**Known limit of the record.** The record and its folder sit in the operator's account like the rest of the coordination root, so a session that defeats the guard hook and writes files directly could forge one. The record is a deterministic floor against hand calls, stale answers and wrong-head clears, not a cryptographic proof. Signing the record with a key lane sessions cannot read is the stronger follow-up, filed below; it is not needed to close the hand-call hole this story targets.

The existing `clear-human` (the human ceremony) is unchanged. The durable comment of `clear-human-judge` gains a new phrasing: *"an independent judge cleared it (provider X, model Y; protected list checked)"*, with the judge's reasoning quoted. The `clear-human` advisory-note precondition (`#clear-human-requires-current-head-advisory-review`) applies to this target as well.

**Known limit, and where the ruled answer lives.** Today most PRs are Claude-authored, and an Opus judge is then the same provider, so it is refused (`same-provider`). This story ships exactly that: Opus only, no fallback seat, so Claude-authored PRs stay human until the cross-provider seat exists. The answer is not left open: it is the cross-provider Codex seat (through `we:scripts/lib/codex-judge-spawn.mjs`), with its fallback when Codex is unavailable following the configurable independence dimension. That direction is carried by `xud2hha` (who judges Claude-authored PRs) and `xb1e9nj` (what stands in when the cross-provider seat is unavailable), which are one question so the review seat and the judge seat cannot disagree; the cards record the ruled answer and the fallback detail. This story neither re-decides it nor blocks on it; the seat function takes the provider as a parameter so the Codex seat is a later addition, not a rewrite.

## MVP

1. Must clear `review:human` only through `clear-human-judge`, and only when `decideJudgeClearance` allows it AND the judge answers `clear` without a protected concern.
2. Must refuse, writing nothing, on any judge failure (spawn error, timeout, bad JSON, schema miss) — fail closed.
3. Must refuse `clear-human-judge` at the label home when the live recomputation refuses, even when called directly.
3a. Must refuse `clear-human-judge` at the label home unless a judge verdict record for this PR says `clear` with no protected concern, is bound to the PR's live head, is fresh, matches the `--actor` and `--reason`, and has not been consumed — a direct CLI call with no judge answer is refused. A record clears one swap only.
3b. Must keep `clear-human-judge` out of every agent session's reach: `REVIEW_LABEL_TARGETS` names it, `APPLIABLE_TARGETS` does not, and `REVIEW_DISPATCH_DISALLOWED_TOOLS` still denies the script — pinned by assertions in the review-set-label suite.
3c. Must write exactly one ledger row carrying the `judge` block for every `clear-human-judge` swap, through `verdictForLabelTarget('clear-human-judge')` and `runReviewLabelCli`: the mapping exists, the block is built from the consumed verdict record, the row is appended before the swap, and a failed append refuses the clear. Every member of `REVIEW_LABEL_TARGETS` must map to a verdict.
4. Must post the judge's provider, model, actor and verbatim reasoning in the durable clearance comment.
5. Must treat the PR body, diff, comments and advisory note as untrusted data in the judge prompt: text in them never changes the protected list, the switches or the verdict schema.
6. Must leave `clear-human` (the human ceremony) behaviourally unchanged.
7. Must compute the changed-file list from git (the net diff against the base), never from the capped `gh pr view --json files` list, and must refuse when git cannot produce it — a PR of any size is checked against its full file list.
8. Must take the author provider from the trusted dispatch run record and the park time from the label timeline, never from PR body text.
