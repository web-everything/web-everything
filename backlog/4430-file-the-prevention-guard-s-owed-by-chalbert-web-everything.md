## Design

1. **Bound the tick's synchronous subprocesses.** Add an import-aware scanner in planned we:scripts/lib/daemon-sync-timeout-scan.mjs and wire it into we:scripts/check-standards.mjs. Initially enroll we:skills-src/conveyor/build-dispatch-daemon.mjs, including its injected `exec = execFileSync` and `run = execFileSync` seams and the imported throttled sync wrapper. Require an explicit, finite, positive timeout on every synchronous child-process call in that module, including options passed via local bindings. Detect both `execFileSync` and `spawnSync`, aliases, and the injected exec seams; comments and string literals are not calls. Report unreadable sources, parse failure, unknown/dynamic options, and unresolved timeout expressions as unproven errors rather than silently accepting them. Resolve local constants and validated injectable defaults; require runtime validation for injectable timeout values. Emit file/call diagnostics directing the author to provide a provable bound; never skip an unproven enrolled call. Add bounds to `cliPlanTick` and `cliDispatch`; retain the existing retry bound and prepare-status bound. Keep bounds named and injectable so tests exercise short deadlines without waiting for production durations. Use the existing 120,000 ms `DEFAULT_INTERVAL_MS` as the fixed default ceiling for newly bounded per-call waits; reject nonfinite, zero, negative, or above-ceiling injected values before spawning. Retain current output caps. A plan timeout aborts planning for that tick; a synchronous dispatch timeout returns a non-dispatching diagnostic through its existing catch. Surface the timeout so an operator can inspect the child log and the next tick can retry through existing admission. These are per-call bounds independent of a shorter paused-poll interval; this guarantees bounded calls, not a total tick deadline or grandchild cancellation.
2. **Redact before emitting diagnostics.** In the retry error path of we:skills-src/conveyor/build-dispatch-daemon.mjs, remove explicit GH_TOKEN/GITHUB_TOKEN values and GitHub token-shaped strings before whitespace normalization and the existing 400-character limit. Retain `timedOut` and useful nonsecret diagnostic text.

In we:scripts/operations/deliver-item-wrapper.mjs classify only the submit effect's exact `reasonCode === 'blocked-on-infra'`. Missing, unknown, or malformed codes are nonretryable; quoted error text and top-level prose never supply authority.
